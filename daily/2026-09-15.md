## 官方严谨版

### 今日结论

今天的核心变化不是“又来了一个模型”，而是模型选择、agent API、Codex/CLI 发布与企业治理开始被放到同一张运营表里。GitHub Copilot auto model selection 在 9 月 14 日新增 efficiency、balance、intelligence 三档，用来配置每次 prompt 如何权衡成本、质量和响应时间；同日到 9 月 15 日，Copilot CLI 1.0.84-6 到 1.0.84-8 又把 `/config`、sandbox host allow/deny、scheduled prompts footer、worktree、Agent Factory 暂停/恢复、concise transcript view 等功能继续推向可运营界面。

OpenAI 侧的信号更偏“权限与生命周期”。公开 release notes 显示，Codex policies 相关变更可进入审计日志，Admin API 支持 group 管理，Project API key 支持到期时间与最大生命周期，Agents API 开始把 Research、Code Interpreter、MCP、Image generation、File search 等能力组合进开发者可编排的 agent 路径。GPT-6 Astra 的公开发布页则把“长任务、coding、agentic work、企业控制”放在同一叙事里。

结论: AI 工作流正在从“选哪个模型更聪明”转向“谁可以自动选、按什么目标选、每次花费和权限怎么留下证据”。今天最值得沉淀三张小票: Model Auto-Selection Policy（自动选模型策略）、Agent API Capability Ledger（agent 能力台账）、CLI Runtime Receipt（CLI 运行时小票）。

### Codex/GPT 工作流启发

1. auto model selection 的 tier 不是模型名，而是偏好策略: efficiency 偏成本，balance 平衡成本/质量/延迟，intelligence 偏质量。
2. 同一个 tier 仍可能为简单任务选择小模型，所以报告不能只记录 tier，必须记录实际被选模型和用量。
3. 自动选模型适合日常流量，但高价值、外部副作用和安全决策仍要固定验收标准。
4. Copilot CLI 1.0.84-6 的 sandbox Network host allow/deny 让“能访问哪里”从口头约束变成运行时配置。
5. sandbox host 规则不能替代上游 proxy；两者要分别记录，避免排障时混成一件事。
6. managed Edit/Write rules 覆盖 shell redirection 与 in-place sed 后，自动化脚本要重测写入拦截。
7. `/worktree` 和 `--worktree` 不再需要 experimental mode，说明并行工作树正在变成标准 agent 基础设施。
8. active scheduled prompts 出现在 CLI footer，定时任务的“正在等什么”应该可见，而不是藏在配置里。
9. concise transcript view 把工具活动折叠成工作摘要，适合给用户看，但调试时仍要能展开查证。
10. Agent Factory 能暂停/恢复，意味着多任务批处理要记录暂停原因、恢复时间和未完成队列。
11. Codex 0.155.0-alpha.5 的 release body 很薄，应只作为 alpha lane 活跃证据，不当成稳定功能说明。
12. Codex policies 进入 audit logs 后，策略变更要和具体自动化运行绑定，方便复盘“谁改了门禁”。
13. Admin API group 管理意味着 agent 权限可以按组批量治理，但也要防止组权限漂移。
14. Project API key expiration/max lifetime 适合给自动化密钥加“保质期”，减少长期裸跑风险。
15. Agents API 的 Research、Code Interpreter、MCP、File search 等能力必须逐项登记数据输入和公开输出边界。
16. Codex harness 如果出现在 Agents API 路径里，要区分“agent 能运行代码”和“仓库已完成验证发布”。
17. GPT-6 Astra 这类强模型适合做总包判断，但不应取消小任务胶囊、测试、diff、commit、deploy 的证据层。
18. iPhone/Remote 可以审批低风险转向，但不能替代 Mac/Codex 的本地验证和发布证据。
19. X/社区讨论可以提示方向；本次没有采用无法回到公开原文的 X 内容。
20. 今天新增信号足以更新日报主题，不再延续昨天“无更新复盘”的判断。

### 可沉淀知识卡片

#### 卡片 1: Model Auto-Selection Policy

- 概念: 把自动选模型从“相信平台”改成“有目标、有记录、有复盘”的策略。
- 使用场景: MODEL ROUTING
- 操作步骤:
  1. 为任务标注 preferred tier: efficiency、balance 或 intelligence。
  2. 记录实际被选模型、用量、延迟、任务结果和返工次数。
  3. 对高价值任务保留人工验收和固定关键检查，不只看模型自动选择。
  4. 每周比较同类任务的成本/质量/延迟，而不是跨任务混算。
- 风险: tier 看起来像质量承诺，但实际模型仍会按 prompt 动态选择。

#### 卡片 2: Agent API Capability Ledger

- 概念: 把 agent 可用能力按工具、权限、输入数据、输出证据和回滚方式逐项登记。
- 使用场景: AGENTS API SETUP
- 操作步骤:
  1. 列出 Research、Code Interpreter、MCP、Image generation、File search、Codex harness 等能力。
  2. 对每项标注是否读取私有数据、是否写外部系统、是否会产生成本。
  3. 把公开输出和私有过程证据分层保存。
  4. 为每项能力写停止条件和最小验证命令。
- 风险: 能力组合越顺手，越容易把数据边界和完成证据混在一起。

#### 卡片 3: CLI Runtime Receipt

- 概念: CLI 升级后用一张小票确认配置、沙箱、worktree、定时任务和 transcript 行为。
- 使用场景: CLI UPGRADE
- 操作步骤:
  1. 固定 CLI 版本、OS、shell、账号状态和工作目录。
  2. 检查 `/config`、sandbox host allow/deny、managed Edit/Write、`/worktree`、scheduled prompts footer。
  3. 跑一次 read-only、一次预期被拦截的写入、一次网络 deny、一次 transcript 展开。
  4. 记录通过、失败、需要组织策略允许的项目。
- 风险: CLI prerelease 变化快，只有 smoke pass 不能替代生产验证。

#### 卡片 4: Policy/Audit/Key Lifecycle Gate

- 概念: 自动化运行前确认策略、审计和密钥生命周期三件事都可追溯。
- 使用场景: ENTERPRISE AGENT OPS
- 操作步骤:
  1. 记录适用的 Codex policies 或组织策略版本。
  2. 确认策略变更可进入 audit logs。
  3. 使用带到期时间和最大生命周期的 Project API key。
  4. 将 group 权限变化和具体自动化运行分开记录。
- 风险: 没有生命周期的密钥和没有审计的策略，都会让自动化长期漂移。

#### 卡片 5: Agent Factory Pause Resume Log

- 概念: 批量 agent 运行支持暂停/恢复后，必须记录中断原因和恢复状态。
- 使用场景: MULTI-AGENT BATCH
- 操作步骤:
  1. 每次批量运行记录 run id、任务列表、已完成数和剩余数。
  2. 暂停时写明原因: 费用、权限、失败、用户转向或外部阻塞。
  3. 恢复前重新检查输入是否过期、权限是否变化、是否有重复输出。
  4. 完成后把 transcript 摘要和可展开证据分层保存。
- 风险: 暂停后直接恢复，可能用旧输入继续生产新结果。

## 白话版

今天像公司给 AI 员工发了三样东西: 排班规则、门禁记录、工具箱清单。

GitHub 的 auto model selection 三档像叫车软件的“省钱、均衡、舒适”。你选的是偏好，不是指定哪辆车；系统可能看路况和订单大小再派不同车型。所以以后不能只写“用了 auto”，要写你选了哪档、实际派了谁、花了多少钱、结果有没有返工。

Copilot CLI 的更新像把施工现场的控制面板做出来了: 哪些网址能访问，哪些写入会被门禁拦住，工作树怎么开，定时任务现在在等什么，批量任务能不能先暂停再继续。面板看起来更顺手，但每次升级都要拿小票验一下。

OpenAI 的 release notes 像公司开始给钥匙和门禁上制度: 策略变更要进审计日志，组权限能用 API 管，API key 可以设置保质期。白话说，AI 员工不能拿一把永不过期的钥匙到处跑。

Agents API 像一个大型工具车，里面有研究、代码解释器、MCP、图片生成、文件搜索和 Codex harness。工具越全，越要登记清楚: 哪个工具能看什么、能写哪里、会不会花钱、最后怎么验货。

所以今天别急着“全开自动”。先补三张表: 自动选模型怎么选、agent 工具怎么登记、CLI 运行怎么留小票。小票齐了，自动化才不是黑盒魔法，而是能管理的生产线。
