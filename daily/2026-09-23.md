### Codex/GPT 工作流启发

1. 模型选择器现在不是“哪个聪明用哪个”，而是任务路由、成本、管理员策略和验收基线的组合。
2. GPT-6 Astra/Sol/Luna 可以拆成三条 lane: 高价值判断、日常 agentic coding、快速低风险执行。
3. Claude Opus 5.5 进入 Copilot 后，外部模型还要额外记录 provider pricing、watermark、policy 和可用入口。
4. Copilot JetBrains 的 assisted approvals 适合降低低风险打断，但必须保留哪些工具能自动过、哪些必须人工过。
5. message re-edit/rewind 是强能力；回退的是会话和文件现场，不是单纯改一句 prompt。
6. Codex agent plan mode 出现在 JetBrains 入口后，计划审核正在从 Chat/Codex 独立界面扩散到 IDE。
7. MCP 控制要细到 server/tool，不要只写“开了 MCP”。
8. Copilot CLI 1.0.88 stable 把 exact grant、network denial、fork、namespaced skills、indexed search 和 managed policy 都推成可审计点。
9. Copilot CLI 1.0.89-0 的 Connector consent progress 只能作为本地过程证据，授权 URL 不应进入公开日报。
10. Codex 0.156.0 stable 是今天最值得本地 smoke 的 Codex 锚点，不再只是 alpha 观察线。
11. Codex TUI、voice、usage dashboard 和 worktree command center 意味着 Mac/Codex 更像一个本地工作台，而不是单条命令。
12. stable 升级也要按能力面测: TUI、voice、usage、worktree、daemon、sandbox，各自有独立验收。
13. Node/Python SDK 同日补齐 GPT-6 模型标识，说明 app 端 allowlist 和 agent 端 model picker 要同步。
14. session environment reset events 适合写入长任务恢复测试，避免重置后状态漂移。
15. Python external storage、vault、safety、webhook、retry-replay 更新提醒: SDK 升级就是运营面扩容。
16. C++ whole codebase indexing 提醒我们，agent 的“聪明”常常取决于索引地图是否已经建好。
17. SSH 算法与 RSA key 要求变化会影响 CI、deploy key、开发机和自动化账号，不能等失败时再查。
18. CodeQL all-platform bundle 退役给了明确迁移窗口，CI 下载脚本要改成 OS/arch 显式选择。
19. Claude Code 2.1.280 的 symlink landing、denial backoff、hook telemetry 和 MCP cap 是很好的横向安全检查清单。
20. 今天的关键动作不是追每个新模型，而是把模型、索引、授权、发布包和 IDE agent 控制都变成可回读台账。

### 可沉淀知识卡片

#### 卡片 1: Three-Lane Model Router

- 概念: 把 Astra、Sol、Luna 这类模型放进按任务形状选择的路由表，而不是靠个人临时手感切换。
- 使用场景: MODEL ROUTING
- 操作步骤:
  1. 给每个模型记录适用任务、入口、成本、上下文、工具兼容、隐私边界和 fallback。
  2. 把高风险规划、日常 agentic coding、快速低风险执行分成不同默认 lane。
  3. 每次切换模型时保存任务类型、选择原因和验收结果。
  4. 外部模型另记 provider pricing、admin policy、watermark 或数据保留差异。
- 风险: 模型越多，越容易把质量、成本和权限问题混成一个模糊的“换个模型试试”。

#### 卡片 2: IDE Agent Control Receipt

- 概念: IDE 里的 agent 也要留下 plan、approval、rewind、shared instruction 和 MCP tool 控制证据。
- 使用场景: IDE OPS
- 操作步骤:
  1. 记录 assisted approval 是否启用、哪些动作自动批准、哪些必须人工批准。
  2. 使用 message re-edit/rewind 前后，保存影响范围和文件变化读回。
  3. 标明 shared skills/instructions 的组织或企业来源。
  4. MCP 工具按 server 和 tool 分开记录启用状态，不把内置 GitHub MCP 与手动 MCP 混写。
- 风险: IDE agent 看似贴近日常开发，若没有小票，自动批准和回退会很难复盘。

#### 卡片 3: Stable Upgrade Smoke Matrix

- 概念: 稳定版升级也要按能力面 smoke，而不是看到 stable tag 就直接替换默认工具。
- 使用场景: RUNTIME RELEASE
- 操作步骤:
  1. 列出本次 stable 新增能力面，例如 TUI、voice、usage、worktree、daemon、sandbox。
  2. 每个能力面准备一个最小真实任务和失败停止条件。
  3. 先在 disposable workspace 或低风险仓库跑，再推广到主工作流。
  4. 报告中区分 stable tag、local smoke、默认启用三层证据。
- 风险: stable 表示发布线稳定，不表示你的本地工具链、账号、代理和仓库都已适配。

#### 卡片 4: Index Warmup Receipt

- 概念: 大代码库的代码智能要把索引首次构建、复用和关闭选项写进运行记录。
- 使用场景: KNOWLEDGE OPS
- 操作步骤:
  1. 记录语言、索引器、默认启用状态、首次构建耗时和内存峰值。
  2. 用 /lsp logs 或等价日志确认索引进度。
  3. 把冷启动耗时和热索引查询耗时分开比较。
  4. 在 CI 或共享环境中明确索引缓存位置和清理策略。
- 风险: 不区分冷索引和热索引，会把基础设施延迟误判为模型能力差。

#### 卡片 5: Platform-Specific CI Artifact Gate

- 概念: 当安全工具停止提供全平台包时，CI 下载逻辑必须按 OS/架构显式选择。
- 使用场景: CI MIGRATION
- 操作步骤:
  1. 列出 CI runner 的 OS、架构和所需工具版本。
  2. 把下载 URL、checksum、cache key 和 fallback 分平台维护。
  3. 为 Linux ARM64 等特殊路径单独跑 smoke。
  4. 在弃用日期前移除 all-platform bundle 假设。
- 风险: 一个 all-platform 包消失后，最先坏的往往是夜间扫描、release 检查和临时 runner。

## 白话版

今天的 AI 工具更新，像工具间突然多了三排新货架、一个新的值班台、一张车间地图和一套安检规则。

第一排货架是 GPT-6 Astra/Sol/Luna。Astra 像总工程师，适合高价值判断；Sol 像主力师傅，适合日常复杂开发；Luna 像快手助手，适合低风险快活。问题不是谁“更强”，而是这件事该派哪辆车。

第二排货架是 Claude Opus 5.5 进了 Copilot。它能做长任务和知识工作，但它也带着价格、管理员开关和水印规则。白话说，外包高手进场前，也要登记工牌、工资和工作边界。

新的值班台是 Copilot JetBrains 和 Copilot CLI。它们开始支持低风险自动批准、计划模式、回退早先消息、MCP 工具开关、任务分叉和连接器授权进度。听起来很顺，但越顺越要有小票，不然事后没人说得清“谁按了哪个按钮”。

车间地图是 C++ whole codebase indexing。大代码库不是靠模型临场乱找路，先建一张符号地图，之后查定义、找引用、理解代码才快。像进大商场先看导览图，不是每次都从一楼问起。

安检规则是 SSH 和 CodeQL。SSH 老算法、短 RSA key、CodeQL 全平台包都在被清理。它们不花哨，但一旦没迁移，坏的可能就是 CI、发布和自动化账号。

今天最值得带走的一句话: 模型越多、入口越多、agent 越顺手，越不能靠感觉开工；要像管理车钥匙、施工票和仓库地图一样，把模型、授权、索引和发布依赖都登记清楚。
