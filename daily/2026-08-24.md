### Codex/GPT 工作流启发

1. Agent Plugins 1.0 说明插件资产正在从“某个客户端自己的格式”变成跨客户端包；个人工作台要先检查 manifest 和边界，再谈启用。
2. 兼容客户端清单已经覆盖 VS Code、Cursor、GitHub Copilot、ChatGPT & Codex 等入口；同一个 skill/MCP 可能跨工具出现，权限账本必须跨入口。
3. Agent Plugins client loading 明确要求先解析 `plugin.json`，再发现固定位置组件；这适合变成本地插件上架前的超市上架清单。
4. loading/discovery 里强调路径不能逃出插件根目录；本地 MCP、skills、脚本和扩展都要有路径边界。
5. conformance checklist 强调缺失组件不是错误、失败组件隔离处理；插件平台应降级加载，不因一个 skill 坏掉拖垮整包。
6. OpenAI API 的 request-level regional processing 让“请求发到哪里处理”进入任务信封；合规和延迟不再只是项目级默认值。
7. Prompt Caching dashboard 让缓存命中、cache read/write 和未缓存 token 可观测；日报类自动化可用相同思想记录复用率。
8. GPT-5.6 Sol 价格更新提醒模型路由卡要记录时间点；价格、模型和促销期都可能漂移，不能长期硬编码旧成本判断。
9. ChatGPT 8 月 21 日的 plugin discovery、local time、long conversation loading、progressive interactive replies 和 iOS 更新，继续强化会话内运营能力。
10. ChatGPT 8 月 20 日的 Apple Messages plugin、Computer History、Codex snapshot 和 Sites URL 更新，把跨 app、历史和分享边界推到前台。
11. Codex 0.150 alpha 高频发布说明功能节奏快；自动化只能引用 release 页状态，不能假设本机已具备同等能力。
12. Codex 0.149.0 的 queue、doctor、dashboard 和 exact CLI config overrides 适合变成发布前执行闸门。
13. GitHub Copilot in Slack 把 agent session 变成团队共享现场；优点是可见，风险是多人 steering 容易改变目标，需要任务信封。
14. GitHub Copilot in Teams 把会议动作项接进 agent session；会议结论必须先转成可验证任务，而不是直接让 agent 猜。
15. JetBrains enterprise managed settings 把 plugin governance、MCP allowlist、OpenTelemetry 和 permission modes 放到管理员配置；个人工作台也应借鉴成一张控制矩阵。
16. Copilot weekly release 的 side chat、`/tasks`、queue、`/rewind` 和 context-preserving `/app` 说明长任务会越来越像可暂停、可恢复、可回滚的运行系统。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 用固定模板派发任务，写清绝对日期、是否允许发布、是否允许外部工具和停止条件。
2. Chat: 把口语需求整理成任务信封，明确入口、目标、读写边界、预算、approval 和最终 owner。
3. Plugin intake: 新 skill/MCP/plugin 先过 manifest、路径边界、权限、外部副作用和撤销路径检查。
4. API run: 若调用 OpenAI API，记录区域处理、模型、service tier、cache dashboard 指标和成本时间点。
5. Slack/Teams: 只做共享派工、状态和 steering；高风险写动作回到 PR、issue、Codex 或本地审批。
6. Mac/Codex: 发布前检查 repo 状态、source-card 数、JSON/JS 同步、diff、commit、push 和 Vercel Ready。
7. Knowledge: 将插件 intake、请求地理/缓存、ChatOps 任务信封和企业控制矩阵沉淀为可复用卡片。

### 可沉淀知识卡片

#### 卡片 1: Portable Agent Plugin Intake

- 概念: Agent Plugins 1.0 让插件包跨客户端流动，启用前必须做上架检查。
- 操作步骤:
  1. 先读取 `plugin.json`，记录 schema、name、版本、来源和 owner。
  2. 检查 `skills/`、`mcp.json` 和 client extension 是否在固定位置。
  3. 校验路径是否逃出插件根目录。
  4. 标注每个组件的读写能力、外部副作用、权限提示和撤销路径。
  5. 失败时只隔离坏组件，记录是否允许降级加载。
- 风险: 插件越可移植，误装、越权和跨客户端漂移的风险越高。

#### 卡片 2: Request Geography & Cache Dashboard

- 概念: API 请求的处理区域和缓存效率要进入同一张运行看板。
- 操作步骤:
  1. 为每类 API 任务记录目标区域、项目 geography、模型和 endpoint。
  2. 标注是否允许 request-level regional processing。
  3. 跟踪 prompt cache hit rate、cache reads/writes 和 uncached tokens。
  4. 按模型和 service tier 汇总成本、延迟和复用率。
  5. 价格或模型更新时重新计算默认路由。
- 风险: 合规位置和缓存成本都可能被默认值隐藏；没有看板就只能靠感觉优化。

#### 卡片 3: ChatOps Shared-Agent Envelope

- 概念: Slack/Teams 让多人在同一个 agent 现场协作，但必须先把聊天转成任务信封。
- 操作步骤:
  1. 写清 workspace/channel/thread、repo、目标、权限和预算。
  2. 区分问答、triage、创建 issue、改代码、开 PR 五类动作。
  3. 默认只允许计划、诊断和草稿；写动作需要明确 owner。
  4. 多人 steering 时记录谁改变了目标、何时改变、是否影响验收。
  5. 合并前回到 PR、测试、额外审批和 deploy 证据。
- 风险: 共享现场提高透明度，也会放大隐式改需求和误触发。

#### 卡片 4: Enterprise Agent Controls Matrix

- 概念: 企业托管设置把插件、MCP、遥测和权限模式变成可审计控制面，个人工作台也应复用这套矩阵。
- 操作步骤:
  1. 列出允许插件、禁止插件和允许 marketplace。
  2. 建 MCP allowlist/denylist，记录 transport、URL/command 和 owner。
  3. 为遥测记录 collector、protocol、service name 和内容捕获策略。
  4. 为每个入口定义 permission mode: read-only、draft、ask-before-write、blocked。
  5. 每月复核一次误触发、被拒组件和人工返工点。
- 风险: 没有集中控制矩阵，入口越多，权限越容易靠默认值扩散。

## 白话版

今天这期像是从“每个工具自己带一套插头”变成了“大家开始统一插座标准”。

Agent Plugins 1.0 就像插线板标准。以前一个插件要给 VS Code、Copilot、Codex、Cursor 各做一套包装；现在开始有统一盒子，里面能放 skill、MCP 和客户端自己的扩展。好处是工具更容易搬家，坏处是也更需要超市上架清单: 这个盒子是谁的、能读什么、能写什么、会不会连外部服务、坏了是整盒下架还是只下架一个零件。

OpenAI API changelog 像给厨房装了两个表: 一个表看这单菜在哪个区域处理，另一个表看有没有复用半成品。区域处理关心合规和延迟，Prompt Caching dashboard 关心缓存命中和成本。以后做 API 任务，不能只看“模型会不会答”，还要看“请求从哪里走、有没有复用、花了多少”。

Slack 和 Teams 的 Copilot agent 像把施工现场搬进群聊。大家都能看到、补充、转向，会议里说出的动作项也能马上交给 agent。但群聊不是验收台。最后能不能合并、能不能发布，还是要看 PR、测试、审批和部署证据。

Codex releases 像施工工具箱快速升级。queue、doctor、dashboard、reasoning effort 这些东西说明它不只是会写代码，还在变成能排队、能体检、能看状态、能选用力档位的工作台。对我们来说，下一步不是盲目追新版本，而是把版本、队列、体检、预算和最终 owner 记清楚。

所以今天最该沉淀的不是某个炫技玩法，而是四张表: 插件上架清单、请求区域和缓存看板、群聊 agent 任务信封、企业级 agent 控制矩阵。工具越来越多，入口越来越多，真正值钱的是边界和证据。
