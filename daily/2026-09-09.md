### 今日结论

今天的核心不是单点模型新闻，而是 OpenAI SDK、Agents SDK、Codex alpha、Copilot CLI 和 GitHub Enterprise 同时把能力、权限、凭证与验证小票做细。

GPT Image 2.5 已进入 Node/Python/Java SDK 的公开发布面。Node 7.12.1 明确补上 7.12.0 未发布到 npm 的 GPT Image 2.5 支持，并加入 Cloudflare example release regression；Python 3.10.0 同时加入 GPT Image 2.5 和 service-account API key expiration fields；Java 4.60.0 也补齐 GPT Image 2.5，且 4.59.0 已同步 prompt cache diagnostics、key expiry 和 function argument completion fields。结论: 多语言 agent 工程现在需要 SDK parity matrix（多语言 SDK 同步矩阵），不能只看一个语言的 release note。

Agents SDK 0.22.1 的方向更偏运行时治理: web search 工具可返回 image results，MCP tools 可配置 server-wide guardrails，output guardrail blocked message 可定制，还加入 Unix-local environment isolation、Docker labels 和 streamed transcription options。结论: guardrail（安全拦截规则）不再只是 prompt 层口头约束，而应进入工具服务、容器、回放和导出边界。

Codex 0.154.0-alpha.8 已出现在公开 release feed，但正文仍只有 release label。它只能证明 alpha 线有发布节奏，不能证明稳定功能或修复。Copilot CLI 1.0.84-3 修复 OAuth MCP server 冷启动可靠性和 /copy completion message；1.0.84-2 则强调 Vim mode、exact UUID resume、Windows sandbox blocked-access recording 与 managed hook lockdown。结论: CLI 升级验收要同时覆盖交互体验、MCP 启动、会话导出、sandbox bypass 小票和 hook policy。

GitHub Enterprise Server 3.22 把 Copilot CLI 带进 disconnected / air-gapped enterprise 场景，但仍是 technical preview；Dependabot 的 GitHub-hosted private registry 读取可减少 PAT，但要验证 GITHUB_TOKEN packages:read、package Actions access 和 registry fallback precedence。结论: “少用长期 token”是好方向，但不能省略权限读回和路由验证。

今天建议沉淀五个资产: SDK Multimodal Parity Matrix、Service Account Expiry Receipt、MCP Server Guardrail Contract、Air-Gapped Agent Provider Gate、Registry Fallback Auth Gate。

### Codex/GPT 工作流启发

1. GPT Image 2.5 同时进入多语言 SDK 后，升级验收应从“某个 SDK 能跑”升级为“生产语言栈一致可跑”。
2. Node 7.12.1 明确补 7.12.0 未发布到 npm 的能力，说明 release tag 和包管理器可安装状态必须分开核验。
3. Python/Java 的 service-account expiration fields 适合进入凭证小票，减少“key 突然失效但不知道为什么”的排障成本。
4. prompt cache diagnostics 进入 SDK 字段后，长任务应记录 cache hit/miss 与成本，而不是只记录总 token。
5. Agents SDK 的 image web search result 需要单独分类: 图片可见不等于版权、隐私、可复用边界都已确认。
6. MCP server-wide guardrails 比单个 agent prompt 更接近真实治理层，但仍要验证重启、回放、导出和错误提示。
7. 自定义 blocked message 可以提高用户可修复性，但不能把被拦截内容重新泄露进提示文本。
8. Unix-local environment isolation 和 Docker labels 适合进入 sandbox cleanup receipt（沙箱清理小票）。
9. Codex alpha 只有占位正文时，不能当稳定功能证据；alpha lane 继续观察即可。
10. Copilot CLI 的 OAuth MCP 冷启动修复提醒: agent “工具可用”必须从新会话冷启动验证，不只看热会话。
11. /copy 包含 completion messages 后，导出材料更接近完整交接，但也要重新检查公开边界。
12. Vim mode 是人机协作体验，不是 agent 能力；它影响输入效率，不替代验收。

16. air-gapped provider setup 需要把模型、凭证、审计、更新、回滚和外联边界写清楚。

### 可沉淀知识卡片

#### 卡片 1: SDK Multimodal Parity Matrix

- 概念: 把 Python、Node、Java 等 SDK 的图像模型、图像选项、缓存诊断、服务账号到期字段和流式事件字段做成同一张升级矩阵。
- 使用场景: SDK PARITY
- 操作步骤:
  1. 逐语言记录版本、发布时间、npm/PyPI/Maven 发布状态和 release body。
  2. 用相同输入测试图像选项、缓存诊断、key expiry 和 function-call streaming。
  3. 只有所有生产语言通过固定 smoke 后，才更新共享 agent 模板。
- 风险: 只验证一个 SDK 会让另一个语言栈在同名能力下行为不同。

#### 卡片 2: Service Account Expiry Receipt

- 概念: 服务账号 API key 不再只记录名字和创建人，还要记录过期字段、轮换负责人和失效前的验证动作。
- 使用场景: KEY EXPIRY
- 操作步骤:
  1. 读回 SDK 或管理接口里的 expiration 字段。
  2. 记录 owner、用途、允许项目、轮换日期和失败 fallback。
  3. 到期前跑最小真实请求，确认新旧 key 切换和日志脱敏。
- 风险: 没有到期小票时，agent 失败会被误判为模型或代码问题。

#### 卡片 3: MCP Server Guardrail Contract

- 概念: 把 guardrail 从单个 agent 提示提升到 MCP server 级别，统一定义工具输出拦截、用户可见提示和回放边界。
- 使用场景: MCP GUARDRAIL
- 操作步骤:
  1. 按 server 记录允许工具、禁止输出类型和 blocked message。
  2. 测试被拦截输出是否进入 replay、checkpoint 或导出文本。
  3. 上线后抽样验证每个工具仍返回可行动的错误信息。
- 风险: 只在 agent 层拦截会漏掉工具服务重启、复用和导出的路径。

#### 卡片 4: Air-Gapped Agent Provider Gate

- 概念: 离线或隔离企业里的 Copilot/Codex 需要把模型提供方、凭证来源、网络边界和预览状态单独列为准入条件。
- 使用场景: AIR GAP
- 操作步骤:
  1. 记录 GHES 或本地平台版本、model provider、凭证来源和允许网络路径。
  2. 标明 technical preview 或 GA 状态，禁止当成稳定云端能力。
  3. 用无外网样例任务验证认证、日志、更新和回滚。
- 风险: 隔离环境里最常见的失败不是模型能力，而是凭证、路由和审计边界。

#### 卡片 5: Registry Fallback Auth Gate

- 概念: Dependabot 或 agent 从私有 registry 拉包时，区分显式凭证、平台 token fallback 和普通公共 registry 路由。
- 使用场景: REGISTRY AUTH
- 操作步骤:
  1. 读回 package 的 Actions access 和仓库权限。
  2. 确认 GITHUB_TOKEN 只请求 packages:read，且显式 registry 凭证优先。
  3. 跑一次依赖更新并保存 registry host、认证方式和回滚方案。
- 风险: fallback 认证省掉 PAT 的同时，也可能掩盖错误的 registry 路由。

## 白话版

今天像工具房来了新设备，但重点不是“刀更锋利了”，而是仓库管理员终于把借刀登记、门禁、锁柜和质检小票都补上了。

GPT Image 2.5 进了 Node、Python、Java 三个工具箱。以前像只在一个工位试过新钻头，现在三条生产线都能拿到类似规格。真正要做的不是立刻全厂换钻头，而是拿同一块材料分别在三条线上试一遍，确认孔径、噪音、电费和说明书都一致。

Agents SDK 的变化更像给整排工具柜装总闸。以前是提醒每个师傅“别乱拿东西”，现在开始在 MCP 工具服务这一层装安全开关；如果开关拦住了，还能给用户一个更清楚的说明。问题是，拦住的东西不能从导出记录、回放记录或错误提示里绕回来。

Codex alpha 今天只是箱子上贴了新编号，没有说明书。它值得放观察架，不适合搬上生产线。Copilot CLI 则是在修长会话里的细节: 工具冷启动要稳，复制交接记录要完整，沙箱拦截要有小票，hook 不能被扩展绕过。

GHES 3.22 像把 Copilot CLI 带进断网工厂，但牌子上写着“技术预览”。Dependabot 去 PAT 化则像不再给长期万能钥匙，而是让系统临时拿一张只读通行证去仓库取包。两件事都方向正确，但都必须现场验门禁、路由和回滚。

所以今天的动作很明确: 别急着喊“升级默认”。先升级验收表，把 SDK 同步矩阵、key 到期小票、MCP 总闸合同、隔离环境准入和 registry fallback 认证都补齐。
