### Codex/GPT 工作流启发

1. 内容排除 GA 后，agent 的第一道安全线不再是“事后扫描”，而是“上下文装载前就不让它看”。
2. 内容排除策略应按 enterprise、organization、repository 三层读回，不能只在本地 prompt 里口头声明。
3. 企业默认模型可按团队托管后，模型选择变成配置管理问题，需要记录 model key、team-mappings、是否可覆盖和回滚点。
4. 默认模型不等于最强模型；它应该代表团队的隐私、成本、稳定性和工具兼容折中。
5. custom agent 的多模型候选列表适合做 fallback，但 required policy 必须避免 agent 自行跳到未批准模型。
6. Linux sandbox 代理出站限制说明联网不应是二元开关，而应绑定代理、证书、域名和失败处理。
7. Healthcare Public Data 插件适合查公共药品、公开资源和公开医学资料，不适合承载个人病历、claims 或 PHI。
8. 医疗插件的组织连接器和公共数据源要分开验收，不能把“能问公共资料”扩展成“能处理个人健康数据”。
9. iOS 队列能附加图片/PDF/文件后，移动派工要记录附件是否公开、是否脱敏、是否允许进入最终日报。
10. Priority view 和工作时长能降低远程盯任务成本，但“正在运行”仍不是完成证据。
11. thread ID 复制是长任务换车的低成本锚点，适合进入所有跨设备 handoff。
12. Codex 0.153 alpha 今天有新构建但 release body 很少，适合观察节奏，不适合提炼具体能力承诺。
13. Codex 0.152.0 仍是当前稳定 runtime 合同来源: timeout、MCP output ceiling、credential refresh 和 backend URL trust。
14. AI approval、budget expires_at、model retention 和 content exclusion 已经形成同一条治理链: 谁能看、谁能跑、谁能花钱、谁能盖章。
15. Agents SDK replay hardening 继续提醒: 内容被拦截后，不只模型上下文要清理，应用自有日志也要对齐。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 新建任务时先列附件清单，标注公开/私有/需脱敏，私有附件默认不进公开日报。
2. iPhone/Remote: 用 Priority view 看 running、unread、needs response；只批准低风险补充。
3. iPhone/Remote: 复制 thread ID 给 Mac/Codex，并记录原始入口、队列状态、附件状态和预期验收。
4. Mac/Codex: 读取任务信封后再决定允许哪些文件、哪些 MCP、哪些外联代理。
5. Mac/Codex: 对 GitHub/Copilot 类执行通道先读 content exclusion、default model、budget、approval policy。
6. Mac/Codex: 对 Healthcare/Public Data 类插件只允许公开资料问题，不允许个人病历、claims、账号内健康数据进入公共源。
7. GitHub/Copilot: default model 变更需要像配置发布一样走 diff、review、rollout 和 rollback。
8. 知识库: 只沉淀 contract 和 gate，不复制 release note 全文。

### 可沉淀知识卡片

#### 卡片 1: Context Exclusion Contract

- 概念: 在 agent 装载上下文前就定义哪些文件、路径、资料类型不能被读取或用于推理。
- 使用场景: GitHub Copilot app/CLI、私有代码库、客户资料、密钥模板、公开日报自动化。
- 操作步骤:
  1. 记录 enterprise、organization、repository 三层 exclusion 来源。
  2. 把 excluded paths、适用工具、适用 agent、例外审批人写成合同。
  3. 运行前读回配置，运行后做公开边界扫描。
- 风险: 只靠 prompt 声明“不要看”不等于运行时真的不会装载。

#### 卡片 2: Managed Model Default Receipt

- 概念: 把默认模型当作可审计配置发布，而不是个人偏好。
- 使用场景: GitHub Copilot app、Copilot CLI、VS Code、团队默认 agent 模型。
- 操作步骤:
  1. 记录 model key、适用团队、team-mappings、是否允许用户覆盖和生效入口。
  2. 默认模型变更前确认隐私、保留策略、成本、工具兼容和回滚路径。
  3. 变更后抽样读回新会话默认值。
- 风险: 默认模型一旦错配，会把错误成本扩散到所有新任务。

#### 卡片 3: Healthcare Public-Data Boundary

- 概念: 公共医疗资料查询和个人健康数据处理必须分成两条通道。
- 使用场景: Healthcare Public Data、EHR/claims 组织插件、临床/保险/药品公开资料检索。
- 操作步骤:
  1. 标注问题是否只涉及公开资料。
  2. PHI、病历、claims、账号内健康数据默认不进入公共数据插件。
  3. 需要组织健康数据时，单独确认连接器、权限、审计和输出边界。
- 风险: 公共医学资料能回答问题，不代表它适合处理个人健康记录。

#### 卡片 4: Mobile Attachment Queue Envelope

- 概念: 手机派工时把附件、队列状态、thread ID 和最终验收字段打包成任务信封。
- 使用场景: ChatGPT iOS、Codex Remote、PDF/图片/文件附件、后台发送。
- 操作步骤:
  1. 记录 origin device、queued prompt、attachment list、background-send status 和 thread ID。
  2. 附件按公开、私有、需脱敏、禁止公开四类标记。
  3. Mac/Codex 收口时补测试、diff、commit、push、deploy 证据。
- 风险: 附件越容易随手发，越需要前置公开边界。

#### 卡片 5: Proxy-Egress Sandbox Gate

- 概念: 把 sandbox 的网络出站限制到指定代理，并把代理凭证和域名范围当作独立 gate。
- 使用场景: Copilot CLI sandbox、外部模型通道、企业代理、mTLS、受控联网任务。
- 操作步骤:
  1. 记录 proxy、证书/凭证来源、允许域名、工具范围和失败处理。
  2. sandbox 里禁止绕过代理直接联网。
  3. 失败时先记录错误类型，不自动扩大网络权限。
- 风险: “能联网”如果不分代理和域名，会把受控 agent 变成宽外联进程。

### 待确认/待对齐

2. 是否把团队默认模型变更纳入配置发布流程，要求 model key、team mapping 和回滚证据。
3. 是否为 iPhone/Remote 派工强制增加附件公开边界字段。
4. Healthcare Public Data 类插件是否默认只允许公共资料检索，个人健康数据必须另走组织连接器审批。

## 白话版

今天这期像“给 AI 办公室装门禁”。以前我们关心的是 AI 能不能进更多房间，现在更关键的是: 哪些房间它根本不能进，进门后默认坐哪张工位，用谁的预算，最后谁能签字。

GitHub 的 content exclusions 就像超市上架清单的反面: 有些货明确不上架，AI 就不该拿它当材料。敏感代码、密钥模板、客户材料、私有附件，不是等 AI 看完再提醒它“别说出去”，而是一开始就别让它进购物车。

企业默认模型像公司统一配车。不是谁跑得最快就默认给全员用，还要看油耗、保险、能不能进园区、出了问题怎么换回来。GitHub 现在可以按团队设置默认模型，所以每次换默认模型都要像发布配置一样留小票。

Healthcare Public Data 像公共图书馆里的医学资料区。你可以查公开药品信息、公开资源、公开医学资料，但不能把自己的病历、保险 claims、身份证号一类个人健康信息塞进去问。公共图书馆能查书，不代表它能保管你的私人病历夹。

iPhone 这边更像遥控器升级成“带附件的工单夹”。它可以把图片、PDF、文件和任务一起排队，还能看哪些任务在跑、哪些等你回复，并复制 thread ID。但最终验收还是要回到 Mac/Codex 工作台: 文件在不在、测试过没、diff 看过没、commit/push/deploy 有没有证据。

所以今天的重点不是多追一个新模型，而是把门禁、默认车、预算卡、附件工单和最终验收章分清楚。AI 越能干，越要先规定它不能碰什么。
