### Codex/GPT 工作流启发

1. Voice 是入口，不是审批替代品

OpenAI Release Notes 显示 Voice 已进入 Work 和 Codex 桌面体验。语音适合临场派工、补充背景、打断和改方向，但不适合承担费用、权限、公开发布、删除、授权等高风险确认。实际动作应落回文字任务卡和可检查 diff。

2. Workspace Agents 是流程资产化信号

Workspace Agents 可创建、测试、发布、选择模型/推理力度、连接工具、团队共享、在 Slack 使用、按计划运行或 API 触发。对个人工作台来说，重复晨报、月度知识卡片、PR review、素材归档都应从“临时 prompt”升级成“版本化 agent 说明 + 工具边界 + 验收清单”。

3. GitHub 正把多家 coding agents 纳入同一条 issue-to-PR 管道

GitHub Docs 明确第三方 coding agents 可从 Agents tab、Issues、Pull Requests、GitHub Mobile 和 VS Code 启动，完成后创建 PR 并请求 review。这个结构比“agent 直接改主分支”安全: 所有执行都应落在草案、PR、review、扫描和迭代评论里。

4. Codex mobile 的核心价值是及时介入

OpenAI 的 Codex mobile 说明强调手机可以 review 输出、批准动作、切模型、看截图/终端/diff/测试结果。它的价值不是替代 Mac，而是缩短长任务等待用户判断的时间。手机负责“别让任务卡住”，Mac 负责“别让错误发布”。

5. Agents SDK 把沙箱、文件、命令和 AGENTS.md 变成标准工程件

OpenAI Agents SDK 更新把 sandbox、filesystem、shell、apply patch、MCP、skills、AGENTS.md 等能力放进 agent harness。个人自动化也应学习这层分工: prompt 不是全部，运行环境、工具权限、输入目录、输出证据同样是产品的一部分。

6. Codex CLI release 频繁迭代，日报不要锁死版本判断

GitHub Releases 显示 openai/codex 仍在高频 alpha/patch 发布。日报中的工具建议应避免依赖某个未验证新版本特性；涉及 CLI 行为时应记录本地版本、命令输出和失败边界。

7. 第二大脑正在从“存笔记”变成“可被 agent 操作的知识底座”

Obsidian second brain 相关项目强调 Markdown vault、自动合成、冲突调和、跨 CLI 检索和计划 agent。知识库不应只是归档链接，而应沉淀成 agent 可读的事实、决策、流程和反例。

8. 领域专家仍然是 agent 成功的放大器

Anthropic 研究显示，用户通常做规划决策，agent 做执行决策；领域知识越清楚，每条指令能释放的 agent 工作越多。对 AI Radar 来说，用户的“完成标准”和“安全边界”比堆更多工具更关键。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone / Voice: 收集公开链接、口述目标、补上下文、低风险批准、查看长任务状态。
2. Workspace Agent: 承载可重复流程，例如晨报源筛选、source-card 归一化、知识卡片候选生成。
3. GitHub Issue / PR: 把较大的执行任务落成草案 PR，让 agent 在 review 评论中迭代。
4. Codex on Mac: 执行本地文件更新、JSON/JS 同步、静态检查、secret/path 扫描、commit/push/deploy。
5. Obsidian / knowledge: 把可复用经验写回知识卡片，而不是只留在当天新闻摘要里。
6. Vercel / GitHub: 只在 Mac 上做最终公开发布和 Ready 验收。

### 可沉淀知识卡片

#### 卡片 1: 可复用 agent 资产验收单

- 概念: 一个可复用 agent 不只是 prompt，还包括输入范围、工具、权限、调度、证据、失败停点和知识回写。
- 适用场景: Workspace Agents、Codex skills、日报自动化、PR review、资料整理。
- 操作步骤: 写目标 -> 限定输入 -> 列工具 -> 标权限 -> 写验收 -> 写失败停点 -> 写回知识库。
- 风险: 只保存 prompt 会导致下一次换入口后权限、证据和输出格式全部漂移。
- 原文: https://help.openai.com/en/articles/20001143-chatgpt-workspace-agents-for-enterprise-and-business

#### 卡片 2: Voice 派工确认闸

- 概念: 语音可用于快速派工和补上下文，但高风险动作必须回到可读文字、diff 和显式确认。
- 适用场景: ChatGPT Voice in Work/Codex、iPhone 远程控制、会议后临时派工。
- 操作步骤: 语音输入 -> agent 复述任务卡 -> 用户确认边界 -> 执行低风险步骤 -> 高风险动作转 Mac 终审。
- 风险: 口语容易遗漏否定条件、金额、路径、账号和公开边界。
- 原文: https://help.openai.com/en/articles/6825453-chatgpt-release-notes

#### 卡片 3: Issue-to-PR agent 管道

- 概念: 异步 coding agent 的安全形态是从 issue/PR/Mobile/VS Code 启动，产出草案 PR，请求 review，并接受评论迭代。
- 适用场景: GitHub third-party coding agents、Codex、Claude、Copilot cloud agent。
- 操作步骤: 写清 issue -> 选择 agent/model -> agent 开 PR -> 安全扫描 -> 人类 review -> 评论迭代 -> merge。
- 风险: 直接改主分支或跳过 review 会把 agent 的幻觉和权限错误带进发布链路。
- 原文: https://docs.github.com/en/copilot/concepts/agents/about-third-party-coding-agents

#### 卡片 4: Markdown 知识底座

- 概念: 第二大脑应让 agent 能检索、更新、调和冲突和沉淀决策，而不是只堆网页剪藏。
- 适用场景: Obsidian vault、Codex memory、自动化日报、项目决策记录。
- 操作步骤: 用 Markdown 存事实/决策/流程 -> 标日期和来源 -> 定期合并重复 -> 记录反例 -> 让 agent 读写受控目录。
- 风险: 没有结构的笔记会越存越难用；全库写权限又会带来误改和泄密风险。
- 原文: https://github.com/eugeniughelbur/obsidian-second-brain

## 白话版

今天的变化像是你家里的工作台又多了几个入口: 可以用手机遥控，可以直接说话派活，也可以把常用工种做成固定员工。入口变方便了，但真正要紧的是: 谁能拿钥匙、谁能动仓库、谁能按发布按钮、出了错有没有监控录像。

Voice 进了 Work 和 Codex，就像你可以对同事口头说“帮我把这件事推进一下”。这很好用，但口头交代容易漏字，所以重要事情不能只靠一句话。它应该先复述成任务卡，再让你确认。

Workspace Agents 像把临时工变成固定岗位。以前你每天写一遍 prompt，现在可以把“做晨报”“整理资料”“检查 PR”做成可测试、可发布、可调度的固定流程。固定岗位的好处是下次不用重新培训，坏处是如果岗位说明没写清，它会稳定地重复同一个错误。

GitHub 的第三方 coding agents 像把不同外包团队都接进同一套工单系统。你可以从 issue、PR、手机、VS Code 叫 Codex 或 Claude 来干活，但它们最好都交一个草案 PR，让你验货，而不是直接冲进仓库改主货架。

所以今天的核心不是“又多了哪个新按钮”，而是“每个按钮后面有没有闸门”。手机和语音像遥控器，负责叫人、补话、看状态；Mac 像验货台，负责看 diff、跑测试、提交、部署；知识库像仓库账本，负责把今天踩过的坑变成下次能用的规矩。
