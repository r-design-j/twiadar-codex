### Codex/GPT 工作流启发

1. 企业 SSO 凭证授权现在可以由企业安装的 GitHub App 批量处理，自动化服务账号轮换时应记录 app 权限、credential identifier 和 target orgs。
2. 这个 API 使用非秘密 token ID 或 SSH key fingerprint，不应把 PAT/SSH 私密材料传给 App。
3. SCIM profileUrl 让身份目录、GitHub 用户和外部 IdP 之间的匹配更稳定；缺失 profileUrl 应被记录为 unresolved link。
4. Copilot 预算申请 GA 说明 AI 成本管理正从后台账单变成工作流内审批。
5. 预算申请不能只看“谁卡住了”，还要关联任务价值、模型路由、审批人和后续使用复盘。
6. AI Scan 不再要求 CodeQL default setup，PR 安全覆盖统计需要从“CodeQL 是否开”改成“code scanning + AI Scan 是否启用且仓库是否 eligible”。
7. 对 GHAS 组织，AI Scan coverage report 应和 merge protection、SARIF、alert tracking 放在一张门禁表里。
8. Copilot CLI 1.0.86-1 的 include-custom-instructions 让自定义 agent 可以继承仓库指令，适合统一团队规范，但必须先验指令优先级。
9. 恢复会话后保留 marketplace plugins 和 skills 是长会话稳定性信号，尤其适合检查“换车”后工具是否还在。
10. sandbox policy 报告 local-network access，说明网络边界正在变成 CLI 运行小票的一部分。
11. background shell 状态从 Working 改成 waiting for background shells，适合减少“任务还在工作还是 dev server 没关”的误判。
12. Copilot CLI 1.0.85 stable 把 Vim、context management、concise transcript、/config、sandbox network host allow/deny、session/memory import 合并成更完整的 operator surface。
13. transcriptView concise 适合日报/自动化，但验收时仍要能展开工具活动，避免只保留漂亮摘要。
14. session/memory import 支持 semantic JSONL interchange，适合迁移，但必须做隐私过滤和字段契约检查。
15. Copilot CLI 1.0.86-0 可以恢复 recoverable corrupted transcript，长任务应加入故意损坏 transcript 的恢复 smoke。
16. Autopilot accepted-completion 后停止，说明“完成后不要继续乱跑”也开始进入运行时修复范围。
17. OpenAI Node 7.17.0 的 compaction progress events 提醒我们: 上下文压缩不是黑盒，应进入 run receipt。
18. preserve chat runner abort reasons 对 UI 和自动化都关键；失败状态要区分用户取消、超时、策略拒绝和运行时错误。
19. OpenAI Codex 0.155.0 alpha tag 很活跃，但 release body 仍薄，不能据此声称功能变更，只能列为 release-line watch。
20. 今天的主线可以归纳为: 授权、身份、预算、安全覆盖、指令继承、会话恢复、压缩遥测，都是让 agent 从 demo 进入运营系统的小票。

### 可沉淀知识卡片

#### 卡片 1: Enterprise Credential Delegation Receipt

- 概念: 把企业 SSO 下的 PAT/SSH 授权变成 GitHub App 可审计流程，而不是靠人逐个组织手动点。
- 使用场景: SSO CREDENTIALS
- 操作步骤:
  1. 确认 enterprise-level SSO、GitHub App 所属企业/组织、enterprise_credentials:write 权限。
  2. 记录非秘密 credential identifier: classic PAT token ID 或 SSH key fingerprint。
  3. 记录 target organizations、skipped organizations、installation token 一小时有效期和操作人。
  4. 轮换 token 或新增组织时重新跑授权，并保留失败组织清单。
- 风险: 如果把它当成“批量传密钥”，会把自动化便利变成凭证泄露风险。

#### 卡片 2: AI Budget Escalation Queue

- 概念: Copilot 额度追加要像费用申请一样进入队列，而不是谁卡住谁临时加钱。
- 使用场景: AI COST OPS
- 操作步骤:
  1. 记录申请人、触发任务、当前额度、请求额度和付费账号。
  2. 审批时写明 approved amount、有效期、拒绝原因或调整原因。
  3. 恢复访问后复盘是否真的完成了高价值任务。
  4. 把异常高频申请和模型路由/任务类型联动分析。
- 风险: 只批准额度、不看任务价值，会让 AI 成本变成看不见的漏水。

#### 卡片 3: Instruction Inheritance Contract

- 概念: 自定义 agent 继承仓库指令前，要先定义哪些指令会被读、优先级是什么、能不能被恢复会话保留。
- 使用场景: AGENT INSTRUCTIONS
- 操作步骤:
  1. 列出 AGENTS.md、copilot-instructions.md、CLAUDE.md 的读取顺序和作用域。
  2. 为 include-custom-instructions 准备一组冲突样例，验证谁覆盖谁。
  3. 恢复会话后检查 marketplace plugins、skills、working directory 和 plugin directory 是否保留。
  4. 记录 sandbox local-network 状态和 background shell waiting 状态。
- 风险: 指令继承如果不验优先级，agent 可能听到多套互相冲突的规矩。

#### 卡片 4: AI Scan Coverage Gate

- 概念: AI Scan 覆盖率要按 enablement 和 repository eligibility 算，不再只看 CodeQL default setup。
- 使用场景: PR SECURITY
- 操作步骤:
  1. 列出 organization-owned、personal、GHAS eligible repositories。
  2. 分别检查 code scanning、AI Scan 和企业/组织/仓库级 enablement。
  3. 把 PR 上的 AI Scan、code scanning alerts、merge protection 和 SARIF 证据放在同一张表。
  4. 对没有 CodeQL default setup 但可运行 AI Scan 的仓库补覆盖标记。
- 风险: 还按旧口径统计，会低估 AI Scan 覆盖，也可能漏掉没启用的仓库。

#### 卡片 5: Compaction Progress Telemetry

- 概念: 长上下文压缩不能只说“系统会处理”，要把 compaction progress 和 abort reason 暴露进运行小票。
- 使用场景: LONG CONTEXT
- 操作步骤:
  1. 记录 compaction start/progress/end 事件和关联 run id。
  2. 保存 abort reason，而不是只写 canceled 或 failed。
  3. 把压缩前后的关键约束、权限边界、验收命令做摘要对照。
  4. UI 或日志只展示 metadata，不展示敏感 payload。
- 风险: 没有压缩进度和中止原因，长任务失败时很难判断是上下文丢失、用户取消还是运行时故障。

## 白话版

今天的 AI 圈不是又来一个“更聪明的大脑”，而是办公室制度补齐了一圈。

第一是门禁和工牌。GitHub 现在能用企业安装的 App 批量给 PAT 和 SSH key 做 SSO 授权，SCIM 也多了 profileUrl。白话说，以前员工每进一个分公司都要手动刷门禁，现在总部可以按规则批量开门，而且员工档案里多了一个更稳定的 GitHub 主页编号。

第二是报销。Copilot 额度用完后，成员可以直接申请加预算，审批会走到真正付钱的组织或企业账号。意思是 AI 不再只是“想用就用”，它开始像差旅费一样，需要说清楚谁申请、为什么申请、批多少、用完有没有产出。

第三是安检。AI Scan 不再必须依赖 CodeQL default setup 才能跑，像是机场多了一条 AI 安检通道。问题是旧地图上可能还标着“只有 CodeQL 柜台开了才算安检覆盖”，现在覆盖口径要重画。

第四是岗位说明书。Copilot CLI 的自定义 agent 可以选择读取 AGENTS.md、copilot-instructions.md、CLAUDE.md 这些仓库指令，像新同事入职时终于能拿到团队手册。但手册多了也会冲突，所以要先验谁优先、谁覆盖谁。

第五是长途行车记录仪。OpenAI Node SDK 开始给 compaction progress 和 abort reason 留事件。长会话像长途开车，以前只知道“车停了”，现在至少能知道是换车、堵车、司机取消，还是车自己报错。

今天最值得带走的一句话: AI 同事越来越正式，所以别只问它会不会干活；还要问它有没有工牌、预算、岗位说明书、安检记录和行车记录仪。
