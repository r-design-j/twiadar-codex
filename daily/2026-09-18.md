### Codex/GPT 工作流启发

1. Copilot impact dashboard 的 feature engagement 说明 adoption 已经从“总活跃用户”细化到“具体功能是否被稳定使用”。
2. 28-day active-user 口径适合判断启用后的真实习惯，不适合拿来证明某个单日任务完成。
3. agentic CLI customizations 进入 usage metrics API 后，skill、custom agent、MCP、slash command、plugin 都应该进入工具投资复盘。
4. plugin totals 是 skill totals 的子集，不能把两者相加；否则会重复计算。
5. customer-defined names 被隐藏成 other/custom 是隐私保护，不是采集失败。
6. Workflow execution protections GA 后，Actions 自动化必须把 actor、event、workflow path 和 evaluate/enforce 状态写入治理小票。
7. public repo 的 pull_request_target 默认保护有 2026-11-02 enforcement 节点，开源仓库要提前跑 insights。
8. Ubuntu 26.04 GA 和 ubuntu-latest 迁移会影响 AI 自动化的 CI 基线，尤其是依赖系统包、编译器、预装二进制的项目。
9. Copilot CLI 1.0.86 stable 把昨天的 prerelease 能力收进稳定线，升级检查重点是指令继承、resume、sandbox 状态和 transcript 恢复。
10. OpenAI Codex 0.155.0 stable 的关键不只是 voice，而是 operator surface: 任务隐藏/归档/删除、Touch ID MCP 验证、daemon 更新与恢复。
11. Codex 里 account switch 会清理旧身份的 remote-control session、WebSocket cache 和 model catalog，这提示所有长任务都要记录身份归属。
12. Node 7.18.0 与 Python 3.15.0 同步出现 managed Responses WebSocket sessions，说明 SDK 会话生命周期正在被正式化。
13. prompt-cache prewarming 值得进性能小票，但必须记录命中证据，不能只写“已预热”。
14. agent session model settings 要和路由、预算、验收命令绑定，否则会变成看不见的模型漂移。
15. Python 新增 preserve chat stream moderation results，提醒我们不要在流式会话里丢掉安全/审核结果。
16. Claude Code 2.1.275 的账号确认、token redaction、npm pack --ignore-scripts 和 integrity verification 可作为跨工具供应链清单。
17. telemetry helper failure warning 是重要信号: 没有遥测不应静默成功。
18. queued-message send-now 让长会话插队/合并输入更可控，但要把“哪些消息已排队、何时被模型接收”写入 transcript。
19. claude plugin eval 的测试集 + grader + no-plugin baseline 模式，适合迁移到 Codex/Claude 双栈插件治理。
20. 今天的总原则: AI 工具链进入运营期，所有“能跑”的能力都要配 adoption、permission、runtime、session、upgrade 五类证据。

### 可沉淀知识卡片

#### 卡片 1: Feature Engagement Ledger

- 概念: 把 Copilot 采用率从“有人用过”细化成“哪些功能在 28 天里被稳定使用”。
- 使用场景: COPILOT ADOPTION
- 操作步骤:
  1. 拉取 enterprise/org 28-day aggregate reports。
  2. 分开记录 active users、totals_by_feature、users_in_phase_28d 和 null/absent 字段。
  3. 把 code completion、agent edit、code review、cloud agent、CLI、app 分开看，不混成一个总数。
  4. 对低采用功能关联培训、配置缺口和实际任务类型。
- 风险: 只看总活跃人数，会把“大家都开了”误判成“大家都会用关键功能”。

#### 卡片 2: Agentic Customization Usage Ledger

- 概念: 把技能、自定义 agent、MCP、slash command、plugin 的使用情况变成可审计的采用证据。
- 使用场景: AGENT CUSTOMIZATION
- 操作步骤:
  1. 采集 totals_by_skill、totals_by_custom_agent、totals_by_mcp、totals_by_slash_cmd、totals_by_plugin。
  2. 同时记录 distinct_*_use_count，判断工具品类是否扩散。
  3. 注意 plugin totals 是 skill totals 的子集，禁止简单相加。
  4. 客户自定义名称被隐藏时，把 other/custom 当成隐私保护状态，而不是数据丢失。
- 风险: 把所有自定义项加总，会重复计算并误导投资判断。

#### 卡片 3: Workflow Execution Protection Gate

- 概念: 让能触发自动化的人和事件进入白名单，不让危险 workflow 靠默认权限裸奔。
- 使用场景: CI GOVERNANCE
- 操作步骤:
  1. 按 public/internal/private、deploy/release/CI 分类仓库和 workflow。
  2. 先用 evaluate mode 看哪些运行会被挡。
  3. 为敏感 workflow 设 actor rules、event rules 和 workflow path targeting。
  4. 将 insights、REST API 配置和被阻止运行写入治理记录。
- 风险: 直接 enforcement 可能阻断正常发布；完全不设规则则会放大 pull_request_target 和手动触发风险。

#### 卡片 4: Stable Codex Upgrade Receipt

- 概念: Codex 稳定版升级不只看版本号，要验操作界面、身份、任务生命周期和恢复能力。
- 使用场景: CODEX UPGRADE
- 操作步骤:
  1. 记录 tag、published_at、release body、关键 feature/fix 和资产来源。
  2. 本地 smoke 覆盖 /voice 开关、reasoning status、task hide/archive/delete、MCP verification。
  3. 重启 daemon 后检查 saved threads、active goals 和 account-switch cache。
  4. 验证失败时保留旧版本路径和回滚条件。
- 风险: 新稳定版可能改变操作者界面和身份边界，只看 CLI 是否启动不够。

#### 卡片 5: Managed Responses Session Contract

- 概念: Managed Responses WebSocket sessions、session model settings 和 prompt-cache prewarming 要作为同一条会话合同验收。
- 使用场景: SDK SESSIONS
- 操作步骤:
  1. Node 和 Python 都记录 SDK 版本、session model settings、WebSocket start/end/error。
  2. 测试 prompt-cache prewarming 是否真的命中并记录命中证据。
  3. 保留 compaction progress、moderation results、header/default validation 和关闭原因。
  4. 不同语言运行时用同一组 fixture 对齐行为。
- 风险: 只升级一个 SDK，可能让 Node/Python agent 在会话、缓存和错误处理上分叉。

## 白话版

今天的 AI 工具像从“临时外包”变成“正式部门”。

第一是考勤表。GitHub 不再只告诉你 Copilot 有没有人用，而是开始告诉你哪些功能被稳定使用: 补全、agent edit、代码评审、cloud agent、CLI、app。以前像只看公司门口有多少人刷卡，现在能看到大家到底进了会议室、实验室还是客服台。

第二是工具登记表。skills、custom agents、MCP、slash commands、plugins 进入 usage metrics API。白话说，以前大家桌上有什么工具靠问，现在公司能看到哪些工具真的每天被拿起来用。但 plugin 是 skill 的一部分，不能像算账时把“水果”和“苹果”各算一遍。

第三是门禁白名单。Actions workflow execution protections GA 了，可以规定谁能触发 workflow、什么事件能触发、哪一个 workflow 文件受保护。就像仓库不再是谁有钥匙都能开卷帘门，而是 deployment 门、CI 门、release 门各有超市上架清单。

第四是设备升级验收单。Codex 0.155.0 稳定版不是单纯“版本号变大”，它多了 voice、任务管理、Touch ID MCP 验证、daemon 更新和恢复。像工作台换了一套控制面板，必须确认按钮位置、门禁、重启恢复都正常。

第五是行车记录仪。OpenAI Node/Python SDK 都在补 managed Responses WebSocket sessions、session model settings、prompt-cache prewarming。长任务以后不能只说“我连上了”，还要说用的哪辆车、路线怎么预热、断线怎么收尾。

今天最值得带走的一句话: AI 同事越来越正式，所以别只问它能不能干活；还要看考勤、工具登记、门禁白名单、升级验收和行车记录。
