### Codex/GPT 工作流启发

1. AI review 不再只是评论列表，而是一个可复核的 finding lifecycle。
2. Open/resolved/previously missed 三类评审状态适合进入 PR 收口小票。
3. 自动关闭评论必须尊重人类回复，否则会把“不同意”误当“已修复”。
4. 批量应用建议生成 commit message 很方便，但 commit title/description 仍要人工审一遍。
5. Copilot 模型 2026-10-19 退役是硬日期，固定模型脚本和 agent 配置要提前盘点。
6. GPT-5.5/GPT-5.4 到 GPT-5.6 Sol，mini 到 GPT-5.6 Luna，本质是路由合同迁移。
7. npm stage-only token 让自动化只能暂存版本，把最终发布重新交给维护者 2FA。
8. stage-only token 仍能移动 dist-tags 和 deprecate versions，不能降级成低敏凭证。
9. 覆盖率 ruleset API 化以后，coverage gate 可以进入基础设施即代码。
10. Codex 0.155.1 的 reasoning summaries 默认值修复说明 provider 能力差异会直接影响本地 TUI 成败。
11. 显式 reasoning-summary 设置要被尊重，安全默认和用户选择必须拆开。
12. OpenAI Node/Python 都加入 webhook endpoint management，SDK 开始覆盖更多运营入口。
13. Webhook endpoint 不是普通配置；它涉及签名、事件白名单、重试、幂等和环境隔离。
14. Python 3.16.1/3.16.2 的 first-use loading 和 parse_response memory 修复提醒长跑 agent 要看资源曲线。
15. Copilot CLI 1.0.87-0 的 worktreePathTemplate 会影响本地多分支工作区的可追踪性。
16. pending prompt recall 让长会话插队更安全，但 transcript 仍要记录哪些消息被撤回或发送。
17. per-server MCP slow-connection thresholds 可以把“工具慢”从主观感受变成可调指标。
18. Claude Code 的 AGENTS.md fallback 说明跨工具指令文件正在趋同，但每个工具的读取优先级仍需实测。
19. 代理/网关相关 hotfix 要进入升级第一道 smoke，因为它能让所有请求同时失败。
20. 今天的总原则: AI 工具进入运营化后，每个高级能力都要有状态、日期、门禁、资源和回滚记录。

### 可沉淀知识卡片

#### 卡片 1: Review Progress Receipt

- 概念: 把 AI 代码评审从一堆评论变成可追踪的进度账本。
- 使用场景: AI REVIEW OPS
- 操作步骤:
  1. 记录每个 finding 的 open、resolved since last review、previously missed 状态。
  2. 保留 severity、inline comment link、review effort level 和生成时间。
  3. 对自动关闭的评论记录 resolution reason；对人类要求保留的问题做 override 标记。
  4. 批量接受建议时，单独审阅 AI 生成的 commit title 和 description。
- 风险: 只看评论数量会误判进度；真正重要的是哪些问题仍打开、哪些已被验证修复。

#### 卡片 2: Model Deprecation Migration Board

- 概念: 把模型下线当成一次有日期、有替代、有回归测试的迁移项目。
- 使用场景: MODEL GOVERNANCE
- 操作步骤:
  1. 列出旧模型、下线日期、建议替代模型和受影响入口。
  2. 读取管理员 model policy，确认替代模型是否自动启用或需要手动打开。
  3. 用固定任务比较输出质量、速度、成本和工具兼容性。
  4. 在用户可见 picker 改变前准备公告、回滚和例外清单。
- 风险: 等到模型消失才处理，会把路由失败伪装成 agent 能力下降。

#### 卡片 3: Stage-Only Publish Gate

- 概念: 让自动化只能把包放到待审核区，最终发布必须经过维护者 2FA。
- 使用场景: SUPPLY CHAIN
- 操作步骤:
  1. 为包创建 read/write stage-only granular token。
  2. 把 CI 命令从 npm publish 改为 npm stage publish。
  3. 由 maintainer 用 2FA 审核并批准 staged version。
  4. 记录 token 权限、dist-tag/deprecate 权限和 npm/node 最低版本。
- 风险: stage-only token 仍有写权限，不能因为不能 direct publish 就当成低敏凭证。

#### 卡片 4: Provider Capability Preflight

- 概念: 在打开 reasoning summary、工具调用或高级会话字段前，先确认目标 provider 是否支持。
- 使用场景: CODEX RUNTIME
- 操作步骤:
  1. 记录 provider、模型、客户端版本和默认开关。
  2. 先用最小请求验证 reasoning summaries、streaming、tool calling 等能力。
  3. 显式设置和安全默认分开记录；不要让默认值覆盖用户明确选择。
  4. 遇到 provider rejection 时降级能力，不扩大权限或更换账号绕过。
- 风险: 客户端支持某能力，不代表每个 provider 都接受对应请求字段。

#### 卡片 5: Webhook Endpoint Operations Ledger

- 概念: 把 SDK 管 webhook 当成线上入口治理，而不是普通 API 调用。
- 使用场景: SDK OPS
- 操作步骤:
  1. 盘点 endpoint URL、event allowlist、signing secret、owner 和环境。
  2. 记录创建、更新、禁用、轮换和删除动作的审批与回读结果。
  3. 测试签名验证、重试、幂等、失败告警和本地/生产隔离。
  4. SDK 升级时分开验证 Node 和 Python 的行为。
- 风险: Webhook 是外部系统进来的门，配置错了会把测试流量、生产事件和安全边界混在一起。

## 白话版

今天的 AI 工具像从“会写代码的同事”变成“要进公司制度的正式员工”。

第一是评审看板。以前 Copilot review 像给你贴一堆便利贴；现在它开始告诉你哪些便利贴还没处理、哪些已经处理、哪些是后来才发现的。这样你收 PR 时看的不是“纸条多不多”，而是“问题有没有真正关掉”。

第二是车型更换提醒。GitHub 说 2026-10-19 有一批 Copilot 模型要退役，像车队里几辆旧车到期下线。你不能等车钥匙打不开才换车，要提前把路线、司机习惯和备用车都试一遍。

第三是包发布门禁。npm stage-only token 像让自动化只能把货放到待审货架，不能自己按下正式上架按钮。最后上架还得维护者拿 2FA 确认。

第四是进门先问支持不支持。Codex 0.155.1 把 reasoning summaries 默认关掉，是因为有些 provider 不吃这个字段。白话说，同声传译再高级，也得先确认对方耳机支持这一路声音。

第五是 webhook 单独看门。OpenAI Node/Python SDK 开始管 webhook endpoint，等于 SDK 不只会叫模型干活，还能管理外部事件进来的门。门开给谁、怎么验签、失败怎么重试，都要有账本。

今天最值得带走的一句话: AI 工具越像正式员工，越不能只看它聪不聪明；要看评审单、车型迁移、发布门禁、能力预检和外部入口账本。
