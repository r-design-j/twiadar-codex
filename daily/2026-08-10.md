## 官方严谨版

### 今日结论

2026-08-10 的主线是: AI 工作台正在从“多入口统一”进入“多模态控制 + 权限治理 + 可复用技能”的阶段。Codex CLI 0.147.0 在 2026-08-07 引入可移植 Agent Plugins、跨本地/个人/工作区/远程目录搜索和长会话分段浏览；OpenAI release notes 的 7 月 23 日更新把 Voice 放进 Work 和 Codex 桌面端；7 月 16 日桌面更新把 Chat、Work、Codex 的入口关系讲清楚；7 月 9 日引入 Work、Sites、Plugin Directory，并明确 Atlas 已在 2026-08-09 停止工作。对今天来说，Atlas 退场是一个强提醒: 浏览器、cookie、书签、打开标签页、历史记录和公开日报素材必须分层处理，不能把本地状态当成公开证据。

OpenAI Work/Codex 文档进一步明确: Chat 适合快速判断，Work 适合长任务和成品交付，Codex 适合仓库、命令、测试和本地技术执行；Voice 只是控制入口，使用的是对应体验已有的工具和权限。Plugins 文档把技能、app、app template 和源系统权限分开，说明“装了插件”不等于“拿到数据”；Sites 文档把 public publish 放进可审查流程；Record & Replay 则把“演示一次流程”变成 Codex skill 的来源。

工程侧的对应变化是: Agents SDK v0.19.4 修复 Guardrail、MCP、Session、并发失败取消和 Sandbox token 预算等可靠性问题；GitHub 侧 Copilot code review 读取 `AGENTS.md`、Copilot Desktop 支持 worktrees、GitHub MCP Server 支持 stateless spec、JetBrains/Visual Studio 继续补 OTel、模型治理、MCP trust 和成本可见性。这些都指向同一件事: agent 不缺入口，缺的是边界、可观测性、版本化 instructions、可回放的技能和收口证据。

对个人 AI Radar 的直接启发是: iPhone/Remote/Voice 只做控制面；Mac/Codex 做执行和验收面；Work 做研究和文档成品；Sites 做公开展示但必须区分草稿、预览、发布和公开 URL；插件启用前要有“超市上架清单”；Record & Replay 只适合低风险重复流程，录制前先确认凭证、私有数据和外部副作用不会被带进去。

### Codex/GPT 工作流启发

1. Codex 插件目录要先低风险试跑

Codex CLI 0.147.0 的重点不是“又多了插件”，而是插件开始进入可搜索、可携带、可分发的目录体系。个人使用前应先在低风险仓库试跑，确认插件来源、依赖 app、读写动作、确认门和可回滚路径。

2. Voice 是控制面，不是权限放大器

Voice in Work/Codex 可以让你口头启动、打断、转向和协调任务，但它使用的是当前 Work 或 Codex 体验已有的工具和权限。对自动化来说，语音指令不能越过任务胶囊、审批、目录边界和最终验收。

3. Atlas 退场提醒浏览器状态不能混进公开产物

Atlas 已计划在 2026-08-09 停止工作，迁移涉及 conversation、bookmarks、open tabs、history、cookies/passwords 等不同层级。AI Radar 只能公开可复核链接和总结后的知识卡，不能把截图、cookie、书签、登录状态或本地浏览器证据写进日报。

4. Work、Codex、Sites 要分清产物状态

Work 可以交付报告、表格、演示和 Sites；Codex 负责仓库、测试、diff 和发布；Sites 有 private preview、public publish、public URL 和管理设置。不能把“Work 草稿生成”说成“站点已发布”，也不能把“本地 JSON 校验通过”说成“Vercel Ready”。

5. 插件需要权限上架单

Plugins 文档把 skills、apps 和 app templates 分开。插件可见不等于可用，插件可用不等于源系统授权，app template 还可能只是草稿。启用前要检查 role access、actions、approvals、sync、domain、source boundary 和低风险测试。

6. Record & Replay 适合沉淀低风险重复流程

Record & Replay 可以把一次人工演示转成 Codex skill，适合下载公开报表、配置重复 issue、发布低风险素材等流程。录制前必须避开凭证、私密页面、外部写动作和不可逆提交；生成 skill 后还要人工审查步骤和边界。

7. Codex tool 要像同声传译一样限定范围

Agents SDK 的 Codex tool 让上层 agent 把任务转交 Codex。它像同声传译: 可以把业务意图翻译成仓库操作，但必须清楚翻译哪一间屋子、能不能写、谁批准、日志怎么交、失败怎么停。

8. Agents SDK 小版本升级也要跑回归

v0.19.4 这种小版本修复会影响 Guardrail 结果保留、无效参数脱敏、Session 保存、并发失败取消和 Sandbox token 预算。长流程 agent 的稳定性常卡在这些边角上，升级前后要有最小回归。

9. `AGENTS.md` 正在变成跨工具的仓库规则入口

GitHub code review、Desktop commit authoring 和 IDE agent flows 都开始读取 `AGENTS.md` 或相邻 instruction 文件。仓库规则应短、可执行、可测试，指向更深资料，而不是塞成一本长说明书。

10. MCP stateless 化提高扩展性，也提高验收要求

Stateless MCP 减少 sessions 和 initialize 写入，让远程 server 更好扩展；同时 conformance tests 变成必要证据。私有 MCP 的完成标准不应只是“能连上”，还要有协议、鉴权、日志、密钥扫描和回滚计划。

11. GitHub Desktop worktrees 是个人 agent 编队的基础设施

GitHub Desktop 3.6 支持 worktrees，并把 Copilot 介入 commit authoring 和 conflict resolution。对个人 Codex 编队来说，worktree 是隔离并行任务的基本单元；共享同一工作树并发写文件会放大冲突。

12. 公开 X 案例说明“管理 agent”比“多开 agent”更关键

Degen Sing 的公开 X 长帖把一人 AI dev team 拆成 orchestrator、agent spawn、tmux redirect、monitoring cron、task registry 和 Definition of Done。可复用点不是夸张提交数，而是明确任务登记、隔离 worktree、监控和不可谈判的完成条件。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 做提醒、审批低风险动作、查看状态和补充转向。
2. Voice: 在桌面端口头启动或转向 Work/Codex，但不替代权限和验收。
3. Chat: 做快速判断、来源筛选和任务胶囊。
4. Work: 做长研究、结构化报告、表格、演示和 Sites 草稿。
5. Codex: 做本地仓库、命令、测试、diff、commit、push、deploy。
6. Sites: 做公开展示；必须区分 preview、public publish、production alias 和回读。
7. Plugins: 启用前走权限上架单，默认只读，写动作加确认门。
8. Record & Replay: 只录低风险重复流程；录制后审 skill，再跑低风险烟测。
9. GitHub: 用 `AGENTS.md`、worktrees、MCP conformance 和 Copilot metrics 管理 agent 工作。
10. Knowledge: 当天只沉淀可复用卡片，不把新闻摘要伪装成知识资产。

### 可沉淀知识卡片

#### 卡片 1: Voice 控制面验收环

- 概念: Voice in Work/Codex 只能发起、询问、打断和转向任务，不能替代权限、目录边界、测试、diff 或发布证据。
- 适用场景: 桌面端口头派工、长任务中途转向、远程查看 agent 状态。
- 操作步骤: 说出目标 -> 确认体验是 Work 还是 Codex -> 限定读写边界 -> 回看状态 -> Mac/Codex 跑最终验收。
- 风险: 把口头“帮我发一下”误当成外部写权限，会越过审批。
- 原文: https://help.openai.com/en/articles/20001275

#### 卡片 2: 浏览器状态分层迁移

- 概念: conversation、bookmarks、open tabs、history、cookies/passwords 是不同迁移对象，公开日报只保留链接和总结。
- 适用场景: Atlas 退场、浏览器迁移、ChatGPT desktop browser、网页采集自动化。
- 操作步骤: 导出公开 URL -> 单独处理书签和历史 -> 排除 cookie/password/screenshot -> 迁移后只读回看 -> 公开材料只写来源链接。
- 风险: 把浏览器状态当证据公开，会泄露账号与隐私。
- 原文: https://help.openai.com/en/articles/6825453-chatgpt-release-notes

#### 卡片 3: 插件权限上架单

- 概念: 插件是 skills、apps、app templates 的容器；真正的数据和动作权限来自 app 设置与源系统权限。
- 适用场景: GitHub、Gmail、Vercel、Slack、Drive、Notion、CRM、数据仓库插件。
- 操作步骤: 查 required apps -> 查 role access -> 查 read/write actions -> 配 approvals -> 限 sync/domain/source -> 低风险烟测。
- 风险: 插件安装不等于数据授权；source system 权限过大时风险会被继承。
- 原文: https://help.openai.com/en/articles/20001256-plugins-in-chatgpt-and-codex

#### 卡片 4: 可回放 skill 录制门

- 概念: Record & Replay 能把演示流程转成 skill，但只能录低风险、可复核、可回滚的重复动作。
- 适用场景: 下载公开报表、固定格式发布、配置 issue、生成例行文档。
- 操作步骤: 先写不做事项 -> 关闭私密页面 -> 演示最短路径 -> 审查生成 skill -> 低风险烟测 -> 加入版本管理。
- 风险: 把含凭证、外部提交或私有数据的流程录进去，会把隐私和副作用固化成自动化。
- 原文: https://learn.chatgpt.com/docs/extend/record-and-replay

### 待确认/待对齐

## 白话版

今天这期像是在给一个越来越智能的办公室重新贴门牌。

以前你只要知道“ChatGPT 能聊、Codex 能写代码”。现在不够了。桌面 app 里有 Chat、Work、Codex，旁边还多了 Voice、Sites、Plugins、Record & Replay。工具多了，最大的问题不是“会不会做”，而是“谁能进哪间屋、能不能动手、动手后有没有小票”。

Voice 像对讲机。你可以对着它说“帮我看看进度”“暂停一下”“把这个任务交给 Codex”。但对讲机不是万能钥匙。它不能让一个没有权限的人突然进仓库，也不能把没跑测试的改动说成已完成。

Work 像写作和研究工作台，适合做报告、表格、演示、网站草稿。Codex 像车间，负责仓库、命令、测试、diff、commit、push、deploy。Sites 像展厅，只有真正发布并回看过，才算摆上货架。

插件像超市上架清单。一个插件可能带 skills，也可能要接 GitHub、Slack、Drive、Gmail。你不能只看“这个插件装了”，还要看它背后每个 app 能读什么、能写什么、要不要你确认、能不能同步数据。清单没写清楚，就容易把不该卖的货也放上架。

Atlas 退场像搬家。搬家时，聊天记录、书签、打开的网页、浏览历史、cookie、密码不是同一类东西。能公开的是“这个公开链接有用”，不能公开的是“我浏览器里当时是什么状态”。日报只带公开链接和整理后的经验，不搬私人物品。

Record & Replay 像把你做菜过程录下来，让下次厨房自动照做。适合录“打开公开报表、下载、整理成固定格式”这种安全流程；不适合录“登录、付款、发消息、提交不可逆表单”这种动作。录之前先把桌面收干净，别把密码和私货录进去。

GitHub 的变化像给车间装了更多摄像头和规章牌。`AGENTS.md` 告诉 reviewer 你们家的规矩，worktrees 让多个 agent 分开干活，MCP conformance 像验收工具接口的年检。真正能复用的 agent 工作流，最后一定要有边界、日志、测试、diff 和回滚。

一句话: 今天不是“多开几个 agent”，而是“给每个入口贴门牌、给每个插件列清单、给每次自动化留小票”。门牌和小票齐了，AI 工作台才不会越用越乱。
