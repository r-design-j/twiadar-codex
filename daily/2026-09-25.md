### 可沉淀知识卡片

#### 卡片 1: Local Agent Sandbox Receipt

- 概念: 把本地 agent 的文件、网络和凭证权限记录成可回读的小票，而不是只写“开了沙箱”。
- 使用场景: SANDBOX OPS
- 操作步骤:
  1. 记录项目级默认、会话级开关、企业托管设置和实际生效策略。
  2. 把 additional read/write、read-only、denied folders、outbound internet、local network 和 credentials 分开。
  3. 确认当前 OS 能执行该策略；不能执行时应失败停止。
  4. 沙箱变更只声明影响新会话、重启会话或当前会话，不混写。
- 风险: 请求的策略和实际生效策略可能不同；企业设置和 OS 能力会让结果更严格或直接失败。

#### 卡片 2: Agent Telemetry Boundary

- 概念: 给 agent 监控建立边界：看流程、工具和模型调用，但内容采集要单独审批。
- 使用场景: OBSERVABILITY
- 操作步骤:
  1. 记录 OTel endpoint、resource attributes、owner、环境和启用范围。
  2. 默认不采集 prompt/response 内容；如要采集，另走审批和保留策略。
  3. 把 model request、tool use、session flow 和错误调查分成不同 trace 视角。
  4. 公开报告只写观测能力和方法，不写监控端点或敏感 span 内容。
- 风险: 可观测性如果没有内容边界，会从排障工具变成隐私和合规风险。

#### 卡片 3: Review Effort Policy Ladder

- 概念: Copilot review effort 要按个人、企业、组织、仓库和单次请求分层记录。
- 使用场景: CODE REVIEW
- 操作步骤:
  1. 记录个人 automatic review、draft PR、新 push 和默认 effort。
  2. 记录企业默认 effort 以及组织/仓库覆盖关系。
  3. 手动请求 review 时保存当次选择，避免误以为等于默认值。
  4. 比较效果时同时记录 Lite/Balanced、PR 类型和触发来源。
- 风险: review effort 混在一起，会让代码审查质量、成本和责任边界都难以复盘。

#### 卡片 4: Node 24 Actions Migration Gate

- 概念: JavaScript Actions 迁移到 Node 24 是运行时硬门槛，要做仓库和 runner 两侧扫描。
- 使用场景: CI MIGRATION
- 操作步骤:
  1. 扫描 action.yml/action.yaml 中 runs.using=node20 的自研 action。
  2. 升级到 node24 后发布新 tag，并让下游 workflow 引用新版本。
  3. 盘点 self-hosted runner 的 macOS 和架构，老 macOS 与 ARM32 需要替换。
  4. 删除依赖临时 opt-out 的流程，并跑一次真实 workflow smoke。
- 风险: 只升级官方 action 不够；自研 action 和自托管 runner 才是最容易被漏掉的断点。

#### 卡片 5: Voice-to-Device Codex Loop

- 概念: 把语音、Codex、本地渲染器和实体设备拆成可调试链路。
- 使用场景: MOBILE WORKFLOW
- 操作步骤:
  1. 先定义人类反馈入口：Voice、桌面 ChatGPT 或移动端指令。
  2. 让 Codex 负责 renderer、skill 和集成代码，但由人反馈真实显示效果。
  3. 本地 Mac/设备 controller 只接收明确帧或命令，避免模型直接碰设备权限。
  4. 记录每次迭代的目标、视觉问题、代码变更和设备读回。
- 风险: 实体设备反馈不能靠日志替代；看得清、听得懂、能恢复才算可用。

## 白话版

今天的 AI 工具更新，像施工队终于不只是“师傅会干活”，而是开始配围挡、监控、审稿标准和设备换发动机清单。

第一件事是围挡。Copilot app 的本地沙箱可以按项目限制文件、网络和凭证。白话说，施工队不是想去哪间房就去哪间房；哪些门能开、哪些网络能连、哪些钥匙能用，都要先写清楚。

第二件事是监控。OpenTelemetry 让企业能看 agent 一路调用了什么模型、用了什么工具、在哪一步出错。但这不等于可以把聊天内容都录下来。监控摄像头可以看动线，收音麦克风要另批。

第三件事是审稿标准。Copilot code review 现在有个人设置和企业默认 effort。就像一篇稿子到底是快看一眼，还是认真逐段批注，不能每次临场猜；个人、企业、仓库和单次请求都可能有自己的标准。

第四件事是流水线换发动机。GitHub Actions 不再给 Node 20 JavaScript actions 留后门，临时豁免也没了。自研 action 和老 self-hosted runner 如果没迁移，下一次坏的可能不是代码，而是发布管道。

第五件事是模型车队继续扩编。Codex stable 和 Copilot CLI 都开始把 GPT-6 Sol/Luna 放进选择器。Sol 像主力车，Luna 像省油快车；重点不是看到车就上，而是先决定这趟活该派哪辆。

最后，OpenAI 那个 LED display 案例很有意思：人用 Voice 说需求，Codex 写 renderer 和 skill，Mac 把画面变成小屏幕能吃的帧，再发给实体灯板。它提醒我们，个人 AI 工作流不一定只停在文档和代码里，也可以接到真实桌面和设备上；但真实设备要靠肉眼验收，不能只看日志说“应该亮了”。

今天最值得带走的一句话: agent 越像一个能干活的同事，越要给它围栏、监控边界、审稿标准、运行时迁移表和能回看的工作小票。
