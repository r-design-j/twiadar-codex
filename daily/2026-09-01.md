### Codex/GPT 工作流启发

1. alpha release 是“观察信号”，不是“生产默认”。今天 0.152 alpha 线密集发布，应该先进入单独 lane。
2. 0.151 stable 仍是更适合生产验证的基线；先把 MCP result inspection、插件目录、沙箱路径、权限恢复和预算聚合跑通。
3. alpha lane 要有 owner、版本 pin、验证任务、回滚路径和“不自动推广”规则。
4. release body 很短的 alpha 版本不能提供完整行为合同；需要对 config schema、资产签名、二进制分发和真实命令做本地读回。
5. Copilot CLI 的 proxy mTLS 支持提醒: 代理 CLI 的网络能力会碰到企业代理和客户端证书，凭证边界必须独立记录。
6. `/sandbox` policy 把路径授权按来源分组，说明授权不只看最终路径，还要看是谁授予、为什么授予、何时撤销。
7. 检测到的 developer tools 应该进入本地验收，而不是进入公开日报；公开输出只写总结和公开链接。
8. Agents SDK Python/JS 都在收紧被 guardrail 拒绝的工具输出 replay，说明“拒绝了”不等于“副作用不存在”。
9. 明确 OpenAI client 配置位置，可以避免 `organization/project` 写在无效层级里造成审计错觉。
10. usage accounting 隔离适合进入长任务预算表；子任务、恢复、嵌套 agent 不能只看主会话 token。
11. scheduled tasks 和 app updates 的组合仍要写 idempotency key，避免同一邮件、issue 或 Slack 事件重复触发。
12. Apple Messages/Gmail/Slack 等发送面继续保持 draft、recipient confirmation、send approval 三段式。
13. GitHub Copilot 的统一策略和 mobile/cloud agent 合流，说明移动端是控制面，不能代替本地验收证据。
14. Claude Code hooks 可继续作为生命周期参考，但迁移到 Codex 时要重新定义事件名、权限和证据格式。
15. Obsidian/Agent Fleet 类工具适合沉淀 agent run log，但 vault 写入要先限定 inbox/drafts。

### 可沉淀知识卡片

#### 卡片 1: Alpha Lane Upgrade Gate

- 概念: 把 alpha、beta、nightly、preview 版本放进独立验证 lane，禁止自动替换生产默认。
- 使用场景: Codex alpha、Copilot CLI prerelease、Agents SDK RC、浏览器自动化 beta、插件市场预发布。
- 操作步骤:
  1. 记录版本、发布时间、来源链接、是否 prerelease 和 release body 完整度。
  2. 固定验证任务，不用生产仓库首跑。
  3. 标注 owner、可写目录、网络边界、凭证边界和回滚命令。
  4. 跑最小真实任务并保存本地证据。
  5. 只有稳定版或明确批准后才推广默认值。
- 风险: alpha 更新速度快，昨天可用的行为今天可能已变化。

#### 卡片 2: Proxy Credential Boundary

- 概念: 当 agent CLI 支持企业代理、mTLS 或客户端证书时，把网络路由和凭证授权当成独立风险面。
- 使用场景: GitHub Copilot CLI、Codex CLI、公司代理、私有包仓库、内网 MCP、浏览器自动化。
- 操作步骤:
  1. 标明代理地址、证书来源、适用域和有效期。
  2. 日志默认脱敏，不把证书路径、指纹或账号细节写入公开报告。
  3. 区分模型请求、网页请求、包管理请求和 Git 请求。
  4. 每次失败记录 HTTP 状态和证书错误类型，不直接重试到更宽权限。
  5. 保留撤销、轮换和本地只读检查路径。
- 风险: 代理打通后，agent 的外联面会比原计划更宽。

#### 卡片 3: Sandbox Grant Receipt

- 概念: 每次给 agent 授权路径、工具或开发环境，都留一张“授权小票”，写清来源、范围、原因和撤销条件。
- 使用场景: `/sandbox` policy、Codex permission profile、MCP server、developer tools、workspace mount、view_image 额外路径。
- 操作步骤:
  1. 记录 grant source、path/tool、read/write、reason、owner、time。
  2. 把自动检测到的 developer tools 与手动授予的权限分开。
  3. 输出进入公开站点前做 local-path/secret scan。
  4. 恢复会话后重新读权限，不沿用旧分类。
  5. 任务完成后撤销临时授权或记录保留理由。
- 风险: 只看最终能访问什么，会漏掉权限是如何来的。

#### 卡片 4: Replay-Safe Guardrail Contract

- 概念: 被 guardrail 拦截的工具输出不能再通过 replay、checkpoint、session store 或应用自有副本回到模型上下文。
- 使用场景: Agents SDK、Responses API、tool output guardrails、approval checkpoint、长会话恢复、持久化 agent。
- 操作步骤:
  1. 标注哪些输出可持久化、哪些只能本地短期审计。
  2. guardrail trip 后替换或 withheld 模型可见内容。
  3. 外部副作用单独记录，不因 replay 清理而假装已撤销。
  4. 对 live RunState、serialized checkpoint 和 new run 三种路径分别测试。
  5. 应用自有日志也做同等脱敏策略。
- 风险: SDK 清理 replay state 不会自动清理外部系统和应用自有存储。

## 白话版

今天这期像“楼下施工队贴出了临时通行证”。Codex 0.152 alpha 不是正式门禁卡，而是施工期间用的临时卡。它很有价值，因为能看出大楼下一步要改哪里；但你不能拿临时卡直接给全公司换门禁。

昨天我们重点查旧门禁卡有没有失效；今天重点是给新临时卡划一个试用区。试用区里可以跑小任务、看日志、查权限、验证工具，但不能直接改生产默认值。等它变成正式卡，或者你明确批准，再推广。

Copilot CLI 的 mTLS proxy 像给施工队开了公司大门的专用通道。通道本身不是坏事，但必须写清楚: 哪张证书、能去哪里、谁批准、日志怎么脱敏、什么时候收回。不然通道越顺，越容易忘记它其实连着公司的内网和外网。

`/sandbox` policy 的路径授权像施工许可证。以前只看“能进哪个房间”，现在要看“是谁批的、为什么批、批到什么时候”。所以我们要留 Sandbox Grant Receipt，也就是授权小票。

Agents SDK 的 guardrail replay 安全像保洁阿姨发现一袋危险垃圾后，不只要把它从客厅拿走，还要确认它没有被复制到储藏间、备份箱和下一次搬家清单里。被拦截的工具输出不能因为恢复会话又回到模型眼前。

所以今天的动作不是追热点升级，而是把新版本、新代理、新沙箱、新恢复机制都放进有边界的试用流程。能试、能看、能回滚，才值得继续。
