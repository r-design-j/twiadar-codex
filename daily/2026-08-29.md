### Codex/GPT 工作流启发

1. 模型迁移要当成发布变更，不是 UI 选择题；2026-08-31 前要扫自动化、托管配置、团队文档和旧模板。
2. API-key Codex 与 ChatGPT 登录态 Codex 的模型可用性边界不同，迁移清单必须分认证方式。
3. Browser lane 要继续细分: local browser 适合已登录本机页面，Site tools(WebMCP) 适合结构化站点动作，cloud browser sign-in 适合跨端任务但不能继承本地 profile。
4. Webhook scheduled task 把自动化从 cron 变成事件驱动；每条事件任务都要记录来源 app、payload schema、幂等策略和重复事件处理。
5. 插件市场自动同步降低维护成本，但也会把“上架清单”变成活配置；必须保留 allowlist、版本 pin、变更 diff 和回滚入口。
6. Apple Messages 这类插件把 Work/Codex 推到真实外部副作用边界；准备草稿和发送消息必须分开审批。
7. GitHub 的统一 Copilot 策略说明移动端、网页端和云 agent 会越来越像同一会话系统；保留期、默认开启和策略继承不能靠口头约定。
8. Copilot CLI 的 defaultMode/defaultPermissionMode 值得借鉴到 Codex 自动化: 每个任务模板固定执行模式、权限模式、恢复策略和中断处理。
9. Bot-authored PR 和超大 PR 能被 agent 审查后，人的职责不该退化成“点通过”，而是检查独立性、测试证据和风险覆盖。
10. AI-to-AI code review 已经有大规模实证数据，但它仍是少数活动；不能把“AI 审过”直接等同于独立质量保证。
11. Claude Code hooks 的生命周期模型给了一个通用启发: 把 PreToolUse、PostToolUse、Stop、ConfigChange 类事件映射到 Codex/Work 的审计点。
12. Cato 假 Codex 事件说明品牌、搜索广告、Google Sites 和终端命令可以组合成攻击链；开发者安装说明也要纳入安全训练。
13. OpenAI Agents SDK 0.22.0 的 guardrail redaction、terminal failed/incomplete 抛错和 usage 隔离，适合固化到所有 agent runtime 升级验收。
14. 任何 persistent/proactive agent 的传闻或预告都只能作为 watch item，未官方发布前不进入生产依赖。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 发任务信封，只写目标、日期、允许公开来源、是否允许浏览器、停止条件和审批范围。
2. Work: 对 Gmail/Slack/GitHub 事件触发任务只先生成计划、摘要或草稿；涉及发送、上传、授权、删除、发布时停下。
3. Mac/Codex: 扫模型、自动化和配置，确认是否还有 GPT-5.4/GPT-5.4 mini；将迁移写入可回滚清单。
4. Browser: 开工前选 lane；local/UI lane 需要观察前态和读回，tool lane 需要 schema 和结果对象，cloud sign-in lane 不复用本地 profile。
5. GitHub: 对 agent-authored PR 打上审查标签，要求 bot reviewer、human reviewer、测试结果和风险说明各自有证据。
6. 安装: 任何 AI 开发工具只从官方域名、官方 GitHub、npm/pip 包名或已固定的内部上架清单安装；搜索广告不作为可信来源。

### 可沉淀知识卡片

#### 卡片 1: Model Migration Freeze List

- 概念: 在模型退场或默认模型切换前，把所有会引用旧模型的位置冻结成清单，逐项迁移并验收。
- 使用场景: Codex 模型退场、Copilot global model policy、团队托管配置、自动化任务、custom agents、CI agent。
- 操作步骤:
  1. 扫 workspace defaults、config、自动化、scheduled tasks、custom agents、文档模板和脚本。
  2. 区分 ChatGPT 登录态、API-key、本地 CLI、云端 agent 和第三方客户端。
  3. 给每项写旧模型、新模型、owner、迁移日期、验证命令和回滚方式。
  4. 迁移后跑最小关键任务，记录真实输出和失败边界。
  5. cutoff 后再次扫描，移除旧模型引用。
- 风险: 只改 UI 默认值会漏掉后台任务、旧模板和 API-key 旁路。

#### 卡片 2: Agent Session Policy Matrix

- 概念: 对每条 agent 会话记录入口、执行面、保留期、权限继承、默认 effort、移动端可见性和最终验收责任。
- 使用场景: Codex、ChatGPT Work、Copilot cloud agent、GitHub Mobile、Slack/Teams agent session、长会话换车。
- 操作步骤:
  1. 标明 Chat、Work、Codex、Mobile、CLI、cloud agent 哪个是控制面，哪个是执行面。
  2. 记录默认开启、管理员策略、会话保留期和数据边界。
  3. 固定 default mode、permission mode、review effort 和恢复策略。
  4. 对每条会话写“谁能停、谁能发、谁能发布、谁能最终验收”。
  5. 政策变化前后各跑一次读回检查。
- 风险: 移动端能看见任务，不代表移动端能证明任务已经完成。

#### 卡片 3: Marketplace Auto-Update Gate

- 概念: 插件市场可以自动同步时，先把上架清单、版本、权限、审计和回滚写成门禁，而不是让插件静默变更。
- 使用场景: GitHub Copilot extraKnownMarketplaces、ChatGPT Business 插件 marketplace、Codex plugins、内部 skill/catalog 分发。
- 操作步骤:
  1. 建 allowed marketplace 清单，记录来源仓库、owner 和签收人。
  2. 对每个插件保留版本 pin、自动更新开关、权限摘要和依赖 app。
  3. 每日同步后生成 diff，重点看新增工具、写动作和身份要求。
  4. 高风险插件先在测试 workspace 启用。
  5. 保留禁用、回滚和通知路径。
- 风险: 自动同步如果没有 diff 审查，会把权限变化包装成普通更新。

#### 卡片 4: ClickFix Install Guardrail

- 概念: 任何要求复制命令到 Terminal/PowerShell 的安装说明，都先经过来源、域名、命令、包名和副作用审查。
- 使用场景: Codex CLI、Claude Code、MCP server、开源 agent 工具、curl pipe shell、公司 onboarding。
- 操作步骤:
  1. 只信任官方域名、官方 GitHub、npm/pip registry 和内部上架清单。
  2. 搜索广告、Google Sites、短链和镜像站不作为安装来源。
  3. 执行前读完整命令，拒绝隐藏 URL、base64 解码、直接 pipe shell、写启动项或清除隔离属性。
  4. 首次安装在隔离环境或测试机器验证。
  5. 把最终可信命令写入团队 runbook。
- 风险: 开发者习惯“复制命令安装工具”，正好是 ClickFix 攻击的入口。

## 白话版

今天这期像是“工具房要换电压、换钥匙、换门禁”。最要紧的不是又多了几个按钮，而是旧插头还能不能用、谁有钥匙、钥匙会不会自动换、出了事谁验收。

Codex 的 GPT-5.4/GPT-5.4 mini 退场像小区通知 8 月 31 日旧门禁卡失效。你不能只把自己口袋里的卡换掉，还要检查快递柜、车库、保洁阿姨、自动门和备用卡有没有还在用旧卡。对应到工作流，就是默认模型、自动化、custom agent、scheduled task、配置文件和教程示例都要扫。

浏览器 lane 像三种进门方式: 用你自己家的钥匙进本地浏览器，用物业提供的工具门进 Site tools(WebMCP)，或者去临时前台登记进 cloud browser sign-in。三种方式都能进楼，但登记表、监控、权限和能不能带东西出来完全不同。

GitHub Copilot 的统一策略像把前台、手机门禁和保安巡逻合成同一套制度。方便是方便，但“默认开不开”“录像留多久”“谁能巡查”“巡查强度多高”都要提前写清楚。

AI 审 AI 的 PR 像学生互改作业。如果两个学生都用同一本答案书，互改不等于独立复核。真正有用的是让测试、规则、人工重点风险检查和另一套 reviewer 分开留下小票。

假 Codex 下载事件更像骗子在商场门口摆了一个很像官方维修台的摊位，还让你自己拿螺丝刀拆手机。以后凡是让你复制一条命令到 Terminal 的安装说明，都先问: 是不是官网、是不是官方仓库、命令到底在下载什么、有没有隐藏 URL、有没有让你绕过系统保护。

所以今天最该做的四件事很朴素: 旧模型清单、会话政策表、插件自动更新门禁、复制命令安装守则。
