### Codex/GPT 工作流启发

1. 模型退场日要按 release checklist 处理，不能只靠 UI 里看不到旧模型就算完成。
2. Codex 0.151.0 的 tool result inspection 说明 MCP 输出进入模型前也需要可审查层；这比只审 tool input 更接近真实风险面。
3. 插件目录开始合并 per-repository configuration，说明“同一个插件市场”在不同仓库可能有不同生效面，必须留 catalog diff。
4. 远程沙箱路径语义、executor home directory 和 OS 传播进入 Codex release notes，说明跨机器执行不能用本机路径假设做安全判断。
5. 子代理 token usage 计入 root goal budget，适合把“便宜旁路”也纳入总预算，不再只看主会话消耗。
6. preserved permission profiles 和 stale Guardian classification 修复提醒: 恢复会话后必须重新读取权限状态，不能拿旧分类授权新动作。
7. ChatGPT Work 的 scheduled tasks 变成 app-event 触发后，每条任务都要有 trigger schema、幂等键、重复事件策略和 owner。
8. Apple Messages 这类插件把 assistant 从“生成文本”推到“真实发送”，草稿、收件人确认和发送必须是三个状态。
9. GitHub Copilot unified policy 会把移动端、网页端和 cloud agent 拉到同一策略下，团队需要先确认默认开启和保留期。
10. Copilot review effort 默认变化说明平台默认值本身就是风险；关键仓库应显式 pin。
11. Bot-authored PR 可被 Copilot review 后，人类验收要从“有没有 review”转为“review 是否独立、是否覆盖测试和风险”。
12. Agents SDK Python/JS 同步强化 output guardrail replay safety，说明被拦截的工具输出不应残留在可重放状态里。
13. Claude Code hooks 的 lifecycle 模型仍值得借鉴，但映射到 Codex 时要重新定义事件名、权限和证据格式。
14. Obsidian/Agent Fleet 类项目把 run log、skill、task 写回 markdown vault，适合做 second brain，但 vault 写入必须有 ownership fence。
15. Fake Codex ClickFix 继续提醒: 搜索广告和复制终端命令不能作为安装信任链。
16. persistent agent 传闻只能作为 watch item；未官方发布前，不进入生产依赖或自动化承诺。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 只发任务信封，确认日期、公开来源、允许动作、停止条件和是否需要发布。
2. Mac/Codex: 先跑 Cutoff-Day Model Audit，扫默认模型、自动化、custom agents、scheduled tasks、脚本和文档模板。
3. Codex CLI: 更新到候选版本前先看 release notes；重点检查 MCP、plugin catalog、sandbox、permission profile 和 budget 相关变更。
4. Browser/Work: 每次网页或 app 事件任务先声明 lane；公开网页、登录浏览器、Site tools(WebMCP)、cloud sign-in 不混用证据。
5. Messages/Gmail/Slack: 允许读和写摘要不等于允许发送；发送、发布、删除、授权必须单独审批。
6. Knowledge vault: Obsidian/MCP 只先开 read/search；写入、删除、自动整理和夜间任务必须经过 ownership fence、备份和 diff。
7. GitHub: 对 agent-authored PR 使用独立审查门；bot reviewer、human reviewer、测试和风险说明分开留证。

### 可沉淀知识卡片

#### 卡片 1: Cutoff-Day Model Audit

- 概念: 在模型退场日，把所有旧模型引用当成发布阻断项逐项扫清。
- 使用场景: Codex 模型退场、Copilot global model policy、Agents SDK 模型迁移、团队默认模型切换。
- 操作步骤:
  1. 扫 workspace defaults、automation、custom agents、scheduled tasks、CLI config、CI config、文档模板和示例命令。
  2. 区分 ChatGPT 登录态、API key、本地 CLI、云 agent 和第三方客户端。
  3. 每条记录 owner、旧模型、新模型、迁移时间、验证命令和回滚方式。
  4. 跑 1-2 个关键真实任务，保留输出、失败和性能边界。
  5. cutoff 后再扫一次，删除旧引用和过期说明。
- 风险: 只改可见默认值会漏掉后台自动化和旧模板。

#### 卡片 2: MCP Tool Result Inspection Gate

- 概念: 不只审查 agent 传给工具的 input，也审查工具返回给模型的 result，必要时替换、脱敏或阻断。
- 使用场景: Codex MCP、插件、app server、browser tool、知识库检索、第三方 connector。
- 操作步骤:
  1. 给每个 MCP tool 标明 result schema、敏感字段、公开字段和错误码。
  2. 在结果进入模型前做字段 allowlist、长度限制、链接校验和私密信息扫描。
  3. 对可疑结果做 withheld、redacted 或 human review。
  4. 记录原始结果只留在本地审计边界，不进入公开日报或站点。
  5. 回归测试覆盖正常、超长、错误、私密字段和恶意注入结果。
- 风险: 只审 tool input 会漏掉工具返回中的 prompt injection、密钥、私信或本地路径。

#### 卡片 3: Cross-App Send Approval Ledger

- 概念: 把跨 app 的读、搜、草稿、收件人确认、发送和发送后证据拆成独立审批状态。
- 使用场景: Apple Messages、Gmail、Slack、Teams、GitHub issue/PR、日历邀请、社交平台。
- 操作步骤:
  1. 标明 app、账号、目标对象、允许动作和禁止动作。
  2. read/search 默认只读，draft 只生成草稿。
  3. 发送、发布、删除、授权和提交表单必须单独确认。
  4. 发送后只记录必要状态，不公开收件人、内容、cookie、截图或非公开线程。
  5. 每次失败保留停止原因和最后可验证状态。
- 风险: “帮我写一下”如果自动升级成“帮我发出去”，外部副作用会失控。

#### 卡片 4: Vault-Agent Ownership Fence

- 概念: 把 Obsidian/markdown vault 当成个人知识资产库，先定义哪些目录可读、可写、可自动整理和必须人工确认。
- 使用场景: Obsidian MCP、Agent Fleet、second brain、Codex memory、研究库、团队 runbook。
- 操作步骤:
  1. 分区: inbox、sources、drafts、decisions、runbooks、private、archive。
  2. 默认只给 agent read/search，写入先限 inbox 或 drafts。
  3. 自动整理前做备份、dry-run 和 diff。
  4. 删除、重命名、移动和跨目录合并必须人工确认。
  5. 每周复盘误写、漏写和过期卡片。
- 风险: vault 一旦开放 read/write，agent 既能提效，也能破坏长期知识结构。

## 白话版

今天这期像“旧门禁卡最后一天失效”。最重要的不是研究新门禁有多高级，而是检查每一扇门、每一张备用卡、每个自动开门器有没有还在用旧卡。

Codex 的 GPT-5.4/GPT-5.4 mini 退场就是旧卡作废。你不能只看主门能不能进，还要看车库、快递柜、保洁阿姨、备用钥匙和自动门。对应到工作里，就是默认模型、自动化、custom agent、scheduled task、CLI 配置、脚本和文档模板都要扫。

Codex 0.151.0 像物业升级了门禁后台: 不只检查谁刷卡，还检查门禁机吐回来的记录有没有问题。MCP tool result inspection 就是这一步。以前我们容易只看“代理要调用什么工具”，现在还要看“工具返回了什么，会不会把不该给模型看的东西塞回来”。

插件市场和自动更新像超市上架清单。每天自动进货很方便，但如果没人看清单，货架上多了一个能发消息、改文件、连账号的工具，你可能第二天才发现。所以要有 allowlist、版本、权限 diff 和回滚。

Apple Messages、Gmail、Slack 这类跨 app 能力像让助手拿到真实邮筒钥匙。帮你写草稿和帮你寄出去是两回事；读邮件、写草稿、确认收件人、点击发送、发送后留小票，必须分开。

Obsidian second brain 像你的书房。让代理进来找书可以，帮你把书摆到临时桌也可以；但让它自动扔书、改目录、合并笔记，就要先备份、看清单、看 diff。书房一乱，后面每次找资料都会变慢。

所以今天的动作很朴素: 查旧模型、查工具返回、查发送审批、查知识库写入边界。不是为了保守，而是因为 agent 越像一个能干活的同事，就越需要门禁、工牌和工作小票。
