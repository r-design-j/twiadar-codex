今天的新信号不是“又多一个聊天入口”，而是 AI 编程工作流的三层地基继续加厚: 组织治理、运行时上下文、实时/流式稳定性。

结论: 今天应新增三张复用卡片: Repository Governance Taxonomy（仓库治理标签表）、Agent Context Management Gate（agent 上下文管理闸门）、Realtime Stream Resilience Checklist（实时流韧性清单）。白话说，AI 员工不只要会干活，还要贴对工牌、带对钥匙、走稳定的对讲频道。

### Codex/GPT 工作流启发

1. Copilot 建议 custom properties allowed values，适合把 repo 的风险级别、数据分类、面向外网、合规域、owner 队列先标准化。
2. custom properties 不是装饰字段；真正价值在于后续能被 rulesets、security configurations、审查队列和 agent 任务路由使用。
3. Enterprise/organization owner 可以用 Copilot policy 控制 repository custom property suggestions，说明“AI 帮你定标签”本身也要进权限策略。
4. GitHub Advanced Security configuration enforcement 从 repository owner 扩展到 organization owner，降低本地仓库管理员绕开企业基线的空间。
5. 对自动化仓库，建议新增 `security-baseline-enforced`、`agent-writable`、`public-output` 这类 repo property，再绑定规则。
6. SHA-1 HTTPS sunset 与 AI 看似无关，但 CLI、代理、老 Node/Python、企业代理和本地证书链都可能因此暴露遗留问题。
7. Copilot CLI 1.0.84-9 的 context management tools opt-in，意味着 agent/subagent 的上下文裁剪开始变成显式设置，不再只是提示词手艺。
8. context management 不能只看“省 token”，还要验证是否删掉了停止条件、权限边界、验收命令或用户约束。
9. scheduled prompts 运行失败时显示错误，是 recurring task 的关键体验；失败必须显式化，不能只靠用户发现当天没产出。
10. MCP turns 在 tool list refresh 失败后继续，适合增强韧性，但验收时要记录“工具列表刷新失败后是否降级运行”。
11. IDE bridge config validation 修复说明 CLI 与 IDE 共存时，plugin/MCP reload 仍是高风险路径，需要单独 smoke。
12. `--share=~/notes.md` 路径修复提醒所有自动化都要测 tilde expansion、相对路径、绝对路径和输出目录权限。
13. OpenAI Codex 0.155.0-alpha.8 公开 release body 仍只有极简说明，不足以判断功能变化；只可作为 alpha lane 活跃证据。
14. Codex alpha assets 包含 digest，适合建立 artifact integrity check，但不能替代安装后行为验证。
15. openai-node 7.16.0 的 WebSocket event limits 适合给 realtime agent 加“单次 iterator 最大事件数”保护，避免无限堆积。
16. malformed WebSocket events 与 buffering 修复说明测试集要包含坏包、半包、过量事件和中途取消。
17. callback credentials local to each HTTP request 是重要安全信号；多请求、多租户、多工具场景要防凭证跨请求泄漏。
18. openai-python 3.14.1 的 metadata-only Live WebSocket diagnostics 说明日志应服务排障但不暴露 payload。
19. Python Responses commentary parsing 修复提醒: commentary 是控制/说明层，不能强行套结构化解析口径。
20. today 的主线是“agent 能力上线后如何被组织治理、上下文管理、实时韧性和公开发布证据接住”。

### 可沉淀知识卡片

#### 卡片 1: Repository Governance Taxonomy

- 概念: 把仓库 custom properties 变成可执行治理标签，而不是随手填的备注字段。
- 使用场景: REPO GOVERNANCE
- 操作步骤:
  1. 固定属性名: 数据等级、面向外网、合规域、owner 队列、agent-writable、public-output。
  2. 为每个属性定义 allowed values，并记录谁能修改。
  3. 将属性绑定到 rulesets、security configurations、审查队列和 agent 任务路由。
  4. 每周查一次空值、异常值、未授权改动和规则覆盖缺口。
- 风险: 标签如果不绑定规则，只会变成好看的表格。

#### 卡片 2: Agent Context Management Gate

- 概念: agent/subagent 的上下文管理必须经过显式开关、样例回归和边界检查。
- 使用场景: CLI CONTEXT
- 操作步骤:
  1. 记录 CLI 版本、`/settings` 开关、适用 agent/subagent 和任务类型。
  2. 准备一个长任务样例，包含权限边界、停止条件、验收命令和用户偏好。
  3. 分别运行开启/关闭 context management 的结果，对比是否丢失关键约束。
  4. 记录 token、时延、返工、误删上下文和最终验收结果。
- 风险: 只追求少上下文，可能把最重要的安全线和验收线剪掉。

#### 卡片 3: Realtime Stream Resilience Checklist

- 概念: Live/WebSocket agent 要把事件上限、坏事件、取消、日志和凭证隔离放进升级验收。
- 使用场景: REALTIME AGENTS
- 操作步骤:
  1. 为每个 iterator 设置最大事件数或超时，并验证超限行为。
  2. 注入 malformed event、半包、重复 acknowledgment、空 payload 和中途取消。
  3. 确认 diagnostics 只记录 metadata，不保存敏感 payload。
  4. 验证每个 HTTP/WebSocket request 的 credentials 作用域互相隔离。
- 风险: demo 能跑不代表长会话、坏网络和多租户场景能安全运行。

#### 卡片 4: Scheduled Prompt Failure Receipt

- 概念: 定时 prompt 失败时必须产生可见错误、失败原因和下一步动作。
- 使用场景: RECURRING TASKS
- 操作步骤:
  1. 每次定时任务记录触发时间、输入版本、运行设备和目标产物。
  2. 失败时保存错误类型: 权限、网络、工具加载、数据不可达、验证失败或发布失败。
  3. 在任务摘要中只写用户需要知道的下一步，不公开本地过程细节。
  4. 重跑前检查是否会重复发布或覆盖当天成果。
- 风险: 沉默失败比显式失败更危险，因为用户会误以为自动化仍在工作。

#### 卡片 5: Artifact Integrity Lane

- 概念: 对 alpha/prerelease CLI 或 Codex 资产先检查版本、digest 和来源，再谈行为验证。
- 使用场景: CLI RELEASE WATCH
- 操作步骤:
  1. 记录 tag、published_at、prerelease/stable、asset names、digest 和下载入口。
  2. release body 过薄时，不推断功能；只标为版本线观察。
  3. 隔离环境安装后跑 smoke: version、help、read-only、expected denial、rollback。
  4. 只有 smoke 和项目回归通过，才允许进入默认工具链。
- 风险: 只看到新版本号就升级，会把未知 alpha 行为带进生产自动化。

## 白话版

今天像是给 AI 团队补了三件“办公室基础设施”。

第一件是工牌。GitHub Copilot 可以帮组织定义仓库 custom properties 的 allowed values，就像给每个项目贴标准工牌: 这个是不是对外服务、有没有合规要求、谁负责、AI 能不能写。贴了工牌以后，门禁和规则才知道该怎么管它。

第二件是门禁。GitHub Advanced Security configuration 现在可以从企业层强制下去，组织和仓库管理员也不能随便改掉。白话说，总部定了安全门禁，分店不能自己偷偷拆门。

第三件是对讲机。Copilot CLI 1.0.84-9、OpenAI Node/Python SDK 都在修上下文、MCP、定时失败提示、WebSocket 事件、坏消息、日志脱敏和凭证隔离。这些不是炫酷新功能，但很关键: AI 员工干久活、接多工具、遇到坏网络时，不能一边说“我还在跑”一边悄悄丢消息。

所以今天不要只盯“哪个模型更聪明”。更重要的是: 仓库有没有标准标签，安全门禁能不能强制，agent 的上下文会不会乱剪，实时连接出错时有没有小票。小票齐了，AI 才像稳定同事，不像临时搭起来的演示。
