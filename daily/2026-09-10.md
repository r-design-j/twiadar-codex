### 今日结论

今天的重点从“agent 会不会做事”转向“企业能不能把 agent 的动作边界管住”。GitHub 在 9 月 9 日集中推出 Copilot agent 企业托管权限、PR secret merge block、Code Quality 批量 agentic autofix、CodeQL 2.27.0 Linux ARM64 和 JetBrains 企业托管 sandbox；OpenAI 侧则在 SDK/release 线上继续补 key expiration、image-generation options、UnixLocal symlink race 修复和 Codex 0.154.0 稳定包。

结论: agent 工程的下一张验收表应从模型能力表升级为 operation policy matrix（操作策略矩阵）。每个入口要能回答: 哪些 shell/file/network 动作 deny（禁止）、ask（需审批）、allow（可直接执行）；PR secret 是否在合并层阻断；批量 autofix 是否消耗 AI credits 并产出可审查 PR；CodeQL/Code Scanning 是否能在 ARM64 和私有查询源下稳定跑；IDE/CLI/应用是否执行同一套 sandbox 规则。

今天建议沉淀四个资产: Agent Operation Policy Matrix、PR Secret Merge Gate、Bulk Autofix Review Queue、ARM64 CodeQL Parity Gate。

### Codex/GPT 工作流启发

1. enterprise managed permissions 把 agent 权限从“每个用户自己点同意”推进到组织策略层，适合成为所有 agent 入口的总闸。
2. deny/ask/allow 要分别记录 shell command、file read/edit、network domain，不能只写“允许 Copilot”。
3. 托管限制不能被用户设置、auto-approval 或历史审批削弱，这一点适合写进安全验收。
4. Code Quality 的 agentic autofix 最多 25 条一组，意味着 backlog 可以批处理，但 review queue 也会批量膨胀。
5. 批量 autofix 会消耗 AI credits，预算小票要和修复批次绑定。
6. Copilot 自称会验证自己的改动，但最终仍要由人 review 和 merge；不要把 PR 打开等同于缺陷已关闭。
7. PR secret merge block 补的是 push protection 之后的合并层，适合捕获 generic/custom pattern 或推送时漏过的秘密。
8. secret gate 验收要同时确认 scan completed 和 alerts open count，而不是只看 ruleset 已保存。
9. CodeQL Linux ARM64 原生支持会让 ARM runner 上的 code scanning 更自然，但旧 GHES 仍可能需要手动升级 CodeQL。
10. CodeQL default setup 可用组织 private registry config 拉 custom queries/packs，认证来源要进入扫描小票。
11. Rust 新增 command-line injection 查询，Rust CLI/agent 工具仓库应重新跑一次 code scanning baseline。
12. JetBrains 的 enterprise-managed sandbox 覆盖 filesystem、network、proxy、developer tools、macOS Keychain 等，说明 IDE 侧也进入托管策略时代。
13. Managed sandbox settings 优先于用户设置，适合用来避免“本地 IDE 放宽、CLI 收紧”的策略漂移。
14. Agents SDK 0.22.2 的 UnixLocal symlink race 修复提醒: 本地文件 API 不只验路径字符串，还要验符号链接和竞态窗口。
15. compaction response chain 修复说明长会话压缩后仍要检查响应链恢复，尤其是 pop / resume / replay 场景。
16. Node/Python SDK 同日补 service-account API key expiration controls，凭证生命周期已经成为 SDK 一等字段。
17. Codex 0.154.0 是稳定 release，但公开 release body 仍偏包和资产层；升级默认前仍需固定 smoke。
18. Copilot CLI 最新公开 release 仍停在 1.0.84-3，昨天记录的 MCP OAuth 冷启动和 copy export 修复继续作为 CLI 验收项。

### iPhone + Mac + Codex 协作玩法

1. iPhone/Remote: 看到 GitHub agent 权限新闻后，只派工“建立策略矩阵”，不要直接批准扩大 agent 自动执行范围。
2. Mac/Codex: 本地维护一张 agent operation policy matrix，列出 Chat/Codex/CLI/IDE 对 shell、文件、网络、Keychain 的 deny/ask/allow。
3. Mac/Codex: 对批量 autofix 只接受 PR + 测试证据 + diff 范围，不接受“Copilot 已处理”作为完成证据。
4. Mac/Codex: 对 secret merge block 建一个模拟 PR，验证 scan completed 与 open alerts 对合并状态的实际影响。

6. IDE/CLI: JetBrains、VS Code、Copilot app、Copilot CLI 如果都启用 agent，需要读回托管策略，不用单个入口状态代表全部。

### 可沉淀知识卡片

#### 卡片 1: Agent Operation Policy Matrix

- 概念: 把 agent 的 shell、file read/edit、network domain、Keychain、developer tools 等动作按 deny/ask/allow 做成组织级矩阵。
- 使用场景: AGENT POLICY
- 操作步骤:
  1. 按入口列出 Copilot app、CLI、VS Code、JetBrains、Codex 的策略来源和生效范围。
  2. 按团队列出 deny、ask、allow，并标注是否可被用户设置覆盖。
  3. 每次策略变更后用新会话读回实际限制，并保存被阻断动作的小票。
- 风险: 只靠个人 auto-approval 会让旧审批或本地设置绕过组织边界。

#### 卡片 2: PR Secret Merge Gate

- 概念: 在 PR 合并层要求 secret scanning 完成且新增 alerts 全部解决，补上 push protection 之外的最后一道闸。
- 使用场景: SECRET MERGE
- 操作步骤:
  1. 在 repository / organization / enterprise ruleset 启用 require_secret_scanning_alert_resolution。
  2. 标注覆盖的 secret types、bypass 权限和适用分支。
  3. 用模拟 PR 验证 scan completed、open alerts、bypass 三种状态。
- 风险: 只启用 push protection 会漏掉某些 PR 层、generic/custom pattern 或配置外路径。

#### 卡片 3: Bulk Autofix Review Queue

- 概念: 把 Copilot 批量修复 code quality findings 的结果统一进入待审 PR 队列，而不是直接关闭 backlog。
- 使用场景: AUTOFIX REVIEW
- 操作步骤:
  1. 每批最多 25 条 findings，记录 selection、branch、AI credits 和 owner。
  2. 要求 PR 展示测试、验证命令和涉及文件清单。
  3. reviewer 按批次决定 merge、split、rerun 或 reject。
- 风险: 批量修复会快速制造 PR，但 reviewer 不跟上会把技术债变成 review 债。

#### 卡片 4: ARM64 CodeQL Parity Gate

- 概念: 把 Linux ARM64 上的 CodeQL 原生执行纳入 code scanning parity，保证 runner 架构变化不降低扫描覆盖。
- 使用场景: CODEQL ARM
- 操作步骤:
  1. 记录 CodeQL CLI / bundle 版本、runner 架构和 GHES/github.com 环境。
  2. 验证 custom queries、packs、private registry config 和认证来源。
  3. 对 Rust、Java/Kotlin、C# 等新增/增强查询保存 baseline 差异。
- 风险: 换成 ARM64 runner 后，如果 query pack 或私有认证失败，扫描可能静默降级。

## 白话版

今天的 AI 新闻不像“来了一个更聪明的员工”，更像“公司终于开始给这批员工配门禁卡、审批单和仓库闸机”。

以前我们常问 agent 能不能改代码、跑命令、联网。现在问题变成: 谁能规定它什么时候不许动、什么时候要举手问、什么时候可以自己做。GitHub 的企业托管权限就是这套门禁: shell 命令、文件读写、网络域名都可以分成红灯、黄灯、绿灯，而且员工自己不能把公司门禁改松。

批量 agentic autofix 像让 Copilot 一次领 25 张维修单。它会去开分支、修问题、跑验证、开 PR，但这不等于维修单已经验收。真正完成还要有人看 PR、看测试、看有没有修过头。

PR secret merge block 像出厂前的最后一道安检。推送时没拦住的密码、token 或自定义敏感串，合并前还要再扫一遍；扫描没完成或告警没清，车就不能出厂。

CodeQL 支持 Linux ARM64，则像质检仪器终于能直接搬到 ARM 工位上用。但仪器能开机不等于检查项目都一样，私有规则包、认证、Rust 新查询都要重新跑一遍。

所以今天不该急着装更多 agent，而是先画清楚一张“操作红绿灯表”: 哪些动作禁止，哪些动作要问，哪些动作可以自动做。表画清楚，再让 agent 干活。
