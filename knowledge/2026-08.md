# AI/Codex/GPT 个人知识沉淀 - 2026-08

## 2026-08-03

### 知识卡片: 入口冻结协议

把 agent 长任务拆成可转向阶段和冻结阶段。采集、探索、方案阶段可以 Steer；一旦进入验证、commit、push、deploy，就只允许 Queue 新检查，不随意改主线。

用户操作链路:

1. 开始任务时写清阶段和成功标准。
2. 采集阶段发现方向错了，允许 Steer。
3. 进入验证后，只 Queue 额外检查。
4. commit/deploy 后只处理失败原因，不临时改需求。
5. 结束时输出文件、验证、commit、部署证据和待拍板事项。

风险: 发布阶段随意转向会制造半成品文件、难追踪 diff 和错误部署。

### 知识卡片: 工具路由白名单

工具不是越多越好。低风险读操作可以通过 tool search 按需加载；去重、聚合、字段校验可以交给 Programmatic Tool Calling；写文件、发起外部动作、发布和授权必须保留审批和验证链。

用户操作链路:

1. 按 namespace 分组工具。
2. 标注只读、可逆、不可逆。
3. 只把低风险工具放进自动调用路径。
4. 对输出做 schema/字段校验。
5. 高影响动作必须留下人工审批或可复核证据。

风险: 大工具面会增加误调用概率；程序化工具不适合审批敏感动作。

### 知识卡片: 私有工具窄通道

私有 MCP、Obsidian、本地脚本、内部 REST API 不应直接暴露公网。更稳的默认是 customer-run client、outbound-only、明确目的地、可检查日志和可撤销配置。

用户操作链路:

1. 写工具上架清单。
2. 限定目标、方法、路径、超时和响应大小。
3. 优先只读接入。
4. 本地记录健康检查和失败原因。
5. 定期撤销不用的入口。

风险: 隧道一旦变成通用网络桥，便利会吞掉安全边界。

### 知识卡片: 仓库化 agent workflow

重复自然语言自动化应该进入仓库，用 Markdown 写任务，用 frontmatter 写触发、权限、网络、safe outputs、engine、timeout 和预算，再通过人工触发或排程运行。

用户操作链路:

1. 选择一个重复任务，例如每日状态报告。
2. 写 workflow.md 和最小权限。
3. 声明 safe outputs 和预算上限。
4. 先手动触发验证。
5. 稳定后再排程或接入更多 engine。

风险: 没有 safe outputs 的 agent workflow 会把自然语言任务变成难审计写权限。

## 2026-08-04

### 知识卡片: 四入口分工表

把 Chat、Work、Codex、Sites 分别定义为判断、长任务、代码执行、公开交付四类入口。入口合并后，关键不是“都能做”，而是每类入口有不同的成功标准、读写权限和验收方式。

用户操作链路:

1. 判断任务属于问答、长任务、代码执行还是公开交付。
2. 写清对应入口和成功标准。
3. 标注能读什么、能写什么、需要谁审批。
4. 固定产物路径和验证命令。
5. 结束时输出链接、测试、commit、部署或待确认事项。

风险: 入口统一后容易把所有工作塞进同一会话，造成上下文污染和验收不清。

### 知识卡片: 本地 agent lane

对私有代码、离线验证和高频构建，先让本地模型/本地 agent 读写、构建、复现，再决定是否交给云端。Apple MLX 的本地 agent 演示说明，本地 lane 可以成为私有验证和低风险草稿的独立通道。

用户操作链路:

1. 启动本地模型服务或本地 agent。
2. 通过 OpenAI-compatible endpoint 或 agent 配置接入。
3. 限定工具和目录权限。
4. 跑 build/test/repro。
5. 只把 diff、日志摘要和可公开证据带到下一步。

风险: 本地模型能力、上下文长度和工具权限不稳定，不能免除人工验收。

### 知识卡片: 双 agent 审查门

一个 agent 做规划/实现，另一个 agent 做只读审查或对抗审查，最后由人类合并和发布。适合迁移、认证、计费、安全、长任务换车等高风险工作。

用户操作链路:

1. 主 agent 产出计划或 diff。
2. 第二 agent 只读 review 或 adversarial review。
3. 汇总阻塞项和非阻塞建议。
4. 主 agent 修复必要问题。
5. 人类看 diff/test/deploy 后决定合并。

风险: 两个 agent 互相改会产生预算黑洞和责任不清。

### 知识卡片: 插件上架清单

插件是 skills、apps、app templates 的能力包。安装前要像超市上架一样审核能力、权限、角色和撤销方式，而不是把它当普通提示词。

用户操作链路:

1. 看插件包含哪些 skill/app/template。
2. 确认是否需要连接外部账号。
3. 标注读操作、写操作和不可逆动作。
4. 配置 workspace/role 范围。
5. 先用低风险任务测试，再记录撤销路径。

风险: 把插件当普通提示词会低估外部动作和数据权限。

## 2026-08-05

### 知识卡片: 入口职责矩阵

每个任务先声明入口: Chat 做判断，Work 做长任务交付，Codex 做代码和本地执行，Voice 做桌面协调，iPhone Remote 做状态和审批。

用户操作链路:

1. 先判断任务属于快速判断、长任务交付、代码执行、语音协调还是远程审批。
2. 写清能读什么、能写什么、是否接触本地文件。
3. 写成功证据，例如文件、测试、diff、链接、部署状态。
4. 写停止条件，例如登录弹窗、验证码、权限不足、无法验证。
5. 结束时输出产物、验证、commit、deploy 和待拍板项。

风险: 入口混用会导致历史、权限、文件位置和验收责任不清。

### 知识卡片: UI 自动化证据环

Computer Use/浏览器自动化不是“点按钮”，而是观察状态、执行动作、回传截图或 DOM、复核结果、失败停止的闭环。

用户操作链路:

1. 先记录当前 UI 状态和预期目标。
2. 声明下一步动作和选择器/坐标依据。
3. 执行动作后立即回传截图或 DOM。
4. 校验是否到达预期状态。
5. 未达到预期时停止并说明失败原因。

风险: 只记录动作不记录状态，会把误点、遮挡、登录弹窗和权限页误判为完成。

### 知识卡片: Agentic Workflow 上架单

重复自然语言自动化进入仓库前，要写触发、权限、engine、network、safe outputs、lockfile 和回滚方式。

用户操作链路:

1. 写 `.github/workflows/*.md` 自然语言任务。
2. 用 frontmatter 声明触发、权限、工具、网络和 engine。
3. 配 safe outputs，限定允许写出的结果。
4. compile 生成 lockfile。
5. review diff 后手动触发，稳定后再排程。

风险: 没有 safe outputs 和权限声明的 workflow，会把聊天任务变成不可审计写权限。

### 知识卡片: 凭证与外联兜底

agent 安全不能只靠用户审批或模型拒绝；敏感路径、凭证、网络外联和日志必须由环境强约束。

用户操作链路:

1. 限定可写目录和可读敏感路径。
2. 默认关闭网络或使用外联白名单。
3. 凭证不放进工作区，也不让 agent 自动读取。
4. 高风险动作保留审批门。
5. 保留 agent-native logs 作为审计证据。

风险: 用户审批会疲劳；一旦 agent 拿到凭证并能外联，模型层防线可能不足。

## 2026-08-06

### 知识卡片: 自动化三层分工

ChatGPT Tasks 做提醒和轻量监控，Work 做长任务交付，Codex automation 做本地仓库执行和发布。先判断任务是否需要本地读写，再选择入口。

用户操作链路:

1. 判断任务是否需要本地文件、命令、测试或发布。
2. 需要本地执行时交给 Codex automation。
3. 只需要提醒、定时报或监控变化时交给 ChatGPT Tasks。
4. 需要研究、报告、表格、演示或 Site 草稿时交给 Work。
5. 结束时输出文件、来源、测试、commit、deploy 或待拍板事项。

风险: 把本地仓库任务塞进 Scheduled Tasks，会导致权限、文件访问和验收边界不清。

### 知识卡片: Codex tool 封装清单

当自建 agent 调用 Codex 时，必须显式封装工作目录、沙箱、认证、线程复用、日志、输出结构和用量。

用户操作链路:

1. 设置 `workingDirectory`，只指向允许处理的仓库。
2. 设置 `sandboxMode` 和审批策略。
3. 记录或复用 `threadId`，避免上下文漂移。
4. 把 streaming 事件接入 tracing 或日志。
5. 用 `outputSchema` 或结构化结果收口。

风险: 没有目录和沙箱约束的 Codex tool 会把 agent 应用变成不透明本地执行器。

### 知识卡片: Agentic Workflow 安全门

自然语言仓库自动化必须默认只读，写操作只能通过 safe outputs、scoped write job 和人工可审查策略落地。

用户操作链路:

1. 写 Markdown workflow。
2. 声明 permissions、engine、tools 和 network。
3. 配置 safe outputs。
4. 设置 budget、timeout 和失败停止。
5. compile 生成 lockfile，review diff 后再手动触发。

风险: 直接让 agent 带 secrets 和 write token 跑仓库，是把 CI 变成不可审计写权限。

### 知识卡片: Second-brain 写回阀

Obsidian/second-brain agent 可以读链接和写回决策，但写入 vault 前必须有备份、diff、审批和回滚。

用户操作链路:

1. 只给相关 notes 或 tag 范围。
2. 第一轮只读分析，不自动写。
3. 产出拟写卡片或补链建议。
4. 人工审查后写入。
5. 写入后查看 Git diff，并定期 lint/去重。

风险: 让 agent 自动改全库，会制造重复概念、错误链接和静默知识污染。

## 2026-08-07

### 知识卡片: Agent 资产发布闸

Workspace Agent 的 draft、preview、publish、schedule、API trigger 和 Slack channel 是不同状态，不能把“已更新草稿”说成“已上线运行”。

用户操作链路:

1. 创建 draft。
2. 配置 tools、apps、skills、files 和 memory。
3. 低风险 preview 或 test。
4. 设置访问权限和 write approvals。
5. publish 后再启用 schedule、API trigger 或 Slack channel。
6. 做一次运行回读并记录证据。

风险: 未发布 draft 不会影响用户；schedule/API trigger 也可能因未发布而未生效。

### 知识卡片: 插件权限上架单

Codex 插件像超市上架清单，必须列清 skills、required apps、optional apps、app templates、读写动作、确认门和数据范围。

用户操作链路:

1. 查看插件依赖的 skills、apps 和 app templates。
2. 确认 app 是否启用，源系统权限是否匹配。
3. 限定角色、账号、domain、sync scope 和 source boundary。
4. 默认只读，写动作要求确认。
5. 用低风险 prompt 做烟测。
6. 定期复核权限和使用记录。

风险: 插件安装不等于源系统授权；源系统权限过大时，插件会继承风险。

### 知识卡片: Issue automation 置信度门

Issue triage 自动化要把动作分成 auto-apply、suggest-for-review、stop 三档，并为每个动作记录 rationale。

用户操作链路:

1. 定义 safe outputs。
2. 要求 issue intents 或等价结构化理由。
3. 设置 confidence threshold。
4. Medium/low 只建议，高置信度才自动应用。
5. 人工批量接受或拒绝建议。
6. 保留 rationale 和审计线索。

风险: 审批面板不是安全边界；真正边界仍是 token、permissions 和 allowed actions。

### 知识卡片: 浏览器状态迁移清单

Atlas 退场和 ChatGPT desktop browser 演进提醒我们，浏览器状态迁移要把 conversation、bookmarks、open tabs、history、cookies/passwords 分开处理。

用户操作链路:

1. 导出需要保留的公开 URL。
2. 单独处理书签、打开标签页和历史。
3. 不把 cookies、passwords、截图或本地浏览器状态写进公开材料。
4. 记录不可迁移项。
5. 迁移后做只读回读。

风险: 把浏览器状态截图或 cookie 当作公开证据会泄露隐私。

## 2026-08-10

### 知识卡片: Voice 控制面验收环

Voice in Work/Codex 可以口头启动、询问、打断和转向任务，但不能替代权限、目录边界、测试、diff 或发布证据。

用户操作链路:

1. 说出目标和期望结果。
2. 确认当前体验是 Work 还是 Codex。
3. 限定读写边界和停止条件。
4. 通过状态回看判断是否需要转向。
5. 回到 Mac/Codex 跑最终验收。

风险: 把口头指令当成外部写权限，会越过审批和验收。

### 知识卡片: 浏览器状态分层迁移

conversation、bookmarks、open tabs、history、cookies/passwords 是不同迁移对象，公开日报只保留来源链接和总结。

用户操作链路:

1. 导出需要保留的公开 URL。
2. 单独处理书签、打开标签页和历史。
3. 排除 cookie、password、截图和登录状态。
4. 迁移后做只读回看。
5. 公开材料只写可复核链接和总结后的知识卡。

风险: 把浏览器状态当证据公开，会泄露账号与隐私。

### 知识卡片: 插件权限上架单

插件是 skills、apps、app templates 的容器；真正的数据和动作权限来自 app 设置与源系统权限。

用户操作链路:

1. 查看 required apps、optional apps 和 app templates。
2. 检查 role access 和源系统权限。
3. 列出 read/write actions。
4. 配置 approvals、sync scope、domain 和 source boundary。
5. 用低风险 prompt 做烟测。
6. 定期复核权限和使用记录。

风险: 插件安装不等于数据授权；源系统权限过大时风险会被继承。

### 知识卡片: 可回放 skill 录制门

Record & Replay 能把演示流程转成 skill，但只能录低风险、可复核、可回滚的重复动作。

用户操作链路:

1. 先写清不做事项。
2. 关闭私密页面和含凭证界面。
3. 演示最短安全路径。
4. 审查生成的 skill。
5. 跑低风险烟测。
6. 加入版本管理。

风险: 把含凭证、外部提交或私有数据的流程录进去，会把隐私和副作用固化成自动化。

## 2026-08-11

### 知识卡片: 高权限 agent 授权单

高权限 agent 先确认身份、workspace/API organization、项目、模型、产品表面、scope、reviewer、sandbox 和日志，再执行。

用户操作链路:

1. 写清任务目标和不做事项。
2. 确认被批准的身份、组织、项目、模型和产品表面。
3. 指定 reviewer 和人类复核点。
4. 绑定 sandbox、permission profile、auto-review 或 approval。
5. 执行后保存命令、结果、日志、diff 和验收证据。
6. 如果范围、权限或模型不匹配，停止而不是扩大解释。

风险: 只写“内部/防御用途”不够；缺少身份和范围时，授权不可审计。

### 知识卡片: 自动审批白名单

自动审批只适合低风险、可重复、可回滚、已知命令；默认不覆盖外部写入、凭证、公开发布和生产变更。

用户操作链路:

1. 列出允许自动审批的命令和目录。
2. 限定网络、写权限和环境变量。
3. 设置失败停止条件。
4. 记录每次命令、参数、退出码和结果。
5. 定期删除不再需要的白名单项。

风险: 自动审批范围过大，会把“省一次确认”变成“失去安全边界”。

### 知识卡片: Project/Voice 上下文闸

Voice 可以带文件和 Project 上下文，但它是输入和控制入口，不是最终完成证据。

用户操作链路:

1. 用 Voice 提供材料或转向。
2. 标注 Project 来源、文件和约束。
3. 生成任务胶囊。
4. Mac/Codex 执行本地文件、命令、测试和 diff。
5. 用 commit、push、deploy 或其他相称证据收口。

风险: 把口头说明当验收，会跳过本地证据。

### 知识卡片: Harness-first 工作流

先掌握一个稳定 agent harness 的 prototype、plan、implement、review、sandbox、cost loop，再引入插件和 MCP。

用户操作链路:

1. 固定一个主工作台。
2. 先做原型或方案对照。
3. 原地生成计划，不换会话。
4. 执行实现并跑测试。
5. 审 diff、日志和成本。
6. 只有当基础闭环稳定后，才增加插件、MCP 或 custom agents。

风险: 先追插件会让工作流碎片化，增加上下文和验收成本。

## 2026-08-12

### 知识卡片: 路由小票

每个 agent 任务启动前记录模型、effort、多 agent、Programmatic Tool Calling、缓存、记忆、预算和最终验收证据。

用户操作链路:

1. 判断任务形状和风险。
2. 选择 Sol、Terra 或 Luna。
3. 写清 reasoning effort、是否允许 sidecar、多 agent 或 PTC。
4. 写缓存策略和记忆写入范围。
5. 写预算、时间和失败停止条件。
6. 执行后记录测试、diff、push、deploy 或其他相称证据。

风险: 不写路由理由，会把“用强模型”或“用便宜模型”变成不可审计的习惯。

### 知识卡片: 缓存成本四分账

长会话成本至少拆成 uncached input、cache write、cache read、output，而不是只看总 token。

用户操作链路:

1. 标记可复用 prompt 前缀。
2. 记录 cache write、cache read、uncached input 和 output。
3. 比较命中率、延迟和最终质量。
4. 对固定模板报告使用显式缓存断点。
5. 对低复用或高漂移任务关闭显式缓存。

风险: cache write 有成本，缓存错误内容还会放大旧上下文影响。

### 知识卡片: 记忆范围闸

风险: 手机越顺手，越容易把“我看见状态”误认为“我完成验收”。

### 知识卡片: Session Export/Fork Ledger

`/export` 和 fork 让长会话换车、分支探索和回放更稳，但需要记录源会话、分叉原因、恢复点和最终接受分支。

用户操作链路:

1. 长任务结束或换车前导出 Markdown 交接摘要。
2. 分叉前写清要探索的问题和不允许改的对象。
3. archive/restore 时记录恢复原因和预期状态。
4. 合并结果前只接受一个写入 owner 的产物。
5. 结束时记录被接受分支、被拒绝分支和原因。

风险: 分叉便宜会诱导多线乱写；没有 ledger 会丢失哪条线才是最终证据。

### 知识卡片: Hooked MCP Runbook

hooks 可以把自然语言 agent 流程变成可拦截流程；MCP tool hooks 则要求每个工具都有上架、审批、超时和失败策略。

用户操作链路:

1. 把发布前检查拆成 pre-write、pre-publish、post-deploy 三类 hook。
2. 为每个 MCP 写 URL、command、name 三类匹配字段。
3. 高风险写动作默认 always ask 或 safe output。
4. hook 失败时 fail closed，并输出可读停止原因。
5. 定期清理不用的 MCP 和 hook。

风险: hook 本身也可能误伤或放行；它是闸门，不是最终验收。

### 知识卡片: Cost/Reasoning Budget Sheet

agent 任务需要在启动时选择推理档位，并在结束时记录成本、credits、耗时、接受率和返工原因。

用户操作链路:

1. 按任务风险选 low、medium、high、max 档位。
2. 记录使用的模型、provider、reasoning level 和工具面。
3. 结束时记录 elapsed、tokens/credits/cost 可得值、产物和验证结果。
4. 对失败任务记录失败阶段和是否重试。
5. 每周回看哪些任务适合低档，哪些必须深审。

风险: 没有成本表，团队会用感觉讨论 agent 价值；没有验收表，低成本也可能只是低质量。

## 2026-08-21

### 知识卡片: Model Routing Card

每类任务启动前先写模型路由，不默认使用最高档，也不为了省钱牺牲必要验收。

用户操作链路:

1. 标注任务类型: 写作、代码、研究、视觉、发布、审查或日常自动化。
2. 选择主模型、侧车模型、推理档位和预算上限。
3. 写清不适用条件: 高风险、安全、隐私、外部副作用、缺证据。
4. 记录验收深度: 轻审、深审、真实发布或人工复核。
5. 结束时补充耗时、是否一次通过、返工原因和下次默认档位。

风险: 没有路由卡，团队会在“贵但稳”和“便宜但返工”之间靠感觉摇摆。

### 知识卡片: Capability Catalog

把 skills、plugins、MCP、browser、GitHub、Sites、local scripts 做成能力目录，按任务需要加载，不把全部能力塞进上下文。

用户操作链路:

1. 为每个能力记录名称、用途、入口、读写边界和 owner。
2. 标注状态: 可用、需安装、需授权、只读、禁用。
3. 写清可处理任务和不能处理任务。
4. 高风险写动作必须有审批和撤销路径。
5. 每次任务只加载最小必要能力，结束后记录是否有效。

风险: 工具太多会放大权限面；没有目录会让 agent 临时乱找工具。

### 知识卡片: Side-Question Log

长任务中途的问题要先作为旁路问题记录，避免打断主 agent 的执行上下文；只有确认会改变目标时才升级为 steering message。

用户操作链路:

1. 记录问题、触发上下文、是否影响目标和期望回答。
2. 不让旁路问题直接修改文件、发布或改变权限。
3. 回答后标注: 仅供理解、补充检查、改变计划、暂停执行。
4. 若改变计划，生成新的任务 capsule 并重新冻结边界。
5. 结束时把有价值的问题回灌到 FAQ 或 playbook。

风险: 旁路聊天很方便，但容易把“顺手问一句”变成隐式改需求。

### 知识卡片: Agent Usage Ledger

多 agent 时代要记录真实使用，而不是凭印象评价哪个 agent 好。

用户操作链路:

1. 记录入口、agent/model、reasoning、工具、任务类型和开始时间。
2. 记录产物、验证命令、通过/失败和是否发布。
3. 记录耗时、tokens/credits/cost 可得值和人工返工点。
4. 用稳定 ID 归并同一 agent，不只看 display name。
5. 每周按接受率、返工率、成本和任务类型更新默认路由。

风险: 没有账本，多 agent 路由会变成品牌偏好；有账本才能持续降本提质。

## 2026-08-22

### 知识卡片: Plugin Discovery Ledger

plugin 发现变主动后，工具本身要从“临时可用”升级成“可盘点资产”。

用户操作链路:

1. 记录插件名称、来源、用途、入口、安装状态和 owner。
2. 区分发现、安装、授权、调用、撤销五个动作。
3. 标注读写能力、可见数据、外部副作用和是否需要审批。
4. 每次任务只启用最小必要插件。
5. 结束后记录是否有效、是否返工和是否保留。

风险: 工具越容易被推荐，越容易在未理解权限时被误用。

### 知识卡片: Shareable State Boundary

Share Snapshot、Pinned Chat、Computer History、Sites 都在增加状态共享能力，但不是所有状态都可公开。

用户操作链路:

1. 把内容分成 public summary、private process、local evidence 三层。
2. 公开层只放公开来源、结论、链接和可复用卡片。
3. 私有过程层保留推理、草稿、截图、DOM、登录状态和审批记录。
4. 本地证据层保留测试、diff、commit、deploy 和 inspect。
5. 发布前扫描本地路径、凭证形态和私有过程词。

风险: 分享按钮越顺手，越要先确认分享的是摘要，不是现场记录。

### 知识卡片: Queue & Doctor Runbook

Codex queue/dashboard 和 doctor 把多任务运行状态与环境健康显性化，适合做自动化发布前闸门。

用户操作链路:

1. 任务入队前写目标、owner、写入路径和停止条件。
2. 共享写入对象只允许一个活动任务。
3. 发布前检查 repo 状态、依赖、CLI、账号和 deploy 工具。
4. 失败时记录 queue 状态、doctor 输出摘要和最后一个可验证 artifact。
5. 完成只以本地文件、测试、commit、push、deploy Ready 为证据。

风险: dashboard 显示“运行过”不是“已交付”，doctor 通过也不是业务验收。

### 知识卡片: ChatOps Agent Lane

Slack/Teams agent 入口适合团队调度和状态回传，但最终验收仍应落到 repo、PR、测试和部署平台。

用户操作链路:

1. 为每个聊天入口记录 workspace、channel、bot/app、权限和可触发动作。
2. 触发词必须具体，默认只读或草稿模式。
3. 高风险动作回到 PR、issue 或本地 Codex 审批。
4. 状态消息只写 artifact 链接和下一步，不写凭证或私有上下文。
5. 每周复盘触发次数、成功率、误触发和返工原因。

风险: 聊天工具降低了启动成本，也放大了误触发和权限扩散。

## 2026-08-24

### 知识卡片: Portable Agent Plugin Intake

Agent Plugins 1.0 让插件包跨客户端流动，启用前必须做上架检查。

用户操作链路:

1. 先读取 `plugin.json`，记录 schema、name、版本、来源和 owner。
2. 检查 `skills/`、`mcp.json` 和 client extension 是否在固定位置。
3. 校验路径是否逃出插件根目录。
4. 标注每个组件的读写能力、外部副作用、权限提示和撤销路径。
5. 失败时只隔离坏组件，记录是否允许降级加载。

风险: 插件越可移植，误装、越权和跨客户端漂移的风险越高。

### 知识卡片: Request Geography & Cache Dashboard

API 请求的处理区域和缓存效率要进入同一张运行看板。

用户操作链路:

1. 为每类 API 任务记录目标区域、项目 geography、模型和 endpoint。
2. 标注是否允许 request-level regional processing。
3. 跟踪 prompt cache hit rate、cache reads/writes 和 uncached tokens。
4. 按模型和 service tier 汇总成本、延迟和复用率。
5. 价格或模型更新时重新计算默认路由。

风险: 合规位置和缓存成本都可能被默认值隐藏；没有看板就只能靠感觉优化。

### 知识卡片: ChatOps Shared-Agent Envelope

Slack/Teams 让多人在同一个 agent 现场协作，但必须先把聊天转成任务信封。

用户操作链路:

1. 写清 workspace/channel/thread、repo、目标、权限和预算。
2. 区分问答、triage、创建 issue、改代码、开 PR 五类动作。
3. 默认只允许计划、诊断和草稿；写动作需要明确 owner。
4. 多人 steering 时记录谁改变了目标、何时改变、是否影响验收。
5. 合并前回到 PR、测试、额外审批和 deploy 证据。

风险: 共享现场提高透明度，也会放大隐式改需求和误触发。

### 知识卡片: Enterprise Agent Controls Matrix

企业托管设置把插件、MCP、遥测和权限模式变成可审计控制面，个人工作台也应复用这套矩阵。

用户操作链路:

1. 列出允许插件、禁止插件和允许 marketplace。
2. 建 MCP allowlist/denylist，记录 transport、URL/command 和 owner。
3. 为遥测记录 collector、protocol、service name 和内容捕获策略。
4. 为每个入口定义 permission mode: read-only、draft、ask-before-write、blocked。
5. 每月复核一次误触发、被拒组件和人工返工点。

风险: 没有集中控制矩阵，入口越多，权限越容易靠默认值扩散。

## 2026-08-25

### 知识卡片: Codex MCP Migration Card

Codex 旧 MCP 命令废弃时，迁移不能靠记忆，要写成可复核卡片。

用户操作链路:

1. 记录旧命令、当前版本、使用场景和调用方。
2. 记录替代入口，例如 Codex app server 或特定客户端插件。
3. 标注涉及的 MCP server、transport、权限和 owner。
4. 在小任务上验证新入口可读、可写、可停止、可回滚。
5. 保留旧入口下线日期、失败症状和恢复路径。

风险: 命令习惯最容易变成隐性依赖；废弃后才发现会卡住自动化。

### 知识卡片: Cross-App Send Approval

Apple Messages、Sites、snapshots 等跨 app 能力必须把“准备、发送、分享、发布”拆成不同审批。

用户操作链路:

1. 区分 read/search、draft、send、share、publish 五类动作。
2. 每次发送前复核收件人、正文、附件和是否含非公开信息。
3. 默认使用 allow once，不给长期免审批。
4. 分享 snapshot 前扫描本地路径、diff、截图、私有上下文和凭证形态。
5. 发布后保留 commit/push/deploy/inspect 证据。

风险: 同一个插件同时能读和发，省一步审批就可能把私有过程发出去。

### 知识卡片: Run-Level Spend Gate

agent 一次任务要有自己的预算闸门，不能只靠组织或项目总额度。

用户操作链路:

1. 为每类任务设置 run budget、模型、service tier 和最大输入/输出 token。
2. 请求前先 count tokens，并按 worst-case 输入价格和最大输出预留。
3. 返回后校验模型、service tier、状态和 usage，再结算实际成本。
4. 若请求中断、usage 缺失或费用无法确认，阻断该 run。
5. 记录价格验证日期和预算排除项，例如 hosted tools、storage、regional prices。

风险: 多步 agent 最容易一小步一小步超支；没有预留机制就只能事后补救。

### 知识卡片: Second-Brain Vault Gate

Obsidian/Markdown 知识库接入 agent 前，先限制 vault、权限和回滚路径。

用户操作链路:

1. 从一个小 vault 和一个明确工作流开始。
2. 把敏感笔记放在 agent 不可访问的 vault 或目录。
3. 所有批量改写先走 preview/diff。
4. 用 Git 或等价备份保存可回滚历史。
5. 每次运行记录输入来源、改动范围、链接策略和人工复核结果。

风险: “本地文件”不等于“本地推理”；云 agent、同步插件和连接器都有各自边界。

## 2026-08-26

### 知识卡片: Event Trigger Envelope

webhook scheduled tasks 不能只记 URL，要把事件来源、输入形状和幂等处理写成任务信封。

用户操作链路:

1. 记录触发源、owner、URL 管理方式和允许事件类型。
2. 固定 payload schema、必要字段、可选字段和版本。
3. 设置幂等键，重复触发时只更新状态，不重复发布。
4. 写清读写边界、外部副作用和失败回退。
5. 结束时记录 artifact、校验、commit、push、deploy 或失败停点。

风险: 事件触发降低启动成本，也放大误触发、重放和重复发布风险。

### 知识卡片: Authenticated Browser Evidence Loop

登录态浏览器任务必须比普通网页阅读多一层动作证据。

用户操作链路:

1. 先读取可见页面、目标元素和当前状态。
2. 声明下一步动作、目标元素和预期变化。
3. 只执行已声明且在读写边界内的动作。
4. 重新读取 DOM 或可见状态，确认变化。
5. 符合预期才继续；遇到提交、授权、支付、删除、发送或权限不明即停止。

风险: 登录态让“点一下”变成真实账号动作；没有证据环就无法区分草稿和提交。

### 知识卡片: Model/API Retirement Gate

模型和 API 都会下线，自动化不能把模型名或旧 endpoint 当永久资产。

用户操作链路:

1. 记录当前模型/API、来源链接、采集日期和退役日期。
2. 记录 fallback 模型/API 与能力差异。
3. 为关键任务保存 2-3 个验收样例。
4. 下线前跑迁移验证，比较输出质量、工具调用和成本。
5. 迁移完成后删除旧硬编码，并保留 rollback 说明。

风险: 退役当天才发现依赖，会让本来简单的日报或发布任务变成紧急修复。

### 知识卡片: Rule Insights Ledger

规则不是写完就结束，要记录它实际拦截、漏拦和误伤的情况。

用户操作链路:

1. 列出每条规则的目标、作用路径和 owner。
2. 记录触发次数、通过次数、拦截次数和人工 override。
3. 把误拦、漏拦和绕过路径写入复盘。
4. 按路径区分公开输出、本地证据、自动化记忆和临时文件。
5. 每周调整一次规则，不让规则变成无人维护的噪音。

风险: 没有洞察台账，规则会在“太松漏风险”和“太严挡交付”之间来回摆。
