### 今日结论

今日主线是: AI 工作台正在从“多入口可用”进入“记忆、权限、预算和浏览器证据都要可治理”的阶段。Codex CLI 0.150.1 把 Remote compaction 的图片预算纳入上下文管理，说明长会话里的截图/图片不能再被当作免费上下文；ChatGPT Learn 的 8 月 24-28 周报把浏览器、Site tools(WebMCP)、云浏览器登录、事件触发任务、Apple Messages、Computer History 串在同一个工作面里；GitHub 和 VS Code 文档则把 Copilot/agent 的企业配置拆成 server、MDM、file 三条下发路径和权限优先级；Agents SDK 0.22.0 继续补 guardrail redaction、失败态抛错和 usage 隔离。

### Codex/GPT 工作流启发

1. Remote compaction 把 retained images 计入预算后，长会话里的图片、截图和视觉输入都要进入上下文账本。
2. 一旦截图类输入很多，别等系统报 context_length_exceeded；到阈值就换车，并把 handoff 写成文本事实。
3. 浏览器任务现在至少有三条 lane: 本地浏览器标签、内置浏览器 Site tools(WebMCP)、云浏览器登录；每条 lane 的证据和风险不同。
4. Site tools(WebMCP) 适合结构化网页动作，但要先确认工具 schema、权限和 dry-run，而不是让代理猜按钮。
5. 云浏览器登录不等于连接本地浏览器 profile；账号输入必须在登录流程里完成，不能把凭证写进聊天。
6. 事件触发 scheduled tasks 把 Gmail、Slack、GitHub PR 变成自动化入口；每条自动化都需要 payload schema 和幂等键。
7. 共享 scheduled task 是复制工作流，不是共享同一权限；接收者要用自己的 app permission 重新创建。
8. Apple Messages 可以从 Work/Codex 准备或发送消息，但 send 是外部副作用，必须逐次确认收件人和正文。
9. Computer History 是 opt-in 记忆层；适合“接着刚才的活干”，不适合无边界公开发布。
10. Record & Replay 把稳定桌面流程录成 skill；录制前先删掉不相关窗口和敏感上下文，录完再验证 skill 的输入和停止条件。
11. 插件不只是按钮集合，而是 skills、connectors、MCP servers、hooks 和 scheduled task templates 的组合包。
12. 插件内置 MCP server 需要 enabled_tools、disabled_tools、approval_mode 和 identity 规则，否则权限会被插件包装层遮住。
13. GitHub/VS Code managed settings 提醒我们: agent guardrails 必须同时看组织策略、设备策略、文件策略和客户端支持差异。
14. Agents SDK 0.22.0 的 blocked tool output redaction、terminal failed/incomplete 抛错、usage checkpoint 隔离，适合改进所有多步 agent 的验收模板。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 只派发任务信封，注明日期、允许公开来源、是否允许浏览器、停止条件和低风险审批范围。
2. Work: 对 Gmail/Slack/GitHub 事件触发任务，只生成计划和草稿；涉及发送、上传、权限、删除、发布时停下等确认。
3. Mac/Codex: 对长会话维护 Context Payload Budget，尤其记录图片和截图输入；超过阈值就换车。
4. 浏览器: 先选 lane。local tab 用观察前态/声明动作/执行/读回/验收；Site tools 用工具 schema 和结果对象；cloud browser sign-in 用登录流程而不是聊天凭证。
5. 插件/MCP: 每次开工前列出插件、MCP server、enabled tools、approval mode、写动作和回滚证据。
6. 发布: 仍由 Mac/Codex 写五文件包、跑检查、看 diff、commit、push、Vercel deploy、inspect Ready。

### 可沉淀知识卡片

#### 卡片 1: Context Payload Budget

- 概念: 把长会话里的文本、图片、截图、文件摘录和工具输出都当成可计量 payload，而不是只看 token 文本。
- 使用场景: Codex Remote、Computer Use、设计走查、截图密集 debug、长会话换车和自动化记忆。
- 操作步骤:
  1. 记录输入类型、数量、估计大小和来源。
  2. 设定文本、图片、附件和历史保留阈值。
  3. 超阈值时先生成文本 handoff，再清理或换车。
  4. compaction 后检查是否保留了不该保留的图片或私密路径。
  5. 复盘每次 context 失败，把阈值写回 runbook。
- 风险: 图片和截图如果被当成“看过就算了”，长任务会在最需要继续时被上下文预算卡死。

#### 卡片 2: Browser Lane Evidence Matrix

- 概念: 把网页任务分成 local browser、built-in browser Site tools、cloud browser sign-in 和公开网页只读四类 lane，每类有不同证据和停止条件。
- 使用场景: 网站测试、账号内只读查询、Work 网页任务、Codex 修 UI、插件或 WebMCP 工具调用。
- 操作步骤:
  1. 开工前声明 lane、目标 URL、是否登录、允许动作和禁止动作。
  2. local/UI lane 走观察前态、声明动作、执行、读回、验收。
  3. tool lane 记录 tool schema、参数、结果对象和错误码。
  4. cloud sign-in lane 只在登录流程输入凭证，不把凭证放进聊天。
  5. 发布公开内容前只保留公开链接和总结，剥离 DOM、截图和登录状态。
- 风险: 不区分 lane，就会把公开网页阅读、登录态操作和工具写动作混成一件事。

#### 卡片 3: Plugin/MCP Approval Matrix

- 概念: 对每个插件和 MCP server 记录 enabled、identity、enabled_tools、disabled_tools、default approval、per-tool approval 和写动作。
- 使用场景: Codex CLI/desktop 插件、ChatGPT Work connectors、团队插件市场、Figma/GitHub/Gmail/Slack 等工具接入。
- 操作步骤:
  1. 列出插件来源、安装面、MCP server 和连接账号。
  2. 给读、搜、草稿、写、发送、发布分别设置 approval mode。
  3. 对外部副作用默认 allow once，不给长期免审批。
  4. 每次运行后记录实际调用、失败、误触发和回滚路径。
  5. 删除不用的工具或把它移入 disabled_tools。
- 风险: 插件把 skill、connector、MCP 和 hook 打包后，权限容易被“安装了就能用”的体验遮住。

#### 卡片 4: Managed AI Settings Runbook

- 概念: 把 agent/AI 客户端设置当成运维配置: server-managed、MDM-managed、file-based、客户端支持矩阵、优先级和验证步骤。
- 使用场景: GitHub Copilot、VS Code AI、Codex CLI、企业插件、模型策略、MCP allowlist 和 bypass/auto-approve 禁用。
- 操作步骤:
  1. 记录默认策略、团队 override 和 owner。
  2. 标明 server、MDM、file 三种下发路径和优先级。
  3. 对每个 key 写客户端支持矩阵，避免以为所有客户端都支持。
  4. 小范围 pilot，读回配置是否生效。
  5. 每次模型、插件或权限策略变化后更新 runbook。
- 风险: 没有 runbook，agent 权限会在不同客户端、设备和团队之间漂移。

## 白话版

今天这期像是“家里开始同时有门铃、监控、钥匙柜、记事本和远程遥控器”，重点不再是哪个按钮新鲜，而是谁能按、按了留下什么小票、出了事怎么停。

Codex 0.150.1 的图片预算修复，像搬家箱子终于开始把相册也算重量。以前长会话里塞很多截图，好像没占地方；现在系统会更清楚地知道这些图片也会占上下文车厢。以后截图密集的任务要早点打包成文字交接，别等车厢塞满才发现开不动。

浏览器任务像有三种进门方式: 你自己的本地浏览器、网站给代理开的专用工具门(WebMCP)、以及云端临时登录门。三扇门的钥匙、监控和出门小票都不同。不能看到“浏览器”三个字就默认同一种安全边界。

事件触发 scheduled tasks 像把闹钟升级成门铃。以前是每天 9 点响，现在是 Gmail 来信、Slack 有反馈、GitHub PR 有评论就响。门铃很方便，但每个门铃都要写清楚谁按的、带了什么信息、重复按怎么办、谁负责最后处理。

Computer History 像桌上的工作日志本。它能帮你想起刚才在哪个 app、哪个网页做过什么，但这本本子默认不上锁就不该乱翻，所以要明确哪些 app 能写进去、什么时候暂停、哪些内容永远不能出现在公开日报里。

插件和 MCP 像工具箱，不只是一个扳手。里面可能有说明书(skill)、账号连接(connector)、远程工具(MCP)、甚至自动运行的 hook。安装工具箱前要先看清楚哪些工具能读、哪些能写、哪些按一次就会发出去。

所以今天最该沉淀的不是一条提示词，而是四张表: 上下文载重表、浏览器入口证据表、插件/MCP 审批表、企业 AI 设置运行手册。
