## 官方严谨版

### 今日结论

今日主线是: agent 工作台正在从“能接更多入口”进入“谁能批准、谁能保留数据、谁能花预算”的治理阶段。OpenAI Codex 0.152.0/0.152.1 把长任务超时、MCP 工具输出上限、凭证刷新、审批恢复和不可信后端 URL 拦截推到前台；ChatGPT iOS/Remote 的队列同步、后台发送和任务优先级让手机更像控制面，但最终证据仍要回到 Mac/Codex。GitHub 侧同日出现 Copilot PR approve、个人预算到期日、Claude Fable 5.1 数据保留政策、Copilot CLI 插件面板和组织登录钉扎，说明高能力 agent 不再只是模型选择，而是审批权、路径白名单、数据保留、预算有效期和跨设备收口的系统设计。

今天建议沉淀五个可复用资产: Connected-Host Queue Receipt、Approval Authority Split、Expiring Budget Lane、Model Retention Policy Gate、MCP Output Ceiling Contract。iPhone/Remote 继续只做派工、状态、补充和低风险审批；Mac/Codex 继续承担文件、测试、diff、commit、push、deploy 和最终收口。

### Codex/GPT 工作流启发

1. 手机端队列同步增强后，iPhone 更适合做任务信封和状态面，不适合替代本地验收。
2. 复制 thread ID 是低成本的跨设备定位能力，适合进入每次长任务交接记录。
3. Codex 0.152.1 的 Node REPL policy 修复说明自动审批必须读取模型元数据，不只看本地配置。
4. Codex 0.152.0 的长 shell timeout 让超长命令成为正式能力，也要求 owner、deadline 和中断条件可追踪。
5. MCP server name 支持 package-style 字符后，命名空间更清楚，但也要避免把 server 身份和工具权限混成一层。
6. MCP output_token_limit 是恢复安全的一部分；截断规则要跨 session 一致。
7. 凭证刷新进度出现在 TUI/exec 里，说明 auth 状态必须作为任务状态记录，而不是只有失败时才看。
8. 不可信 backend URL 和禁 redirect 是 cloud task 的凭证保护边界，可复用到所有 app-server agent。
9. 插件 dashboard 合并 MCP 配置后，插件、MCP、skills 应进入同一资产清单。
10. 企业组织登录钉扎说明 agent CLI 登录本身也需要组织白名单。
11. AI PR review 的 approval 能计入合并规则后，assessment、comment、approval 和 required-check 必须分层。
12. 预算到期日适合用于临时 agent lane，避免一次试验变成永久额度。
13. 长任务模型如果改变数据保留模式，不能只按能力强弱排序，必须先过隐私和管理员策略 gate。
14. Copilot policy convergence 会把 mobile/browser/cloud agent 拉成同一策略，提前审计 retention、billing 和 default effort。
15. VS Code Agent Host 的多窗口、side chat、prompt timeline 和 browser annotations 适合做“多入口协作台”，但证据归属要写清。
16. Agents SDK Python/JS 的 replay hardening 继续提醒: 被拦截输出、外部副作用和应用自有日志是三件事。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 创建或补充任务信封，优先写清目标、目标仓库、截止时间和是否允许发布。
2. iPhone/Remote: 用 Priority view 查看运行中、未读、待响应任务；只批准低风险动作。
3. iPhone/Remote: 复制 thread ID 给 Mac/Codex，避免长任务恢复时靠口头描述找会话。
4. Mac/Codex: 读取 queue receipt 后执行本地文件、测试、diff、commit、push、deploy。
5. Mac/Codex: 对 Codex 0.152.x 的自动审批增加 Node REPL policy readback；对 MCP 工具补 output ceiling。
6. Mac/Codex: 长 shell command 超过常规时间时写 owner、deadline、停止条件和最后可验证输出。
7. GitHub/Copilot: 若启用 AI approval，先从 enterprise/org/repo/path 四层确认白名单，再让 approval 计入 merge rule。
8. 知识库: 只沉淀可复用 gate，不堆 release note 原文。

### 可沉淀知识卡片

#### 卡片 1: Connected-Host Queue Receipt

- 概念: 把手机、Remote、桌面和云端之间的排队提示当作可审计任务信封。
- 使用场景: iPhone/Remote 派工、Codex 长任务、跨设备恢复、后台发送队列。
- 操作步骤:
  1. 记录 origin device、connected host、queued prompt、editable window、background-send status 和 thread ID。
  2. 手机只能派工、补充和低风险审批；最终文件、测试、commit、push、deploy 仍由 Mac/Codex 收口。
  3. 队列发送后必须回读任务状态，不能把“已发送”当作“已完成”。
- 风险: 队列同步越顺手，越容易把控制面误当执行面。

#### 卡片 2: Approval Authority Split

- 概念: 把“AI 认为可以通过”和“AI 的批准计入合并规则”拆成两层。
- 使用场景: AI PR review、自动审批、required approval、路径白名单、代码所有权。
- 操作步骤:
  1. 默认只允许 AI 给 assessment 和 comments。
  2. 只有 enterprise/org/repo policy 明确开启且路径白名单命中时，approval 才能计入 required approvals。
  3. 新 commit 推送后重新请求审查，旧批准自动失效。
- 风险: 没有拆层时，团队会误把建议性结论当成正式审批。

#### 卡片 3: Expiring Budget Lane

- 概念: 给临时 agent 试验设置会自动到期的预算，而不是永久额度。
- 使用场景: 临时模型试用、长任务预算、外部模型评估、团队试点。
- 操作步骤:
  1. 为每个试验记录 owner、plan、budget、expires_at、允许模型和允许工具。
  2. 预算到期前复核是否保留、扩容或关闭。
  3. 高成本模型和长任务必须和到期预算绑定。
- 风险: 无到期预算会让一次试验变成长期开销。

#### 卡片 4: Model Retention Policy Gate

- 概念: 选长任务模型前先确认数据保留、零保留资格和管理员策略。
- 使用场景: GitHub Copilot 模型选择、Claude 系列模型、企业 ZDR 例外、敏感代码仓库。
- 操作步骤:
  1. 记录模型、供应商、适用入口、是否默认保留数据、ZDR/例外资格和计费模式。
  2. 需要保留数据的模型默认不上私有代码和敏感知识库。
  3. 管理员启用策略本身也要作为显式确认记录。
- 风险: 高能力模型不等于同一隐私边界。

#### 卡片 5: MCP Output Ceiling Contract

- 概念: 给每个 MCP 工具配置输出上限和恢复后一致截断规则。
- 使用场景: MCP 工具、长输出日志、恢复会话、公开日报生成、插件工具链。
- 操作步骤:
  1. 记录 server name、tool name、output_token_limit、截断提示和恢复后行为。
  2. 长输出工具先做摘要或分页，再进入模型上下文。
  3. 公开输出前扫描凭证、本地路径和非公开状态。
- 风险: 工具输出过大时，截断不一致会破坏恢复、审批和复盘。

## 白话版

今天这期像“手机遥控器终于能更稳地遥控工作台了”。iPhone 可以把任务排进队列、在后台继续发送、看到哪些任务正在跑、哪些任务等你答复，还能复制 thread ID。它很像遥控器和取号码牌: 能发号、改号、查号，但真正做菜、尝味、装盘，还是厨房里的 Mac/Codex。

Codex 0.152.0/0.152.1 像给厨房换了一套更精细的规章: 哪些命令可以跑很久、MCP 工具最多吐多少字、凭证什么时候在刷新、Node REPL 这种能执行代码的工具要听谁的审批规则。这不是“更爽地乱跑命令”，而是每一步都更适合写清边界。

GitHub Copilot 这边更像把“实习审稿人”升级成“可能签字的人”。以前 AI review 主要是提意见，现在管理员可以让它的 approval 算进合并规则。但这张签字权默认不开，而且要按公司、团队、仓库、文件路径一层层批。也就是说，AI 可以先说“我觉得能过”，但要不要真的盖章，是另一件事。

预算到期日像临时饭卡。试用一个高成本 agent 或模型，不要给永久饭卡，给一张会过期的卡，到点复核要不要续。Claude Fable 5.1 这种长任务模型则像请外部专家进会议室，能力强不代表保密规则一样，先问清数据会不会保留、谁批准、费用怎么算。

所以今天的重点不是追新模型，而是把“手机派工、桌面收口、AI 审批、预算到期、模型保密、MCP 输出上限”这几件事分清楚。遥控器可以更好用，但验收章还得盖在证据齐全的工作台上。
