## 官方严谨版

### 今日结论

今日主线是: AI 工作台正在从“能执行任务”升级为“可治理、可串联、可审计的代理系统”。Codex release 把任务 @mention、终端任务控制和 Interrupt hooks 推到前台；GitHub 的 global model policy 说明模型启用不再只是个人选择，而是默认策略和例外治理；OpenAI Admin plugin、Enterprise/Edu 控制、WebMCP、Programmatic Tool Calling 和 Runme/WebMCP 复用流程，说明插件、站点工具、工具编排和团队管理都需要明确的权限、证据和回滚；Hugging Face 事故则把高能力代理的网络、凭证、监控和停止权限变成硬边界。

直接动作是: 后续个人和团队自动化不要只写 prompt 或 cron。每条流程要沉淀四类资产: Task Link Ledger、Model Policy Matrix、Agent Tool Surface Spec、Capability Containment Review。iPhone/Remote 继续只做派工、状态和低风险审批；Work/浏览器只做已声明证据环内的只读或草稿动作；Mac/Codex 仍负责本地文件、测试、diff、commit、push、deploy 和最终证据。

### Codex/GPT 工作流启发

1. Codex 任务 @mention 和终端任务控制让任务之间开始形成图谱；要维护 task id、依赖、owner 和完成证据。
2. Interrupt hooks 把中断变成可编排事件；高风险任务要定义中断时的 snapshot、cleanup、partial result 和 resume 命令。
3. GitHub global model policy 提醒我们: 新 GA 模型可能继承默认策略，自动化不能只依赖“当前能跑”。
4. Model Policy Matrix 要同时记录默认值和显式例外，尤其是 open-weight、数据保留、预览模型和区域合规限制。
5. Admin plugin 说明管理动作会进入 ChatGPT Work 和 Codex，但 write action 仍必须有授权、结构化结果和独立读回。
6. Enterprise/Edu 控制面把 plugins、skills、Remote、usage limits 和 analytics 放到同一治理层；个人工作流也应照这个思路建台账。
7. Runme + WebMCP 的案例说明，可复用 workflow 应该是可运行资产，而不是藏在聊天记录里的经验。
8. WebMCP 的方向是把网站动作变成结构化工具；内部工具应先给代理可调用表面，而不是让代理猜 UI。
9. Programmatic Tool Calling 适合 bounded tool graph；如果没有循环预算、allowed_callers 和审计日志，就不要急着上线。
10. 浏览器任务现在有 local tab、site tools、cloud sign-in 多条 lane；每次执行前必须声明使用哪条证据链。
11. Apple Messages 和 shared Codex snapshots 让 Mac/iOS 协作更顺，但 send/share 是外部副作用，必须单次审批。
12. Hugging Face 事故说明 agent containment 不是安全团队的抽象话题，而是所有可联网、可拿凭证代理的工程前置条件。
13. source-card 采集也要区分官方、一手转述和社区文章；今天只把官方和可公开验证材料作为主证据。
14. 公开日报只保留链接和总结；本地 route receipt、终端输出、登录状态和过程截图不进入公开边界。

### 可沉淀知识卡片

#### 卡片 1: Task Link Ledger

- 概念: 多 Codex 任务互相 @mention 或由终端创建/消息时，要记录 task id、依赖、owner、状态、允许动作和最终证据。
- 使用场景: 用于长会话、并行子任务、跨线程派工和任务接力，防止“某个任务说过”变成不可追溯的完成依据。
- 操作步骤:
  1. 记录 owner、适用范围和触发条件。
  2. 固定输入、权限、允许动作和禁止动作。
  3. 设置 readback、日志、预算或停止条件。
  4. 产出后对照本地证据复核。
  5. 每次复用后记录误触发、漏项和需要更新的规则。
- 风险: 没有这张卡，代理能力增强会先表现为边界扩散，而不是稳定提效。

#### 卡片 2: Model Policy Matrix

- 概念: 把模型分成默认继承、显式启用、显式禁用和永不默认四类，并记录 rollout date、owner 和审批轨迹。
- 使用场景: 用于 Copilot、Codex、Agents SDK 或任何多模型工作台，避免新模型靠默认策略进入高风险流程。
- 操作步骤:
  1. 记录 owner、适用范围和触发条件。
  2. 固定输入、权限、允许动作和禁止动作。
  3. 设置 readback、日志、预算或停止条件。
  4. 产出后对照本地证据复核。
  5. 每次复用后记录误触发、漏项和需要更新的规则。
- 风险: 没有这张卡，代理能力增强会先表现为边界扩散，而不是稳定提效。

#### 卡片 3: Agent Tool Surface Spec

- 概念: 给 WebMCP 或站点工具定义 action、input schema、权限、dry-run、result schema、错误码和审计字段。
- 使用场景: 用于把网页从“让代理猜按钮”升级为“给代理调用工具”，尤其适合内部后台和可重复流程。
- 操作步骤:
  1. 记录 owner、适用范围和触发条件。
  2. 固定输入、权限、允许动作和禁止动作。
  3. 设置 readback、日志、预算或停止条件。
  4. 产出后对照本地证据复核。
  5. 每次复用后记录误触发、漏项和需要更新的规则。
- 风险: 没有这张卡，代理能力增强会先表现为边界扩散，而不是稳定提效。

- 概念: 高能力代理拿到网络、凭证或共享基础设施前，先审查 egress、credential scope、monitoring triggers、stop authority 和 incident owner。
- 使用场景: 用于 cyber eval、browser/computer use、CI/CD 写入、云资源管理和任何可能越权的代理任务。

## 白话版

今天这期像是“家里不只是多了几个电器，而是开始装配电箱、门禁和停电开关”。

Codex 的任务 @mention 和终端任务控制，像施工现场的工单终于能互相引用。以前每个工人各干各的，现在 A 工单能指向 B 工单，终端也能派新工单、发消息。好处是协作快，坏处是如果没有工单账本，就会没人知道到底谁负责、谁验收、哪个工单还没完。

GitHub 的全局模型策略，像公司把“哪些工具能上架”放进超市上架清单。不是每个新品都靠个人手动开关，而是先按默认规则处理，再对高风险货架做例外。对 AI 工作流来说，模型不是随便换的按钮，而是有默认值、例外、负责人和下线日期的资产。

Admin plugin 像把管理员后台搬进聊天窗口。你可以问谁快超额度、谁缺权限、哪个团队需要开通功能，但真正改权限、调额度、加人删人之前，还得确认“我有权改、改哪里、改完读回是什么”。聊天入口不是万能遥控器，权限和小票要齐。

WebMCP 和 Programmatic Tool Calling 像给代理铺了专用通道。以前代理要看屏幕猜按钮，现在网站可以把“查找章节”“添加评论”“生成结果”做成明确工具。这样更稳，但也更需要写清楚哪些工具能调、最多循环几次、失败怎么停。

Hugging Face 事故像一次很刺眼的消防演习失败。不是说所有代理都不能用，而是说明强代理拿到网络、凭证和共享设施前，必须先装隔离墙、监控器和急停按钮。能干活的机器越强，开工前的安全检查越不能省。

所以今天最该沉淀的不是一个新提示词，而是四张表: 任务链接账本、模型策略矩阵、代理工具表面说明、能力 containment 审查。
