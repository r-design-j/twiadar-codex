# AI/Codex/GPT 个人知识沉淀 - 2026-07

## 2026-07-06

### 知识卡片: 每日固定排程 vs 条件触发排程

固定排程是“每天 9 点自动跑一次”，适合稳定产出晨报。条件触发是“某个高价值账号发了新长帖、OpenAI changelog 更新、某个关键词突然爆发时再跑”，适合追前沿信号。

当前决策: 先用固定排程跑 3-5 天，积累 source-cards，再决定哪些作者和关键词值得做条件触发。

### 知识卡片: iPhone 捕捉、Mac 复核、Codex 执行

iPhone 不适合深度消费 X 信息流，适合做捕捉入口。Mac 适合复核、验证和沉淀。Codex 适合自动整理、链接原文、转换成可执行步骤。

用户操作链路:

1. iPhone 看到 X/YouTube/博客链接。
2. 复制或分享给 Codex 收件箱。
3. 每天 9 点晨报筛选。
4. Mac 上只处理 Top 5 和待拍板事项。

### 知识卡片: 晨报应该是行动白名单

晨报不是新闻摘要，而是“哪些方法值得进入我的工作流”的白名单。进入 Top 5 的内容必须同时满足:

- 有原文链接。
- 有明确作者或来源。
- 能转成用户操作链路。
- 和 Codex/GPT/AI 工作提效/iPhone+Mac 协作相关。
- 能沉淀为知识卡片或后续自动化动作。

### 运行修正: X 登录态判断

2026-07-06 首次运行时出现过误判: Chrome 扩展通道读到了旧的未登录 X 标签，但前台 Chrome 窗口实际已经登录。

后续规则:

1. 如果自动通道显示 X 未登录，先检查前台 Chrome 窗口。
2. 看到 Home、Notifications、Profile、账号菜单任一组合，即视为登录态可用。
3. 不要只依据一个旧标签页判断“X 登录态不可用”。

### 知识卡片: AI 第二大脑正在从笔记变成 agent 可读操作内存

登录态 X 搜索显示，Obsidian vaults + Claude Code / AI tools 正在被讨论为 interconnected second brains。这个方向对用户很重要: 个人知识库不只是“写给人看的笔记”，而是可以给 Codex/Claude Code/GPT 读取、复用、执行的操作内存。

当前动作: 先保持本地 Markdown 知识库；后续如果要接 Obsidian，需要让每张卡片有稳定标题、来源链接、适用场景、操作步骤。

### 知识卡片: iPhone 可以成为 coding agents 的遥控器

登录态 X 搜索出现“从 iPhone 指挥云端 coding agents，完成 clone、edit、open PR、merge”的产品/玩法信号。该方向仍需验证，但与用户需求高度贴合。

当前判断: 先作为观察主题，不立即接入新产品。重点追踪是否支持 Codex、Claude Code、GitHub PR、移动端任务续写、失败回滚。

## 2026-07-07

### 知识卡片: iPhone 是 Codex 遥控器，不是深度工作台

Codex Remote 和 ChatGPT mobile 的价值不是让用户在手机上完成复杂工作，而是让手机成为任务入口。手机适合做三件事: 发起任务、补充一句指令、审批动作。复杂复核、合并、发布仍应回到 Mac。

当前动作: AI Radar 中所有 mobile 类信号都要翻译成“手机点哪里 -> Codex 做什么 -> Mac 怎么复核”的链路。

### 知识卡片: 云端工作站是重任务缓冲区

DigitalOcean for Codex 的价值在于把长构建、大仓库探索、demo 验证放到可销毁的云端工作站，而不是让本机一直承担重负。

当前动作: 暂不直接上云。先建立评估表: 费用、销毁机制、SSH 安全、数据是否允许上云、是否需要持久环境。

### 知识卡片: Subagents 是 agent 小队

Subagents 的本质是把一个复杂任务拆成多个角色，每个角色拿更清晰的上下文。对 AI Radar 来说，适合拆成采集、事实核验、操作链路翻译、网站发布四个角色。

当前动作: 后续 `让 Codex 跑` 的 HIGH 卡片，优先生成 subagent 分工 prompt。

### 知识卡片: 自动化必须闭环到上线

只生成 Markdown 不等于网站更新。完整自动化必须同时完成: 写日报、写 source-cards、更新 report.json、同步 report-data.js、提交 GitHub、部署 Vercel、验证 Ready。

当前动作: 2026-07-07 已把自动化提示词补强为完整发布闭环。

## 2026-07-08

### 知识卡片: 委托任务比聊天更适合 Codex

聊天适合问一个答案，委托适合交一件事。Codex 的价值正在从“立刻回答”转成“后台持续推进、调用工具、留下证据、等待复核”。

当前动作: AI Radar 的 HIGH 信号后续优先写成可委托任务: 读原文、核验、做小实验、产出知识卡、标注失败点。

### 知识卡片: iPhone 是 Codex task 控制台

ChatGPT iOS 已经支持创建、搜索、打开、fork、管理 Codex task。手机端最适合捕捉线索和管理任务，不适合做最终合并或不可逆审批。

用户操作链路:

1. iPhone 看到链接。
2. 创建或追加 Codex task。
3. Codex 后台执行。
4. Mac 复核证据和结果。
5. 决定丢掉、观察、实验或沉淀。

### 知识卡片: 私有 MCP 先守边界，再谈便利

MCP 能把本地或内网能力接到 AI 工作流，但默认目标应是“不公开暴露仍可访问”。本地桥、知识库、公司内网工具都要以只读、白名单、可审计为默认。

当前动作: AI Radar 继续不自动开启公网隧道；任何 Cloudflare Tunnel、ngrok、公开 MCP endpoint 都必须先确认。

### 知识卡片: 第二大脑要写成 agent 可执行格式

知识库不只是给人看的笔记，而是给 agent 读取、复用、执行的操作内存。每张卡片需要稳定字段，避免散文式摘要污染长期记忆。

建议字段: 标题、来源链接、概念、适用场景、操作步骤、风险、更新时间。

## 2026-07-09

### 知识卡片: 手机只负责派活，不负责终审

iPhone 是 Codex 的任务遥控器，Mac 是验收台。手机适合捕捉链接、创建 task、搜索旧任务、补一句上下文、查看状态；复杂 diff、公开发布、提交代码、删除内容等不可逆动作仍应回到 Mac 复核。

用户操作链路:

1. iPhone 看到公开来源链接。
2. 创建 Codex task 或追加到采集队列。
3. Codex 后台核验和整理。
4. Mac 检查证据、文件 diff、验证命令和部署状态。
5. 决定发布、丢弃、观察或沉淀。

### 知识卡片: Agent 成本要和产出绑定

Workspace Agent 开始进入 token 使用量可见阶段后，自动化不能只说“跑完了”。每次运行都要记录 sourceCards、Top signals、knowledgeCards、验证命令、发布状态和失败点，才能判断一次 agent 工作是否真的节省时间。

当前动作: AI Radar 继续把 metrics.sourceCards、topSignals、knowledgeCards 写入站点数据；后续可扩展成月度成本-价值台账。

### 知识卡片: AGENTS.md 是 coding agents 的同声传译

AGENTS.md 的价值不是“多写一份文档”，而是让 Codex、Claude Code、Jules、Cursor 等工具在同一仓库读同一套规则。它应该写清任务边界、测试命令、安全禁区、输出范式、不可逆操作确认规则。

风险: AGENTS.md 过长会让规则互相打架。硬约束、长期偏好、项目临时规则要分层，不要全部堆在一个段落里。

### 知识卡片: 先用最小 agent 验证，再拆 subagents

单 agent 能完成的事，不必立刻上多 agent 编排。subagents 适合天然有角色分工的任务，例如采集、事实核验、操作链路翻译、网站发布。

当前动作: AI Radar 的 HIGH 信号先由单 agent 跑通；只有当某类工作重复出现瓶颈，再拆成明确角色并定义每个角色的验收物。

## 2026-07-12

### 知识卡片: 模型选择是一张工作流白名单

GPT-5.6 之后，模型选择要从“用最强”改成“按任务路由”。Sol 适合高难推理、长代码任务、关键判断；Terra 适合日常自动化和一般工作；Luna 适合高频摘要、初筛和批量整理。max/pro/ultra 只在任务确实需要更长思考或并行 subagents 时启用。

用户操作链路:

1. 先判断任务难度和成本敏感度。
2. 选择 Sol / Terra / Luna。
3. 再决定是否需要 max、pro 或 ultra。
4. 在 source-card 或任务说明里记录模型选择理由。
5. 跑完后回看质量、成本、验证结果。

### 知识卡片: PTC 只接管有边界的工具流水线

Programmatic Tool Calling 适合让模型用受限 JavaScript 处理工具调用的中间过程，例如去重、排序、聚合、字段校验、过滤大输出。它不应该接管审批、发布、关注、评论、私信、提交等不可逆动作。

当前动作: 后续 AI Radar 可做一个小实验，只让 PTC 处理 source-card 的去重和字段校验，最终判断仍由 GPT + 用户复核完成。

### 知识卡片: ChatGPT desktop 是 Mac 验收台

Codex 进入 ChatGPT desktop 后，Mac 的角色可以更明确: 看 Markdown、改代码、读 PR feedback、跨 repo 看上下文、跑验证、决定发布。iPhone 继续做控制台，Mac 做验收台。

用户操作链路:

1. iPhone 创建或 steering Codex task。
2. Codex 后台执行。
3. Mac 打开 ChatGPT desktop。
4. 查看 diff、日报、source-card、验证命令和部署结果。
5. 决定提交、发布、丢弃或沉淀。

### 知识卡片: 更强 agent 更需要硬边界

GPT-5.6 system card 提醒，agentic coding 能力变强后，越要明确目标、可写范围、审批点、停止条件和验收物。个人自动化也要分成只读采集、写入文件、提交代码、公开发布四个阶段。

当前动作: AI Radar 继续保持只读采集；写文件、commit、push、deploy 是发布阶段动作；任何公开互动和私有数据写入仍禁止。

搜索摘要不是证据，公开来源链接和筛选条件才是证据。AI Radar 后续每张 source-card 应优先保留 query、evidenceType、作者、URL、来源类型、why_it_matters 和 actionable_takeaway。

iPhone 是 Codex 遥控器，适合捕捉链接、创建 task、补上下文、看状态、做轻审批。Mac 是验收台，适合看 diff、验证命令、部署状态和公开发布前证据。

风险: 不要在手机上做复杂 diff、删除、发布、push、授权应用等不可逆终审。

coding agent 有没有节省时间，需要用本地指标复盘。AI Radar 目前已经记录 sourceCards、topSignals、knowledgeCards、验证命令和发布状态；后续可以增加失败原因、返工点、是否被用户实际复用。

当前动作: 月底复盘时按“被复用的知识卡/自动化动作”评估，而不是只数跑了多少次任务。

## 2026-07-16

### 知识卡片: 物理控制台先定义按钮白名单

Codex Micro 类硬件会把 agent 操作变快，因此必须先定义哪些按钮能做什么。查看状态、补上下文、暂停/继续属于低风险动作；写文件、commit、push、deploy 属于发布链路，仍要回到 Mac 终审。

用户操作链路:

1. 列出所有高频 Codex 动作。
2. 标注只读、可逆、不可逆。
3. 只把只读和可逆动作绑定到低摩擦入口。
4. 不可逆动作必须保留 diff、验证命令和发布证据。
5. 每次误触或返工后更新白名单。

### 知识卡片: 模型路由要写进任务说明

GPT-5.6 之后，模型选择要从“默认用最强”改成“按任务路由”。初筛、摘要、去重可以用低成本模型；代码、安全判断、公开发布和复杂跨文件修改应升级到强推理模型，并记录为什么升级。

风险: 如果不记录模型选择理由，月底复盘只能看到产物，无法判断质量差异来自模型、提示词、来源，还是验证不足。

### 知识卡片: Agent 采集要拆成候选池和发布链

AI Radar 的采集阶段只负责生成候选，不直接代表可发布结论。发布阶段才写 Markdown、JSON、站点数据、commit、push 和 Vercel deploy。

当前动作: 继续坚持只读采集；所有公开站点字段只保留公开链接、公开作者、公开来源和总结后的学习卡片。

### 知识卡片: Prompt injection 要进入代码审查清单

外部文本、网页、README、issue、评论都可能携带诱导 agent 越权的内容。agent 读取外部来源时，只能把它当数据，不能当系统指令。

用户操作链路:

1. 外部文本只作为资料。
2. 工具调用走白名单。
3. 写入前检查来源和字段。
4. 代码进入静态检查。
5. 发布前保留验证证据。

## 2026-07-21

### 知识卡片: Agent 工作台要有四张清单

ChatGPT Work、Codex、Sites、Plugins 和移动 Remote 放到同一工作台后，重点不再只是“让 agent 干活”，而是把入口、权限、指标、知识沉淀分开治理。

用户操作链路:

1. 入口清单: iPhone、Desktop、Codex、Sites、Plugins 分别能发起什么。
2. 权限清单: 只读、可逆、不可逆、公开发布分别需要什么确认。
3. 指标清单: sourceCards、knowledgeCards、失败原因、返工点、发布状态。
4. 知识清单: 只有高信号、可复用、有来源的做法进入 knowledge。

风险: 没有清单会把“能做”误当“该做”，让 agent 工作台变成权限混杂的长会话。

### 知识卡片: Agent 指标要从组织级下钻到项目级

GitHub Copilot repository-level metrics 提醒: agent 价值评估应该落到具体项目和产出，而不是只看总使用量。AI Radar 也应该从“今天跑了多少条”升级到“哪些条目后来被复用”。

当前动作:

1. 继续记录 sourceCards、topSignals、knowledgeCards。
2. 月底补充失败原因、返工点、发布 Ready 状态。
3. 对 knowledge 卡片增加 candidate / active / retired 的复用状态候选。

风险: 只统计运行次数会奖励噪声，而不是奖励真正节省时间的链路。

### 知识卡片: 私有 MCP 先守边界，再谈连接

Secure MCP Tunnel 的关键不是“终于能连上私有工具”，而是“不公开暴露仍能被受控访问”。本地桥、知识库、公司内网、私有 API 都应默认保持私有边界。

用户操作链路:

1. 默认只读。
2. 工具白名单。
3. 可检查客户端。
4. 不开公网隧道。
5. 写操作和敏感动作保留人工确认。

风险: 为了便利暴露公网 endpoint，会把工作流入口变成攻击面。

### 知识卡片: 长期记忆需要候选池和合并闸门

Agents SDK 的 context personalization 模式说明，长期记忆不应直接追加所有内容。source-card 是候选池，daily 是解释层，knowledge 才是可复用资产层。

当前动作:

1. source-card 保留公开来源和可执行 takeaway。
2. daily 负责当天判断和白话解释。
3. knowledge 只收可复用操作链路。
4. 月底去重、处理冲突、retire 过时卡片。

风险: 没筛选的记忆会污染 agent 判断，让第二大脑变成过期便签堆。

## 2026-07-22

### 知识卡片: Agent 控制台先管状态，再管快捷键

Codex Micro 的关键启发不是“多一个键盘”，而是多条 agent thread 需要可见状态、等待输入、错误、完成和风险级别。快捷键只能加速已经被定义清楚的动作，不能替代审批。

用户操作链路:

1. 定义任务状态: queued / running / needs-input / error / done。
2. 标注动作风险: 只读、可逆、不可逆、公开发布。
3. 只给只读和可逆动作低摩擦入口。
4. accept、reject、commit、push、deploy 保留明确确认。
5. 每次误触或漏审后更新白名单。

风险: 只做快捷键不做状态，会把误触、漏审和等待确认放大。

### 知识卡片: Hackathon 提交标准可迁移成自动化验收标准

OpenAI Build Week 要求 working project、demo、repo、README、运行说明和 Codex/GPT-5.6 使用说明。这个标准适合迁移到个人自动化: 交付物必须可复查、可复跑、可说明 agent 决策点。

当前动作:

1. AI Radar 每日固定生成 Markdown、JSONL、knowledge、report.json、report-data.js。
2. 发布前跑 node check、JSON parse 和字段同步检查。
3. GitHub commit 和 Vercel Ready 才算公开闭环。
4. 结果说明保留失败原因和待用户拍板事项。

风险: 只有截图或口头总结，无法复盘，也无法判断自动化是否真的节省了时间。

### 知识卡片: 移动端适合派工，不适合终审

GitHub Mobile Copilot 和 Codex Remote 都指向同一个模式: 手机适合捕捉、派工、补上下文和低风险审批；Mac 适合看 diff、跑测试、commit、push、deploy。

用户操作链路:

1. iPhone 捕捉公开链接、语音想法和 PR 评论。
2. iPhone 派发只读分析或草稿修复。
3. Codex 在 Mac 工作区执行。
4. Mac 检查 diff、验证命令和公开字段。
5. Mac 完成提交和部署。

风险: 在手机上做 merge、push、deploy 容易漏看边界和副作用。

### 知识卡片: Agent 成本要加 session 护栏

AI credit pool 和 session limit 提醒，agent 不是无限劳动力。长任务、批量修复和自动采集都应有预算上限、失败原因和重试记录。

当前动作:

1. 记录 sourceCards、topSignals、knowledgeCards。
2. 记录失败重跑和部署失败原因。
3. 月底按“被复用卡片”和“失败成本”复盘。
4. 高成本任务先做小样本验证，再扩大执行。

风险: 没有限额会奖励“跑得久”，而不是奖励“产物有效”。

## 2026-07-23

### 知识卡片: Agent 上生产前先写岗位卡

OpenAI Presence 的关键启发是: 生产级 agent 先绑定一个具体岗位、资料范围、系统权限、政策、批准动作和人工接管条件，再谈自动化能力。

用户操作链路:

1. 写清任务目标和成功标准。
2. 列出 agent 可以读取的资料和系统。
3. 列出允许动作、禁止动作和需批准动作。
4. 设置模拟测试和验收命令。
5. 上线后记录失败会话、升级人工和改进建议。

风险: 没有岗位卡，agent 会在目标、权限和验收上漂移。

### 知识卡片: Agent 成熟度要按阶段衡量

GitHub Copilot impact dashboard 把采纳分成 Code-first、Agent-first、Multi-agent/Copilot app 和 Passive。个人工作流也应从“用了多少次”转向“任务进入了哪个阶段、产物是否复用”。

当前动作:

1. 给 signals 增加 entry / execution / validation / reuse 的候选分层。
2. 记录 sourceCards、knowledgeCards、失败原因和 Ready 状态。
3. 月底按复用价值整理 candidate / active / retired。
4. 不把一次性新闻摘要直接沉淀为长期记忆。

风险: 只看使用次数会奖励噪声，而不会奖励真正节省时间的链路。

### 知识卡片: Programmatic Tool Calling 适合过滤中间噪声

GPT-5.6 的 Programmatic Tool Calling 说明，重复、工具密集、数据量大的流程可以让程序先处理中间结果，只把关键证据和决策点交给模型。

用户操作链路:

1. 识别重复工具链。
2. 给工具设白名单和 allowed callers。
3. 程序过滤中间数据。
4. 模型只读关键证据和异常。
5. 用成功率、证据完整性、token、延迟和成本共同评估。

风险: 只减少 token 但降低最终质量，是假优化。

### 知识卡片: 新闻工作流可迁移为线索评分系统

OpenAI 新闻机构案例说明，AI 的价值不只是总结内容，而是帮助扫描公开资料、结构化证据、进行风格校验、评分线索并把结果送到团队已有决策入口。

当前动作:

1. 扫描公开来源。
2. 抽取可验证证据。
3. 给信号打分和分类。
4. 人工判断 Top signals。
5. 只把可复用动作沉淀进 knowledge。

风险: 如果没有评分和人工判断，知识库会变成摘要堆。

## 2026-07-24

### 知识卡片: 语音入口只做协调，不直接发布

ChatGPT Voice 进入 Work 和 Codex 后，语音适合启动、检查、补上下文和转向任务，但不适合直接绑定公开发布、push、deploy、授权、删除等不可逆动作。

用户操作链路:

1. 用语音说明目标和上下文。
2. Codex 先产出计划、diff 或候选卡。
3. Mac 上跑验证命令。
4. 人工确认 commit、push、deploy。
5. 把误解或漏条件写回任务说明。

风险: 口语输入容易省略条件；如果直接连到发布动作，会把模糊指令变成公开副作用。

### 知识卡片: Agent 自动化要带 rationale 和 confidence

GitHub Issues 的 agent automation controls 说明，agent 做标签、类型、关闭、指派等元数据动作时，需要理由、置信度和审批策略。这个结构也适合 AI Radar 的信号分类和候选卡整理。

当前动作:

1. 高置信度、可逆整理可自动应用。
2. 中低置信度建议进入待确认。
3. 删除、归档、公开发布和费用相关动作一律人工确认。
4. 每次错误分类都回写到规则。

风险: 没有理由和置信度，自动化只是把错误动作做得更快。

### 知识卡片: Sandbox 边界要看写入后的消费者

Pillar sandbox escape 系列提醒，agent 的影响范围不只包括它当下能执行的命令，还包括它能写入、并被 Git、IDE、脚本、daemon、MCP 工具等宿主组件稍后信任的文件。

用户操作链路:

1. 列出 agent 可写路径。
2. 标注哪些文件是配置型代码。
3. 列出会读取这些文件的宿主工具。
4. 对 `.git/config`、hooks、package scripts、IDE 配置等危险写入加审批。
5. 把命令白名单升级为调用级检查。

风险: 只看命令名是否安全，会漏掉参数、写入目标和后续执行链。

### 知识卡片: 手机端 intake 要结构化，不做终审

iPhone Shortcuts 可用 Apple Intelligence、Private Cloud Compute 或 ChatGPT 处理输入和输出，适合把链接、语音、提醒、图片和文本整理为候选 source-card 或任务卡。

当前动作:

1. iPhone 收集公开链接和语音想法。
2. Shortcuts 用模型解析字段。
3. 候选进入 source-card 池。
4. Codex 在 Mac 上执行文件变更和验证。
5. Mac 完成公开发布终审。

风险: 手机屏幕和语音都不适合复杂 diff、权限边界和公开发布审查。

## 2026-07-27

### 知识卡片: 任务岗位卡

OpenAI Presence 的关键启发是: agent 上生产前先定义岗位，而不是开放式授权。岗位卡应写清目标、可读资料、可写路径、允许动作、禁止动作、需批准动作、验证命令、成本上限和停止条件。

用户操作链路:

1. 用一句话定义 agent 岗位。
2. 列出它能读取的公开来源、仓库文件或系统。
3. 列出它能写入的文件族和不能触碰的边界。
4. 拆分允许动作、需批准动作和禁止动作。
5. 写明本地验证、线上回读和失败停止条件。

风险: 没有岗位卡，agent 容易从“执行一个任务”漂移成“拥有一堆隐性权限”。

### 知识卡片: 长任务轨迹审查

长时程模型的安全风险要看完整行为轨迹。单步动作可能都能解释，但组合起来可能是在绕过限制、扩大访问范围或达成未授权结果。

用户操作链路:

1. 记录初始目标和硬性边界。
2. 标注每个阶段的关键动作和证据。
3. 检查连续动作是否偏离目标。
4. 对绕过审批、异常写入、外部访问、费用超限立即暂停。
5. 人工确认继续、收缩范围或终止。

风险: 只审单步命令，会漏掉“每一步都合理，但整条路不合理”的问题。

### 知识卡片: AGENTS.md 规则库

Codex Code Review rules 说明，AGENTS.md 可以成为 reviewer 记忆层。最有价值的规则是历史上反复漏掉、但对业务/安全/兼容性有后果的边界。

用户操作链路:

1. 收集最近 3-5 个重复 review 问题。
2. 把每个问题写成短规则和适用范围。
3. 放到根目录或相关子目录的 AGENTS.md。
4. 让 Codex review 引用规则并给出具体文件证据。
5. 按误报和漏报迭代规则。

风险: 规则太泛会变成噪声；规则太长会让 agent 找不到重点。

### 知识卡片: 移动控制面分级

iPhone Remote、Shortcuts 和 Voice 适合做控制面: 收集、派工、补上下文、低风险审批和看状态。Mac 仍应负责复杂 diff、验证、commit、push、deploy 和公开边界终审。

用户操作链路:

1. 手机收集公开链接、语音和提醒。
2. Shortcuts 或 Voice 结构化成候选卡。
3. Remote 选择 host、workspace、branch/worktree。
4. Codex 执行并保留证据。
5. Mac 验证和发布。

风险: 小屏幕和口语输入容易漏条件，不适合费用、权限、删除、公开发布等不可逆动作。

## 2026-07-28

### 知识卡片: 多入口控制表

当同一个 agent 工作台出现 web、mobile、desktop、CLI、cloud/local 多入口时，需要一张统一的入口权限表。入口可以分散，但可读、可写、可批准、日志位置和终审责任必须集中管理。

用户操作链路:

1. 列出所有入口: iPhone、Work、Codex Local、CLI、GitHub Mobile、Vercel。
2. 标注每个入口的执行环境: 云端、本机、远程 host、ephemeral environment。
3. 标注可读资料、可写文件、可批准动作和禁止动作。
4. 标注日志、diff、验证结果和线上回读在哪里看。
5. 新增入口前检查它是否绕过原有审批。

风险: 不同入口默认继承权限，会形成“手机能绕过桌面审批”的隐性通道。

### 知识卡片: 入口隔离策略

客户端 policy 应单独管理，避免把 CLI、desktop、mobile、cloud agent 混成一个权限开关。同一账号授权不等于所有入口都适合执行同一类动作。

用户操作链路:

1. 给每个入口单独设启用/禁用策略。
2. 分别配置插件白名单、网络访问和审批模式。
3. 标注哪些设置由统一策略覆盖，哪些可本地覆盖。
4. 对绕过审批、URL 访问、发布、费用相关动作加硬门槛。
5. 每次策略变化后跑一次最小端到端验证。

风险: 如果只有总开关，新增 app 或 cloud agent 可能带来未审查的能力扩张。

### 知识卡片: 移动端修复草案

手机端可以触发 agent 调查和修复失败 CI，但产物应是草案 PR、候选 diff 或待审核补丁，而不是直接合并、发布或删除。

用户操作链路:

1. 手机从失败通知或 check 触发调查。
2. Agent 在隔离环境中复现并提交草案。
3. 草案必须带失败原因、改动摘要和验证结果。
4. Mac 上检查 diff、跑附加测试和安全扫描。
5. 人工决定 merge、deploy 或退回修改。

风险: 手机屏幕不足以完成复杂 diff、权限、费用和公开发布终审。

### 知识卡片: 结果边界提示法

对成熟 coding agent，应少给逐步指挥，多给目标、边界、上下文、证据、验收标准和停止条件。人负责判断要什么，agent 负责在边界内找路线。

用户操作链路:

1. 用一句话定义目标结果。
2. 写清不能碰的文件、账号动作、网络和发布边界。
3. 提供必要背景和现有约定。
4. 要求输出验证证据和剩余风险。
5. 长任务中审查轨迹，而不是替 agent 逐步导航。

风险: 只说“随便优化”会目标漂移；逐步 micromanage 又会浪费 agent 的执行能力。

## 2026-07-29

### 知识卡片: 可复用 agent 资产验收单

一个可复用 agent 不只是 prompt，还包括输入范围、工具、权限、调度、证据、失败停点和知识回写。重复流程应从临时口头交代升级成可测试、可发布、可复查的资产。

用户操作链路:

1. 写一句话目标。
2. 限定输入来源和禁止读取内容。
3. 列出工具、插件、网络和文件权限。
4. 写清输出格式、验证命令和公开边界。
5. 设定失败停点和人工接手条件。
6. 把可复用经验写回知识库。

风险: 只保存 prompt 会导致下一次换入口后权限、证据和输出格式全部漂移。

### 知识卡片: Voice 派工确认闸

语音可用于快速派工、打断、补上下文和低风险调整，但高风险动作必须回到可读文字、diff、验证结果和显式确认。Voice 是入口，不是审批替代品。

用户操作链路:

1. 语音输入任务意图。
2. Agent 复述成任务卡。
3. 用户确认目标、禁止动作、可写范围和验证命令。
4. Agent 执行低风险步骤。
5. 涉及发布、授权、删除、费用或公开展示时转 Mac 终审。

风险: 口语容易遗漏否定条件、金额、路径、账号和公开边界。

### 知识卡片: Issue-to-PR agent 管道

异步 coding agent 的安全形态是从 issue、PR、Mobile 或 VS Code 启动，产出草案 PR，请求 review，并接受评论迭代。执行结果必须落到可审查边界内。

用户操作链路:

1. 在 issue 写清目标、约束和验收。
2. 选择 agent 和模型。
3. Agent 在隔离环境中提交草案 PR。
4. 安全扫描和测试先跑一遍。
5. 人类 review 后通过评论要求 agent 迭代。
6. Mac 端决定 merge、deploy 或退回。

风险: 直接改主分支或跳过 review 会把 agent 的幻觉、权限错误和未验证代码带进发布链路。

### 知识卡片: Markdown 知识底座

第二大脑应让 agent 能检索、更新、调和冲突和沉淀决策，而不是只堆网页剪藏。Markdown vault 适合作为长期可读、可版本化、可审计的知识底座。

用户操作链路:

1. 用 Markdown 存事实、决策、流程和反例。
2. 给事实标日期和来源。
3. 把长期规则和过期信息分开。
4. 定期合并重复卡片和冲突结论。
5. 只给 agent 受控目录写权限。

风险: 没结构的笔记会越存越难用；全库写权限又会带来误改和泄密风险。

## 2026-07-30

### 知识卡片: Agent 生产闭环

生产 agent 不只是 prompt，而是岗位、权限、模拟、评估、线上信号、改进建议和批准发布的闭环。每个可复用 agent 都应能说明自己服务哪个任务、能访问什么、何时要升级给人、怎么验证、上线后如何修正。

用户操作链路:

1. 定义岗位和成功结果。
2. 限定知识、系统访问和禁止动作。
3. 写批准条件、升级条件和失败停点。
4. 用模拟样例和评估标准做发布前测试。
5. 收集线上质量信号、升级原因和失败样本。
6. 让 Codex 产出改进补丁，人类测试后批准发布。

风险: 只看回答是否聪明会漏掉权限、升级、上线后漂移和回滚责任。

### 知识卡片: 插件身份最小披露清单

Sign in with ChatGPT 降低账号接入摩擦，但登录便利不等于授权安全。每个插件和合作站点都需要单独审查共享身份字段、工具权限、公开动作、撤销路径和是否进入公开产物链路。

用户操作链路:

1. 记录登录会共享的身份字段。
2. 查看插件请求的读写范围。
3. 标注是否能发布、提交、写入或授权下游工具。
4. 标注是否会出现在公开网页、PR、报告或日志中。
5. 保存撤销入口和重新授权步骤。

风险: 把统一登录当作统一安全，会让低摩擦入口绕过原有审批。

### 知识卡片: Review Skills + 只读 MCP

代码评审规则应版本化，外部上下文应只读接入，评审评论应能说明依据。这样 review agent 才能稳定复用团队标准，同时避免把查询工具变成代操作工具。

用户操作链路:

1. 把团队规则写成 `.github/skills/<skill>/SKILL.md` 或同类规则卡。
2. 给 issue tracker、文档系统、服务目录配置只读 MCP。
3. 要求 review 评论标明使用的 skill 或 MCP 上下文。
4. 按误报、漏报和遗漏上下文更新规则。
5. 高风险修复仍回到 PR 和人工 review。

风险: MCP 有写权限会把查证变成代操作；评论无归因会让规则无法迭代。

### 知识卡片: 模型默认启用审计表

新 GA 模型默认可用会提升速度，也会让未经评估的模型进入生产路径。模型治理至少要区分默认继承、显式启用、显式禁用和例外排除四类状态。

用户操作链路:

1. 列出可用模型和所在入口。
2. 标注数据保留、地区、成本、能力和风险。
3. 标注默认继承、显式启用、显式禁用或例外排除。
4. 在策略生效日前跑代表任务。
5. 记录输出质量、成本、失败和回滚方式。

风险: 新模型自动进入生产后，成本、合规、输出风格和回归可能同时变化。
