# AI Radar 执行控制

## 官方严谨版

### 1. 设备接力职责

| 设备/工作面 | 允许职责 | 边界与完成依据 |
| --- | --- | --- |
| iPhone | 接收意图、派工、查看状态、转向下一步、低风险审批 | 不直接承担文件写入、测试、diff、commit、push 或 deploy；不能单独宣布完成 |
| Remote | 在远程入口执行派工、状态查询、转向和低风险审批 | 只做控制面（control plane），不替代本地执行面；不能单独提供发布完成证据 |
| Mac/Codex | 读取和修改获准文件、运行测试与检查、审阅 diff、commit、push、deploy，并收集结果 | 测试、diff、commit、push、deploy 证据由此处收口；只有证据齐全才可标为完成 |

接力顺序是：iPhone/Remote 派工 → Mac/Codex 执行与验证 → iPhone/Remote 回看状态或做低风险审批。任何入口都不得把“已派工”“本地草稿”或“技术 PASS”直接等同于已发布；发布仍需 Mac/Codex 的相应证据。

### 入口职责矩阵

| 入口 | 主要职责 | 可回传内容 | 禁止越界 |
| --- | --- | --- | --- |
| Chat | 澄清目标、冻结范围、分发任务、汇总证据 | 结构化任务和证据摘要 | 不以聊天回复替代文件、测试或发布证据 |
| Tasks | 提醒和轻量监控 | 任务状态、阻塞点、下一动作 | 不在任务卡片中伪造 commit、push 或 deploy 状态 |
| Work | 组织上下文、草拟内容、比较候选方案 | 可审阅的工作材料和决策记录 | 不把工作台草稿当作已验证产物 |
| Codex | 在 Mac 上执行文件操作、测试、静态检查、diff 审阅及发布链路 | 文件差异、命令结果、commit/push/deploy 结果 | 不把未验证或失败结果包装成完成 |
| Voice | 低摩擦地发出派工、询问状态、请求转向或低风险审批 | 可转写为明确任务的意图与状态确认 | 不直接授权高风险写入或发布；动作须落到可追溯记录 |
| Remote | 远程查看、派工、转向、状态确认和低风险审批 | 远程入口状态与审批结论 | 不替代 Mac/Codex 的测试、diff、commit、push、deploy 证据 |

### UI 自动化证据环

涉及 UI 或浏览器自动化时，严格按以下五步闭环；缺一步即停止，不得凭猜测继续：

1. **观察前态**：记录可见界面、目标元素、当前值或 DOM 状态。
2. **声明动作**：用一句话说明将对哪个目标执行什么动作及预期变化。
3. **执行动作**：只执行已声明且在读写边界内的动作。
4. **回传新状态**：重新读取界面或 DOM，回传实际变化和必要的本地截图或 DOM 证据。
5. **验收/失败停止**：按预期条件验收；不符合、无法读取或权限不明时立即停止并记录停止原因。

本地截图、DOM 和登录状态都是本地验收证据，不能进入公开日报、公开网站或其他公开输出；也不能把截图本体或其中的私有内容带入公开边界。公开材料只保留经过脱敏的结论、状态和必要的可复核链接。

### 4. 可复制的 Markdown 执行记录模板

```markdown
## 执行记录
- 任务：
- 入口：
- 设备：
- 读写边界：
- 成功证据：
- 停止条件：
- 前态：
- 动作：
- 后态证据：
- 验收：
- 停止原因：
- 公开输出边界：
```

记录必须区分事实、推断和未知；失败时填写“停止原因”，并保留最后一次可验证状态。公开输出边界应明确排除 cookie、截图内容、私信、非公开账号信息、凭证和任何用户私有本地路径。

## 白话版

iPhone 和 Remote 像对讲机与遥控器：可以说“把这件事交给谁”、问“现在到哪一步”、要求换方向，或批准一个低风险动作，但它们不是施工现场。Mac/Codex 才像工作台加质检台，真正改文件、跑测试、看 diff、commit、push、deploy；这些证据齐了，事情才算收口。

UI 自动化像开门验货：先看门现在是什么状态，再说要按哪一个按钮，按下去后重新看一遍，最后对照验收条件。只要看不清、结果不对或权限不明，就停在现场。截图和 DOM 是验货台上的本地记录；验收结果像小票，只带脱敏的结论，不把私密内容搬到公开日报或公开网站。
