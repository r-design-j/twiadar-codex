### Codex/GPT 工作流启发

1. AI Scan PR API 让安全能力从“手工打开一个仓库”变成“组织级 rollout”，但 GHAS 资格和 GHES 不支持要写进边界。
2. repo-level AI Scan 设置不能覆盖 org-level disabled，这和昨天的托管权限逻辑一致: 上层禁用优先。
3. 安全扫描 rollout 应该记录 read 状态、desired 状态、实际更新结果和回滚命令，不只记录“已启用”。
4. `cache-mode` 把 Actions cache 从隐式权限变成显式权限，低信任事件默认 read-only 是安全基线。
5. 在 `pull_request_target` 上声明 `write` 或 `write-only` 会增大 cache poisoning 风险；这类例外必须进入 review。
6. reusable workflow 不能拿到比 caller 更多的 cache access，这一点适合写成 CI 继承权限测试。
7. 新 PR 列表的 compact mode、advanced search、status check counts 和 unread indicators 对 agent 批量 PR 审查很有用。
8. 但 PR 页当前 preview 缺 saving custom views 和 bulk updates，不能把它当完整队列系统。
9. MAI-Code-1-Flash 退役提醒: 模型策略不是静态配置；需要定期扫描 workflow、IDE、CLI 和 org policy 中的废弃模型名。
10. OpenAI Node/Python 同日补 Live API，说明实时/低延迟路径要纳入正式 SDK 验收，而不是只靠示例项目。
11. OpenAI Node/Python 同日补 Agents API，主 SDK 与 Agents SDK 的职责边界需要重新盘点: 哪些项目走主 SDK，哪些继续走 agents-python。
12. Codex `ExternalMessage` 的关键点是“可加入 turn，但不授予用户授权”；这正适合解决外部系统提示和人类授权混淆的问题。
13. `include_turns` 改变返回 history，不改变模型上下文；日报、handoff、resume 工具不要误把读回历史当作重新喂给模型。
14. 手动或迟到 attach 的 turn handle 不回放早期输出，甚至可能 `TransportClosedError`，所以监控器要区分“事件流起点”和“完整历史读回”。
15. `HookMetadata` 改为 `.root` 包装，升级 Codex SDK 前要扫自定义 hook 读取路径。
16. Codex 0.155.0 仍是 alpha 预览，适合观察方向，不适合自动替换稳定默认。
17. Windows voice 的 Cygwin build source release 是供应链/许可证透明信号，但它是 CI-only，不应被误写成用户包功能。
18. Copilot CLI 1.0.84-4 仍是 prerelease；命令迁移可以先进 smoke，不直接改团队文档默认安装命令。

### 可沉淀知识卡片

#### 卡片 1: AI Scan Rollout Receipt

- 概念: 把 AI Scan for PR 的 org/repo 启用状态、资格、边界和回滚命令做成一张灰度发布小票。
- 使用场景: AI SECURITY ROLLOUT
- 操作步骤:
  1. 先读 org-level AI Scan 状态，再读 repo-level 状态，标注 repo 是否被 org disabled 覆盖。
  2. 记录 GHAS 资格、github.com / GHES 支持边界、操作者和目标仓库清单。
  3. 每次变更都保存 before/after 状态和回滚命令。
- 风险: 只看单仓库 UI 可能误判组织级禁用或计划限制。

#### 卡片 2: Cache Mode Least-Privilege Gate

- 概念: 用 `cache-mode` 把 Actions cache 权限显式化，按低信任、可信、只写和禁用四类验收。
- 使用场景: CI CACHE SECURITY
- 操作步骤:
  1. 扫描 `pull_request_target`、fork PR、trusted push 和 reusable workflow。
  2. 给每类 job 标注 `read`、`write`、`write-only` 或 `none`，解释为什么需要。
  3. 对低信任事件的写权限例外保存 annotation 和 reviewer 结论。
- 风险: cache restore/save 权限过宽会把依赖缓存变成供应链污染入口。

#### 卡片 3: Codex ExternalMessage Boundary

- 概念: 外部系统消息可以进入或加入 Codex turn，但不能自动获得用户授权。
- 使用场景: CODEX SESSION BRIDGE
- 操作步骤:
  1. 标注外部消息来源、tool-level authority、是否可启动 turn、是否可加入 active turn。
  2. 写入、提交、部署、外部副作用仍要求用户或既定 automation 授权。
  3. 用 `include_turns` 读历史时区分“返回内容变化”和“模型上下文变化”。
- 风险: 把外部消息误当用户指令，会绕过审批边界。

#### 卡片 4: Live/Agents SDK Parity Gate

- 概念: 当 OpenAI Node/Python 主 SDK 同步加入 Live API 和 Agents API 时，用双栈小测保证接口、错误和流式行为一致。
- 使用场景: SDK UPGRADE
- 操作步骤:
  1. 分别固定 Node/Python 版本和 release 链接。
  2. 对 Live API 覆盖连接、取消、流式清理和错误 shape。
  3. 对 Agents API 覆盖创建、工具调用、权限失败和追踪字段。
- 风险: 只升级一个语言栈会让生产与自动化脚本出现行为差。

#### 卡片 5: PR Queue Triage View

- 概念: 把新版 PR 列表的筛选、compact view、status counts 和 unread indicators 当成审查队列入口，而不是最终验收系统。
- 使用场景: AGENT PR REVIEW
- 操作步骤:
  1. 建立 authored/involves/status/search 查询模板。
  2. 对 agent 生成 PR 增加 label、owner、测试状态和 unread 更新检查。
  3. 最终合并仍回到 diff、测试、ruleset 和人工 review。
- 风险: preview 页面缺保存自定义视图和批量更新，不能替代正式队列流程。

## 白话版

今天的主题像“公司买了新工具，但真正要紧的是发放、门禁和登记簿”。

AI Scan API 像保安系统终于能批量开关了。以前你可能要去每个仓库门口看一眼，现在可以在总部读一张清单，知道哪些仓库开了安检、哪些被总部禁用、哪些因为套餐不支持根本开不了。

`cache-mode` 像仓库钥匙分级。有人只能拿货不能放货，有人能拿也能放，有人只能放不能拿，还有人完全不能进。尤其是陌生人提交的 PR，如果让它既能拿旧缓存又能写新缓存，就像让外来施工队碰公司的仓库货架，必须很小心。

Codex 的 `ExternalMessage` 像同声传译接入会议。它可以把外部系统的话带进会场，但它不是老板本人，不能替老板签字、批准付款、发布上线。这条边界非常重要。

OpenAI Node/Python SDK 同时加 Live API 和 Agents API，则像两条生产线同时换了接口。你不能只看一条线能跑，就说整个工厂升级完成；两边都要跑一遍小测。

所以今天的建议不是“马上开更多 AI 功能”，而是先把每个功能配上小票: 谁开的、开在哪、怎么关、谁能覆盖谁、出问题怎么回滚。
