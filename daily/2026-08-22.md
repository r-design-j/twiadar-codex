### Codex/GPT 工作流启发

1. Plugin discovery 变得更主动，说明“工具从哪里来”本身要进入账本；发现、安装、授权、调用、撤销不能混成一个动作。
2. 时间感知让 ChatGPT 更适合日程、截止日期和相对时间任务，但公开日报仍要写绝对日期，避免“今天/昨天”漂移。
3. 长会话稳定性、progressive replies 和 mobile polish 会鼓励更长任务留在一个会话里；仍要在关键节点导出或记录 handoff。
4. Codex 与 Sites 同批出现在 ChatGPT release notes，说明“写代码”和“发布可见产物”的边界更近；发布前检查不能省。
5. Share Snapshot 让状态更容易分享，也更容易误带上下文。分享资产必须分 public summary、private process、local evidence 三层。
6. Pinned Chat sync 适合沉淀常用工作台入口，但不等于它们已完成验证；固定的是入口，不是证据。
7. Computer History 让 UI 自动化更可回看，但历史记录只能做本地验收，不应进入公开日报或网站。
8. Codex agents dashboard/queue 把多个任务的等待、运行、完成状态显式化；日报类自动化应记录 queue 状态，不把启动当完成。
9. `codex doctor` 适合变成发布前健康检查: 环境、认证、CLI、repo 状态、依赖和 deploy 工具先过一遍。
10. SDK reasoning effort 支持提醒我们: 子任务应该显式写 low/high/max，而不是默认拉满。
11. GitHub agent panel、Slack workspace agents、Teams bot 说明 agent 会进入团队聊天工具；聊天入口适合 dispatch，不适合作为最终验收系统。
12. Slack AI apps 需要 workspace/admin 级治理；ChatOps agent lane 必须记录安装来源、权限、频道范围和审计位置。
13. Microsoft Agent Framework 与 Copilot Harness 把 agent 的本地开发、评测和部署链路打包；这可作为个人 agent 从脚本升级为服务前的检查框架。
14. Obsidian Web Clipper 仍适合公开来源沉淀，但模板要记录 workflow asset，而不是只剪标题。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 用固定模板派发任务，补充绝对日期、是否允许发布、停止条件和可用入口。
2. ChatGPT: 用 plugin discovery 找候选工具，但只输出工具清单，不直接授权或提交表单。
3. Chat: 把口语输入整理成任务胶囊，冻结 public/private/local 三层输出边界。
4. Mac/Codex: 运行 `codex doctor` 或等价健康检查，确认 repo、依赖、发布工具和账号状态。
5. Codex queue: 只把独立且可验收的任务放入队列；共享写入对象串行处理。
6. Slack/Teams: 只做团队入口、状态广播和低风险审批；代码和发布证据仍落到 repo/PR/deploy。
7. Sites: 可公开展示的是总结后的报告、公开来源和可复用卡片；本地过程证据不进入站点。
8. Memory/Clipper: 把有复用价值的工具边界、队列诊断、分享边界和 ChatOps 入口回灌到知识卡片。

### 可沉淀知识卡片

#### 卡片 1: Plugin Discovery Ledger

- 概念: plugin 发现变主动后，工具本身要从“临时可用”升级成“可盘点资产”。
- 操作步骤:
  1. 记录插件名称、来源、用途、入口、安装状态和 owner。
  2. 区分发现、安装、授权、调用、撤销五个动作。
  3. 标注读写能力、可见数据、外部副作用和是否需要审批。
  4. 每次任务只启用最小必要插件。
  5. 结束后记录是否有效、是否返工和是否保留。
- 风险: 工具越容易被推荐，越容易在未理解权限时被误用。

#### 卡片 2: Shareable State Boundary

- 概念: Share Snapshot、Pinned Chat、Computer History、Sites 都在增加状态共享能力，但不是所有状态都可公开。
- 操作步骤:
  1. 把内容分成 public summary、private process、local evidence 三层。
  2. 公开层只放公开来源、结论、链接和可复用卡片。
  3. 私有过程层保留推理、草稿、截图、DOM、登录状态和审批记录。
  4. 本地证据层保留测试、diff、commit、deploy 和 inspect。
  5. 发布前扫描本地路径、凭证形态和私有过程词。
- 风险: 分享按钮越顺手，越要先确认分享的是摘要，不是现场记录。

#### 卡片 3: Queue & Doctor Runbook

- 概念: Codex queue/dashboard 和 doctor 把多任务运行状态与环境健康显性化，适合做自动化发布前闸门。
- 操作步骤:
  1. 任务入队前写目标、owner、写入路径和停止条件。
  2. 共享写入对象只允许一个活动任务。
  3. 发布前检查 repo 状态、依赖、CLI、账号和 deploy 工具。
  4. 失败时记录 queue 状态、doctor 输出摘要和最后一个可验证 artifact。
  5. 完成只以本地文件、测试、commit、push、deploy Ready 为证据。
- 风险: dashboard 显示“运行过”不是“已交付”，doctor 通过也不是业务验收。

#### 卡片 4: ChatOps Agent Lane

- 概念: Slack/Teams agent 入口适合团队调度和状态回传，但最终验收仍应落到 repo、PR、测试和部署平台。
- 操作步骤:
  1. 为每个聊天入口记录 workspace、channel、bot/app、权限和可触发动作。
  2. 触发词必须具体，默认只读或草稿模式。
  3. 高风险动作回到 PR、issue 或本地 Codex 审批。
  4. 状态消息只写 artifact 链接和下一步，不写凭证或私有上下文。
  5. 每周复盘触发次数、成功率、误触发和返工原因。
- 风险: 聊天工具降低了启动成本，也放大了误触发和权限扩散。

## 白话版

今天这期像是把工作台从“一个会干活的师傅”升级成了“前台接待 + 工具库 + 排队叫号机 + 体检表 + 团队对讲频道”。

ChatGPT 的新变化像前台更聪明了: 它会更主动推荐插件，知道时间，长会话更稳，手机端也更顺。好处是你更容易把一件事从想法推进到动作；坏处是工具越好找，越要记清楚它有没有权限、能不能写、会不会把事情发出去。

Codex 0.149.0 像施工现场多了排队屏和体检表: agents dashboard 看谁在跑，queue 看谁排队，doctor 先检查现场有没有问题，reasoning effort 像选择“普通用力还是深度用力”。但排队屏亮了不代表房子建完，体检过了也不代表项目验收通过，最后还是要看文件、测试、commit、push 和部署 Ready。

Slack/Teams 的 agent 入口像团队对讲频道。大家可以在群里叫 agent 开始干活、问状态、补充要求；但群聊不是质检台。真正的证据还得回到 PR、diff、测试和部署平台。

所以今天的结论很简单: 下一阶段不是多装几个工具，而是把工具发现、状态分享、队列诊断和群聊入口都纳入账本。哪些能公开、哪些只在本地验收、哪些需要审批，要先写清楚。
