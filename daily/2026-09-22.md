### Codex/GPT 工作流启发

1. 凭证、模型、CLI 权限和 worktree 不再是背景设置，都是需要回读的运行资产。
2. GitHub Enterprise credential inventory export 适合做安全事故前的常规盘点，不应只在泄漏后临时查。
3. Grok 4.7 进入 Copilot 多入口后，模型试用要先看 SKU、usage-based billing 和管理员 policy。
4. Copilot CLI 1.0.88-1 的 exact path grant 提醒: 自动化授权要保留最小粒度，不把一个文件误放大成父目录。
5. 网络拒绝出现 proxy tunnel bypass guidance 时，正确动作是记录限制和绕行条件，不是直接放宽沙箱。
6. Copilot CLI 1.0.87 的 pending prompt recall 让长任务可以撤回/编辑排队指令，但需要记录哪些 prompt 已发送、哪些仍在队列。
7. worktreePathTemplate 适合把多任务目录固定化，避免 agent 在临时路径里迷路。
8. active turn fork 是好能力，但要把父任务、子任务、写入边界和完成证据拆开。
9. Codex 0.157 alpha 已快速滚动，但 release body 稀疏；适合观察，不适合默认替换。
10. Codex 0.155.1 的 reasoning-summary 默认修复说明: provider 能力预检比“客户端支持”更重要。
11. ChatGPT iOS 的任务详情/队列/worktree 记忆更适合 iPhone 做派工和状态查看，不适合作为最终完成证据。
12. Copilot 模型 2026-10-19 退役需要提前做迁移表，否则固定 prompt 和 agent 策略会在当天集中断。
13. OpenAI Node 7.20.0 继续把 SDK 推向运营面: vault、external storage、safety case、webhook event 和 SIP security 都要有 owner。
14. OpenAI Python 3.16.2 的 parse_response memory leak 修复提醒: SDK smoke 要覆盖长时间解析和内存行为。
15. Agents Python 0.22.3 仍是长任务地基更新: approval、resume、SQLite、tool usage、subprocess cleanup 都应进入 fixture。
16. Claude Code 2.1.278 的 server-side classifier status 是对照样本: 自动路由一定要能回答“分类在哪里发生”。
17. 如果模型 fallback 会计费，成本小票要写清楚，不要只记录模型输出质量。
18. 今天的关键动作不是追新，而是把“谁有钥匙、谁能选模型、谁被授权访问、谁在哪个 worktree 干活”变成台账。
19. 公开日报只写公开来源和总结后的操作链，不写本地路径、截图、登录状态或私有过程证据。
20. Mac/Codex 仍负责最终收口: 文件、检查、diff、commit、push、deploy 缺一项就不能叫发布完成。

### 可沉淀知识卡片

#### 卡片 1: Credential Inventory Incident Board

- 概念: 把 SSH key、PAT、OAuth token、GitHub App token 做成可导出的权限资产清单，并和审计日志关联。
- 使用场景: ACCESS OPS
- 操作步骤:
  1. 按 owner、credential type、scope、created_at、expires_at、last_used 和 target org/repo 建表。
  2. 把 export CSV/API readback、过滤条件和 audit-log 关联方式写进操作记录。
  3. 事件响应时先冻结受影响凭证集合，再决定 revoke、rotate 或通知范围。
  4. 公开报告只写能力和方法，不写真实凭证名、用户邮箱或组织私密路径。
- 风险: 没有统一凭证清单时，事故响应会靠人工猜测，容易漏掉 app token 或细粒度 PAT。

#### 卡片 2: Model Picker Policy Ledger

- 概念: 每个新进入模型选择器的模型，都同时是权限、计费、可用面和回归测试事件。
- 使用场景: MODEL COST
- 操作步骤:
  1. 记录模型、可用 SKU、入口面、provider list pricing、usage-based billing 和 admin policy。
  2. 在 Business/Enterprise 环境先读 policy，再做 pilot，不默认相信全局自动启用。
  3. 用固定任务比较质量、延迟、费用和工具兼容性。
  4. 把模型启用、禁用、替代和退役日期放在同一张迁移表。
- 风险: 只看到模型名就试用，可能绕过预算、组织策略或固定回归基线。

#### 卡片 3: CLI Permission Micro-Grant Receipt

- 概念: CLI agent 的授权要精确到路径和网络条件，不能把缺失路径误扩成父目录权限。
- 使用场景: CLI SAFETY
- 操作步骤:
  1. 记录 exact path grant、parent directory grant、allow-all 状态和刷新失败时的保留规则。
  2. 把 /list-dirs、/reset-allowed-tools 和 network denial 文案保存为本地验收证据。
  3. 代理遇到 proxy tunnel/network denial 时先解释绕行条件，不直接放宽沙箱。
  4. 权限刷新失败后复读实际有效权限，避免 UI 文案和执行权限分叉。
- 风险: 把一个文件的缺失路径授权扩大成父目录，会让后续代理读写范围悄悄变大。

#### 卡片 4: Prompt Queue Worktree Contract

- 概念: 长任务里的排队提示、撤回编辑、fork 和 worktree 模板要分开记录，避免会话恢复时弄错现场。
- 使用场景: SESSION OPS
- 操作步骤:
  1. 记录 pending prompts、queued prompts、recall 操作和当前处理中的 prompt。
  2. 为 /worktree、/move、/new 和 --worktree 固定模板，并保存 repo/branch 展开结果。
  3. active turn 中 fork 任务时，注明父任务状态、子任务目标和写入边界。
  4. 删除/关闭 session 前区分本地永久删除和服务端 conversation 保留。
- 风险: 提示队列和 worktree 规则混在一起，会导致恢复后在错误目录或错误任务继续写。

#### 卡片 5: Alpha Stable Dual-Lane Gate

- 概念: alpha 版本看方向，stable 版本做默认；两条证据线不能混写。
- 使用场景: RUNTIME ROUTING
- 操作步骤:
  1. 记录最新 alpha、最新 stable、发布时间、release body 丰富度和目标问题。
  2. 没有明确修复点时，只写观察，不建议升级。
  3. 如需试验，用 disposable workspace 和最小 fixture，不污染默认工作流。
  4. 报告里把 alpha 观察、stable 默认和本地 smoke 结论分栏。
- 风险: alpha 连续滚动不等于适合生产；把 alpha 结果当 stable 证据会误导升级决策。

## 白话版

今天的 AI 工具更新，像办公室突然多了四样东西: 一张钥匙总清单、一份新车型上架清单、一个排队取号机，还有一条试验车道。

钥匙总清单就是 GitHub 的 credential inventory export。以前出事时可能要到处问“谁有钥匙、钥匙能开哪扇门、多久没用过”；现在可以提前做成表。白话说，别等钥匙丢了才翻抽屉。

新车型上架清单就是 Grok 4.7 进入 Copilot。它不是单纯多一个模型按钮，而是多了一辆可能按供应商价格计费的车。上路前要看谁能开、多少钱、管理员有没有放行。

排队取号机是 Copilot CLI 1.0.87/1.0.88。它开始更认真地区分哪些提示已经排队、哪些能撤回编辑、worktree 要建在哪里、某个文件授权不能顺手扩大成整个父目录。白话说，长任务不能靠记忆排队，要有票根。

试验车道是 Codex 0.157 alpha。它跑得很快，但稳定通勤车还是 0.155.1。能看方向，但别直接拿 alpha 当日常主力车。

iPhone + Mac + Codex 的分工也更清楚: iPhone 像遥控器，可以派工、看状态、补一句方向；Mac/Codex 像工作台，必须拿出文件、检查、commit、push、deploy 这些证据，才算真正收口。

今天最值得带走的一句话: 新模型、新版本、新授权按钮都不是玩具，它们是门、钥匙、车和票据；用之前先登记，用之后要能回看。
