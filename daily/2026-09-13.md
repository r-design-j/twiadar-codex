## 官方严谨版

### 今日结论

今天的重点是 agent 从“能执行任务”进入“可计量、可迁移、可管控”的运营阶段。GitHub 在 9 月 11 日把 VS Code Agents 纳入 Copilot usage metrics，并让 Copilot code review 能自动关闭已处理评论、使用更多 shell 工具验证代码、在 Lite effort 中采用 agent ensemble（多代理集合评审）。GitHub Copilot 周报还把 Jira 到 shared canvas、HydraFusion 自适应模型编排、VS Code recurring agent tasks、Voice mode 与 JetBrains sandbox 管控放到同一条产品线里。

OpenAI 侧的公开更新形成另一条配套主线: ChatGPT/Codex changelog 继续强调 quick chats、Pets、Appshots for Windows 与中断/接力能力；OpenAI release notes 把 Data plugin、Agents API public beta、GPT-Live 1 GA、API key expiration controls 放进 Work/Codex/API 的治理链路；OpenAI Developers 的 GPT-6 Astra 技术文和 Runme/WebMCP 案例则提醒，长技能、笼统 AGENTS.md 和未验证自动化会让 agent 变慢、变脆或越界。

结论: 下一轮 agent 工作流不要只问“能不能跑”，而要建立四张小票: adoption metrics receipt（采纳度小票）、review closure receipt（评审关闭小票）、permission/data contract（权限与数据契约）、context slimming audit（上下文瘦身审计）。这些小票要能在 Mac/Codex 本地验证，并与 GitHub、Vercel、OpenAI Work/Codex 的外部状态分开记录。

今天建议沉淀五个资产: VS Code Agents Adoption Receipt、Copilot Review Closure Gate、Recurring Agent Task Capsule、Data Plugin Permission Contract、Skill Context Slimming Audit。

### Codex/GPT 工作流启发

1. Copilot usage metrics 新增 VS Code Agents window 字段，说明 agent 采纳度要按入口拆账，不能只看总量。
2. `daily_active_vscode_agent_users` 是活跃人数口径，`totals_by_vscode_agent` 是 session/message 口径，两者不能互相替代。
3. optional/null 字段代表数据不可用或该入口未覆盖，不应被当成 0 使用。
4. Copilot code review 自动关闭已处理评论后，review queue 要改成“open comments are actionable（仍打开的评论才是当前待处理）”。
5. 自动关闭不等于人工验收完成，仍要看 diff、测试、ruleset 和 reviewer 结论。
6. Copilot code review 使用更多 shell tools 后，团队要区分“工具可用”与“工具输出已被验证”。
7. Lite effort 用 agent ensemble 后，低档评审也可能变得更强，但仍需要记录成本、严重级别命中与误报情况。
8. Jira -> shared canvas -> implementation -> PR 的链路适合用 task capsule 固化，但必须保留需求事实来源和产品确认状态。
9. HydraFusion 代表自适应模型编排会进入默认体验；内部路由仍要保留模型、成本、权限和外部边界小票。
10. VS Code recurring agent tasks 与本地 Codex automation 很像，但完成证据仍要回到文件、测试、commit、push、deploy。
11. Voice mode 可用于打断、转向和补充指令，不应被写成发布或审批证据。
12. JetBrains sandbox managed policy 把 filesystem、network、proxy、developer tools、macOS Keychain 纳入企业控制，应和本地 AGENTS.md 权限边界对齐。
13. OpenAI Data plugin 在 ChatGPT Work/Codex 可提供只读数据库入口，但公开日报不能泄露非公开数据、查询结果或本地凭证。
14. Agents API public beta 与 GPT-Live 1 GA 说明 API 侧也在靠近长期 agent/runtime；升级前要做 schema、stream、权限失败和追踪字段小测。
15. API key expiration controls 应进入每个自动化的 credential receipt，尤其是长期日报、Vercel、GitHub 和第三方数据源。
16. GPT-6 Astra 技术文提醒: 复杂技能要从“教模型每一步”转成“给边界、验收、例外和极少量高质量示例”。
17. Runme/WebMCP 案例适合把 notebook-style 步骤变成可复跑任务，但浏览器/工具动作仍要走观察前态、声明动作、执行、回读、验收。
18. Codex 0.154.0 的 worktree、inline answers、Windows background server、权限保持等能力适合做接力实验，但不要把 alpha/prerelease 直接替换稳定默认。
19. Copilot CLI 1.0.84-5 的 semantic JSONL import、shell completion grammar、absolute sandbox paths 和 per-model AI credit breakdown，适合加入 CLI smoke。
20. 本次没有发现需要用户立即安装、授权或关注的动作；建议先把指标、权限、评审关闭和上下文瘦身四类验收表补齐。

### iPhone + Mac + Codex 协作玩法

1. iPhone/Remote: 只派发“检查 agent adoption metrics 是否可读、字段是否为空、是否区分入口”，不直接做企业设置修改。
2. Mac/Codex: 生成 VS Code Agents adoption receipt，字段包含 1-day/28-day、aggregate/user-level、optional/null、权限角色和 policy enabled 状态。
3. Mac/Codex: 对 Copilot code review 自动关闭评论做 PR smoke，推送修复 commit 后记录 closed/open thread 差异。
4. Mac/Codex: 将 recurring agent tasks 的结果和本地 automation 结果对齐，只把本地验证的文件、diff、commit、deploy 作为完成证据。
5. Voice/quick chat: 用来中断、补充条件和确认低风险方向；涉及写文件、推送、发布仍回 Mac/Codex。
6. Data plugin: 若后续连接数据库，先建只读 query allowlist（白名单，像超市上架清单），公开网站只写总结后的公开结论。
7. SDK/API: Agents API、GPT-Live、Data plugin、API key expiration 统一进入 upgrade gate，避免单点升级。
8. Skills/AGENTS.md: 先做 slimming audit，删除重复背景，保留执行边界、验收命令和停止条件。

### 可沉淀知识卡片

#### 卡片 1: VS Code Agents Adoption Receipt

- 概念: 把 Copilot usage metrics 中 VS Code Agents window 的活跃人数、session 和 message 口径单独成账。
- 使用场景: AGENT ADOPTION
- 操作步骤:
  1. 分别拉取 enterprise/org aggregate 与 user-level 1-day/28-day 报表。
  2. 标注 `daily_active_vscode_agent_users`、`used_vscode_agent`、`totals_by_vscode_agent` 是否存在、为空或不可用。
  3. 把 VS Code Agents window、editor Agent Mode 和 generic Copilot usage rollup 分开展示。
- 风险: 把 optional/null 当 0 会误判采纳度；把多个入口混算会误导投入决策。

#### 卡片 2: Copilot Review Closure Gate

- 概念: Copilot code review 自动关闭已处理评论后，用一张复审小票记录 closed/open thread 差异。
- 使用场景: AGENT PR REVIEW
- 操作步骤:
  1. 在修复 commit 前保存 Copilot review comments 清单和对应文件行。
  2. 推送修复后读取自动关闭的评论、仍 open 的评论和 Copilot rereview 结论。
  3. 对自动生成 commit message 的 autofix 记录 diff、测试和人工接受/拒绝状态。
- 风险: 自动关闭只说明 Copilot 判断评论已处理，不代表最终合并或人工验收完成。

#### 卡片 3: Recurring Agent Task Capsule

- 概念: 将 recurring agent task 写成可复跑任务胶囊，固定触发频率、输入、权限、输出和完成证据。
- 使用场景: DAILY AUTOMATION
- 操作步骤:
  1. 记录触发入口、运行设备、读写边界、成功证据和停止条件。
  2. 明确任务是否只提醒、只监控、生成草稿、提交 PR 或发布生产。
  3. 每次运行写入本地 memory，避免重复采集或把旧状态当新状态。
- 风险: “定时启动了”不等于“任务完成并验证”，必须看目标日期产物和发布链路。

#### 卡片 4: Data Plugin Permission Contract

- 概念: ChatGPT Work/Codex 读取企业数据前，先建立只读查询、数据脱敏和公开输出边界。
- 使用场景: DATA ASSISTED CODEX
- 操作步骤:
  1. 固定数据源、查询权限、字段白名单和禁止外发字段。
  2. 将 private query result 与 public summary 分层保存，公开网站只写脱敏结论和公开来源。
  3. 对每次查询保留 who/when/source/query-purpose receipt，不保存凭证。
- 风险: 数据插件让读取更方便，也更容易把非公开事实误带入公开日报。

#### 卡片 5: Skill Context Slimming Audit

- 概念: 面向 GPT-6 Astra 的技能/提示瘦身检查，把长百科式说明改成边界、验收、例外和高信号示例。
- 使用场景: AGENTS.md GOVERNANCE
- 操作步骤:
  1. 标出重复背景、旧模型提示、过细微步骤和会诱导越权的指令。
  2. 保留不可破坏约束、停止条件、验证命令、产物格式和少量真实示例。
  3. 每次删减后跑一个代表任务，比较上下文占用、完成质量和返工率。
- 风险: 只做压缩可能丢失关键边界；瘦身必须以验收结果为准。

## 白话版

今天的主题像“AI 员工已经能干活了，下一步要给它打卡、质检、门禁和工作说明瘦身”。

GitHub 的 VS Code Agents 指标像考勤机。以前只知道 Copilot 总共被用了多少，现在开始能单独看到“专门的 Agents 窗口”有多少人用、开了多少次会、发了多少条消息。这个很重要，因为看总人数不等于知道 AI 员工到底在哪个工位干活。

Copilot code review 自动关闭已处理评论，像质检员复查后把已经修好的问题从待办板上拿掉。但它拿掉不代表产品经理已经签字，也不代表测试全绿；它只是帮你把“还需要看什么”变清楚。

Recurring agent tasks 像给 AI 排班。可以每天、每周让它自己跑，但排班表不是完工单。真正完工还是要看它有没有产出文件、跑过测试、提交代码、推到远端、发布成功。

Data plugin 像给 ChatGPT/Codex 接了公司资料柜钥匙。钥匙很好用，但拿到资料不代表能公开贴到公告栏。需要先定好哪些格子能看、哪些字段不能出门。

GPT-6 Astra 的技能瘦身提醒像给高手换说明书。以前说明书写满“第一步先拿笔，第二步打开本子”，现在高手更需要的是边界、验收和少量范例；写太满反而拖慢它。

所以今天最该做的不是再装一个新插件，而是把四件事补齐: AI 员工怎么打卡、评审怎么收口、数据怎么进出、说明书怎么变薄。
