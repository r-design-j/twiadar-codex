### 今日结论

2026-08-07 的主线是: AI 工作台正在从“多入口能跑”进入“可复用 agent 资产要治理”的阶段。OpenAI release notes 在 8 月 6 日更新 GPT-5.6，并特别说明这次只影响 Chat，不改变 Work 和 Codex；同一条 release notes 还把大段粘贴自动转附件、桌面 Chat/Work/Codex 分离、Sites、Atlas 8 月 9 日退场和 Codex Remote 放在一条连续演进线上。Workspace Agents 和 Plugins in Codex 则把 repeatable workflow、schedule、API trigger、Slack channel、技能、文件、app 权限、write approvals 和 connector constraints 变成可配置资产。

GitHub 侧的对应变化是: Agentic Workflows、Issue automation approvals/confidence/rationale、GitHub MCP stateless spec、Copilot cloud agent for Linear、Copilot app metrics 都在补同一个缺口: agent 不只要会做事，还要能说明为什么改、谁能批准、哪个动作自动执行、哪个动作等人审、怎么统计采用和产出。Meta Muse Code 的新闻则提醒我们: coding agent 价格战会继续，但低价不是免审查理由；同一套任务、权限、日志、测试、隐私和回滚表仍然是比较工具的基准。

对个人 AI Radar 的直接启发是: iPhone/Remote 继续做控制面，Mac/Codex 继续做验证和发布面；Workspace Agents 适合沉淀“可共享、可排程、可触发”的重复任务；Plugins/Apps 必须走权限清单；GitHub Agentic Workflows 适合把仓库巡检和 issue triage 写成可 review 的自动化资产；Obsidian second brain 可以做知识回收站，但默认只读，写回要有 diff、审批和去重。

### Codex/GPT 工作流启发

1. 模型更新和执行面更新要拆开看

8 月 6 日 release notes 说 GPT-5.6 更新适用于 Chat 体验，并说明 Work 与 Codex 不随这次变化改变。AI Radar 以后记录 OpenAI 更新时要分三列: Chat 模型/交互、Work 长任务交付、Codex 本地/云执行。否则很容易把“回答更稳”误读成“本地执行能力也变了”。

2. 大段粘贴附件化是上下文卫生信号

大于 10k 字符的粘贴自动转附件，表面是 composer 体验，实质是防止用户把上下文窗口一次塞满。对 Codex/Work 的启发是: 长材料应变成可引用附件、文件或知识卡，而不是直接塞进 prompt；入口要先判断材料是否需要结构化。

3. Workspace Agents 是“可共享 SOP”，不是一次性聊天

Workspace Agents 可以被创建、测试、分享、排程、API 触发、接入 Slack、配置 skills、files、memory 和 apps。Codex 的 Workspace Agents plugin 能创建、检查、更新和发布 agent，但不能替代真实运行/预览/analytics。适合把“每周产品反馈总结”“每日 issue triage”“AI Radar 候选源扫描”沉淀成 agent draft。

4. 插件权限不能靠提示词授权

Plugins in Codex 明确插件能力来自 skills、apps 和 app templates；app-backed 功能仍受 workspace app 设置与源系统权限控制。提示词说“只读”不够，必须在 app 设置里限制 read/write、confirmation、sync scope、domain、action constraints，并做低风险测试。

5. Codex tool 是 agent 执行器，不是无限本地权限

Agents SDK 的 Codex tool 适合把 bounded workspace task 交给 Codex 执行。关键不是“能不能调用 Codex”，而是 working directory、sandbox mode、approval gate、thread reuse、streaming logs、output schema 和失败停止。

6. GitHub Issues 正在把 agent 改动做成可审计建议

Issue automation controls 的 approvals、confidence、rationale 对个人工作流很重要: 自动化可以先建议标签、字段、关闭、分配，低置信度留给人审。注意 GitHub 也提醒 approvals 是 workflow convenience，不是服务端安全边界；真正安全仍靠权限和 token 范围。

7. MCP stateless 化提高可扩展性，也提高验证要求

GitHub MCP Server 支持新 MCP spec，去掉 sessions/initialize，强调 headers、elicitation 和 conformance tests。对私有 MCP 的启发是: 不要只测“能连上”，还要跑 spec/conformance、鉴权、日志和 secret scanning 边界。

8. Copilot/Linear 表明项目管理层正在变成 agent 派工面

Copilot cloud agent for Linear GA 支持从 Linear issue 指派、选模型、自定义 agent、设置 branch、评论 steer，并把进度回写 Linear timeline。这和 iPhone/Remote 的角色一致: 任务卡负责派工和转向，代码结果仍回到 PR/diff/review。

9. 采用指标开始覆盖桌面 agent app

Copilot app usage metrics 把 app activity 归到 user、feature、model、language 和 code activity rollups。AI Radar 可以借鉴: 月报不只统计 sourceCards，还统计 entry、execution、validation、publish、knowledge write-back 和 failed stops。

10. 低价 coding agent 要用同一张验收表比较

Meta Muse Code 的新闻把价格、反馈换折扣、复杂工程任务能力推到前台。低价会鼓励多跑 agent，但真正要比较的是同一任务下的测试通过率、日志透明度、数据使用条款、隐私边界、人工审查和回滚成本。

### iPhone + Mac + Codex 协作玩法

今日推荐链路:

1. iPhone/Remote: 负责提醒、查看 agent 进度、补充输入、批准低风险动作、暂停或转向。
2. Chat: 负责快速判断和模型更新观察，不把 Chat 模型能力自动外推到 Codex 执行能力。
3. Work: 负责研究、文档、表格、Sites 草稿和 Workspace Agent 需求整理。
4. Workspace Agents: 承接可重复 SOP；draft、schedule、API trigger、Slack channel 和 publish 状态要分开记录。
5. Codex: 负责本地仓库、命令、测试、diff、commit、push、deploy；Codex plugin 可配置 agent，但不能代替运行验收。
6. GitHub: 用 Agentic Workflows / Issues automations 承接仓库内重复巡检；先建议、再人工审、最后才自动应用。
7. Obsidian: 只把当天结论沉淀成知识卡；默认只读，写回前看 diff，避免知识库污染。
8. 安全收口: Atlas/浏览器迁移、cookie、书签、通知、截图和本地状态只做私下处理，不进入公开日报或网站。

### 可沉淀知识卡片

#### 卡片 1: Agent 资产发布闸

- 概念: Workspace Agent 的 draft、preview、publish、schedule、API trigger 和 Slack channel 是不同状态，不能把“已更新草稿”说成“已上线运行”。
- 适用场景: 周报 agent、反馈总结 agent、AI Radar 采集 agent、客服/销售自动化。
- 操作步骤: 创建 draft -> 配 tools/apps/skills/files -> 低风险 preview -> 设置权限 -> publish -> 再启用 schedule/API/Slack -> 做运行回读。
- 风险: 未发布 draft 不会影响用户；schedule/API trigger 也可能因未发布而未生效。
- 原文: https://help.openai.com/en/articles/20001143

#### 卡片 2: 插件权限上架单

- 概念: Codex 插件像超市上架清单，必须列清 skills、required apps、optional apps、app templates、读写动作、确认门和数据范围。
- 适用场景: Gmail、GitHub、Vercel、Slack、Drive、Notion 等 app-backed 插件。
- 操作步骤: 查插件依赖 -> 查 app 是否启用 -> 限定角色/账号 -> 默认只读 -> 写动作要求确认 -> 限制 sync/domain/source -> 低风险烟测。
- 风险: 插件安装不等于源系统授权；源系统权限过大时，插件会继承风险。
- 原文: https://help.openai.com/en/articles/20001256-plugins-in-codex/

#### 卡片 3: Issue automation 置信度门

- 概念: issue triage 自动化要把动作分成 auto-apply、suggest-for-review、stop 三档，并为每个动作记录 rationale。
- 适用场景: label、type、field、close、assign-to-agent、assign-to-user。
- 操作步骤: 定义 safe outputs -> 要求 issue intents -> 设置 confidence threshold -> medium/low 只建议 -> 人工批量接受/拒绝 -> 保留审计。
- 风险: 审批面板不是安全边界；真正边界仍是 token、permissions 和 allowed actions。
- 原文: https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview/

#### 卡片 4: 浏览器状态迁移清单

- 概念: Atlas 退场和 ChatGPT desktop browser 演进提醒我们，浏览器状态迁移要把 conversation、bookmarks、open tabs、history、cookies/passwords 分开处理。
- 适用场景: Atlas/Chrome/ChatGPT desktop/browser-based agent 迁移。
- 操作步骤: 导出要保留的公开 URL -> 单独处理书签 -> 不把 cookies/passwords 写进公开材料 -> 记录不可迁移项 -> 迁移后做只读回读。
- 风险: 把浏览器状态截图或 cookie 作为公开证据会泄露隐私。
- 原文: https://help.openai.com/en/articles/6825453-chatgpt-release-notes

## 白话版

今天这期像是在整理一个越来越大的工具间。

以前我们关注的是“有没有新工具”。现在重点变成: 每个工具到底是谁能拿、能进哪个房间、能不能动手、动手前要不要喊你、干完有没有小票。

ChatGPT release notes 像总公告栏。8 月 6 日说 GPT-5.6 在 Chat 里更稳，但也明说 Work 和 Codex 没跟着这次一起变。所以不能看到“Chat 变强了”，就自动以为“Codex 本地跑命令也变了”。这像前台接待换了新人，不代表车间机器也换了。

Workspace Agents 像把你常做的 SOP 做成固定工位。比如“每周总结反馈”“每天看 issue”“AI Radar 找来源”。但它有草稿、预览、发布、排程、API 触发、Slack 上线这些状态。草稿写好了不等于已经开门营业，排程设了也不等于真的跑过。

插件像超市上架清单。一个插件不只是“会一个技能”，它可能还要接 Gmail、GitHub、Vercel、Slack。每个 app 能读什么、能写什么、要不要确认、能不能同步数据，都要写在清单上。提示词里说“你要小心”不够，货架上没写清楚，结账时就会乱。

Agents SDK 的 Codex tool 像把 Codex 这位车间师傅请进一条更大的流水线。别的 agent 可以让 Codex 修代码、跑命令、改文件，但必须先画好车间边界: 只能在哪个目录干活、要不要审批、日志放哪、最后交什么格式的小票。

GitHub Issues 的新 controls 像给自动分拣员装了“我为什么这么分”的标签。高置信度可以自动贴标签，低置信度就先放到待审框。它提高的是工作流便利，不是保险箱；真正的保险箱还是权限和 token。

MCP stateless 化像把老式登记本换成更轻的通行证，进出更快，也更容易横向扩展。但你不能只看“门能打开”，还要看通行证规则、日志、密钥扫描和官方测试有没有过。

Meta Muse Code 像市场上来了更便宜的新师傅。便宜有价值，但不能只看工钱。你要拿同一张工单比: 是否跑测试、日志清不清楚、会不会拿你的代码训练、失败能不能回滚。

一句话: 今天不是“多叫几个 agent 来干活”，而是“给每个 agent 发工牌、配钥匙、留小票、设退货流程”。小票齐了，自动化才真的能复用。
